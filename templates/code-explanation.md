## 生成时执行的写作提示词

默认简明讲清，不把栏目数量当作篇幅要求。保留五部分、六列变量表、四个整体讲解字段、批判性审查与验证状态；同一结论只在最合适的位置解释一次，后文直接使用，不再换句话复述。

- 定位只交代位置与入口，职责只交代写入目标；进入条件按业务分组，不逐项重抄源码注释。
- 变量表一变量一行，含义与读写点用短语。只列理解当前逻辑所需的变量；方向只按该变量可见的声明或工程对象填写，不得把多个变量合并成“混合方向”等汇总项，也不能用程序读写角色反推接口方向；读写者和位置单独列证据。共享的声明缺口、外部写者未知放表前一次说明；声明不可见时才标为未知，并写明缺少的声明、变量表或工程对象。
- 四字段各讲一件事：处理过程串输入→判断→写入；关键逻辑选最易误读的一点并给简短单因素对照；写法好处只写有依据的局部效果；状态变化只说明写入、不写与保持，复位位置留给交接。每字段通常1～3句，确有独立因果才扩展，不以句数截断必要解释。
- 示例默认一个场景、一张短轨迹表，保留具体初值和连续承接；不额外堆真值表、第二套轨迹和边界长表。涉及保持时承接前值，不得把条件回落后不写当作复位。
- 交接只写实际输入、消费者和清除点，给最短可查位置；审查只列影响当前理解或行为的问题。共同未知与未执行验证集中说明一次，某结论专属的假设就地简注。
- 源码及原注释完整保留。IF/ELSIF、ELSE 与跨行条件判据必须逐行写 ` // AI: `，交代检查对象、条件含义及选路；不能只注释分支内赋值。默认在完整源行后按 ` // AI: ` 追加业务短句，准确说明保存、发送、清除即有价值；用户明确要求原样源码时不追加。删的是重复说明，不删条件、索引对象、顺序、写入/不写及证据边界。

出稿后删除：重复概括、流水账、与本段无关的术语课、反复免责声明和“本节将……”式元话术。读者应能复述“输入是什么→何时通过→写了什么→条件撤回后怎样”。

## 源码呈现的两个分支

- **默认追加注释版**：保留完整原行与原注释，只在行末追加 ` // AI: ` 业务短句；空白行和纯注释行不补。交付时明确称为“追加注释版”，不称原样代码。
- **用户当次要求原样源码**：只给无注释围栏，解释全部写在五部分正文；仍按完整逻辑边界拆块，不用省略号代替。

两种分支都逐段核对并完整呈现请求范围内所有可读源码，不得只摘录关键片段、跳过可读分支或用摘要替代。长源码按完整逻辑边界拆成可核对片段并覆盖全部请求范围，后续讲解可用行号锚点引用已展示片段。若受输出长度限制不能一次呈现，按连续部分分批交付，并在未覆盖完前明确标记未完成。原输入末行无换行时，在最后一个源码围栏后紧邻写 `<!-- source-eof: none -->`。

**图形语言分支**：LAD/FBD 保持同样的五部分与变量前置，第二部分保留原图、可核对的原生导出或拓扑文本，不用 ST 围栏占位、不伪写 ST、不逐行追加 `// AI:`；第三部分按网络与接点/线圈关系说明路径与写入，裁切或连接不清标未知。IL/STL、SFC 等按实际方言保留，五部分不变，校验范围不能冒用 ST 结果。
