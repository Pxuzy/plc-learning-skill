# 逐行注释：简短业务说明风格

## 适用范围

用于代码讲解中的新增行内注释。只规定注释怎么表达，不改变原模板栏目、变量表、正文、批判性审查和验证状态。逐行覆盖范围按用户当次要求执行；不因追求简短而省略已要求的行。

## 表达方法

### 注释前置参考

每次生成或改写注释前，先读取本文件（含“变量命名辅助推断”）与 [自造示例](inline-comment-examples.md)，再核对当前源码、声明和作者注释后落笔。已有可见且未失效的参考可直接复用，不必每行重复读文件；新批次先确认参考仍在上下文中，上下文压缩、换模型或恢复进程后须重新加载。独立模型请求须包含当前风格参考摘要及与本单元匹配的自造示例，不能只给一个模型无法访问的路径，也不能只让模型说“已参考”。参考不可读时注明未加载，不冒称按参考完成。

先拆前缀、英文词段和成员路径，再结合原注释、写入来源与读取用途形成用途解释；声明确认类型和作用域，命名仅辅助推断。写注释时使用短业务句，推断用途仍标“推测”，不把请求或记录写成设备已完成动作。参考是表达样板，不把其变量、业务和参数套到用户工程。

每条注释用自然中文说明这一行的实际作用，通常采用“动作＋对象”，必要时补充条件、来源或用途。例如“读取本次湿度”“刷新面板提示”“按表计倍率换算示值”。不要求每条都写成完整长句，也不机械填满所有成分。

- 条件行：`IF`、`ELSIF`、`ELSE` 及跨行条件表达式（包括 `AND`/`OR`、括号内判据和独立 `THEN` 行）必须逐行在完整原行后追加 ` // AI: `；说明检查哪个对象、什么判据使本路径成立或阻止进入，ELSIF/ELSE 交代前面路径未选中的关系。不能只注释分支内赋值，也不能用围栏外讲解替代。原有注释逐字符保留，新说明不以“条件判断开始”等语法套话占位；未知业务编码只说明可证比较，不编造工艺含义。
- 完整单行 IF 且仅一个简单赋值时，可在行末用一条 ` // AI: <条件＋动作>` 同时说明条件与动作；多动作仍按原逐单元规则。纯 `END_IF;` 默认可不加注释，整段逐行模式按其覆盖约定执行。用户明确要求原样源码时不追加；LAD/FBD 仍按网络级说明。
- 运算行：说明算出的是什么；单位、倍率等含义必须有声明或资料依据。
- 写入行：用业务名称指明更新、保存、清除或发布的对象，必要时交代来源和去向；不要求在中文里再次抄写变量名。
- 调用行：说明本次调用承担的可确认任务；不要把“发出命令”说成“设备动作完成”。
- 结构行：逐行模式下用带业务对象的最短承接说明；没有具体业务信息时如实写结构范围，不编造工艺。

保持相邻同类语句的句式一致；准确的“保存某项读数”本身就有价值，不要求每条再增加一种风险或新误读。原有注释清楚时保留；是否额外追加由当次覆盖约定决定。

## 证据与分工

先核对语句、声明和上下文，再用业务术语。允许按下节的方法，把命名、英文词段和作者注释作为理解用途的线索；证据未闭合时明确标为推断，不因名字看似清楚就断言机械动作、消费者、调用周期或设备状态。不知道某个数值的业务编码时写“与给定值比较”，不擅自命名为合格、故障或就绪。

行内承担就地识别作用：这一行处理什么。执行先后、保持与覆盖、数值反例、平台限制和风险分析放在原模板正文、示例或审查中；确实影响这行正确理解的限定可简短保留。不要为了注释简洁而把这些正文内容删掉。

## 变量命名辅助推断

把命名当作读码线索，结合作者注释与实际读写形成解释，不把缺声明简单处理为“什么都无法理解”。先观察本工程是否有一致命名习惯，再拆前缀、英文词段与成员路径，沿写入来源和读取用途核对；不能把第一个字母机械地都当作前缀。

| 命名线索 | 可以提出的候选解释 | 仍须核对 |
|---|---|---|
| `g_` | 可能表示全局变量 | 全局变量表、声明所在对象和可见性；若实际为局部声明，作用域服从声明，`g_` 仅是命名习惯 |
| `a` | 在本工程约定支持下，可能表示数组 | 是否有下标访问、声明范围和元素类型 |
| `x` | 可能采用布尔量命名习惯 | 声明及表达式实际类型 |
| `ax` / `ast` | 可能是数组＋布尔量、数组＋结构体的组合前缀 | 下标、成员访问和类型定义，不凭前缀补范围 |
| `i` / `r` / `st` | 可能指整数类、实数类、结构体 | 精确类型、位宽与成员定义，约定可能因工程而异 |
| `Enable` / `Ready` / `Done` / `Request` | 可能涉及使能、就绪、完成或请求 | 谁写谁读、置位/清除条件，区分状态、命令、反馈与记录；`Done` 命名或完成位置位本身不证明设备物理动作已完成 |
| `To` / `From` | 可能提示相对于某对象的数据流方向 | 通信映射、调用参数与读写点，不直接等同VAR_INPUT/VAR_OUTPUT |

推断依据分层表达：声明确认精确类型/作用域；可见下标、成员访问和赋值证明代码怎样使用它；命名和作者注释支持用途假说。注释也可能过时，若与代码冲突，以可见代码行为为准，并列出疑点。读取全局变量不证明本变量本身也在全局声明。

自造解读例：`g_axLampPermit` 可拆为 `g_`（可能全局）、`a`（可能数组）、`x`（可能布尔）、`Lamp`（灯）、`Permit`（许可）。再看到作者注释“各区灯光启用许可”，且元素被用于控制预览入口，可以解释为“推断：按区域保存灯光许可的数组”。只有声明可见后才能把全局作用域、BOOL元素和数组范围标为已确认；仅凭这个名字不能认定它驱动灯具输出或属于安全许可。

含义列可写“推断：灯光许可，依据命名、作者注释及入口条件读点”；声明未见时类型列仍写“未知”，在含义说明命名倾向，保留原六列。行内短注释若依赖未证实用途，简短标“推测：……”；同组共用推断可在源码前统一声明并明确适用变量。没有足够业务线索的行退回准确的数据操作，不能把猜测包装成事实。

## 源码与标记

面对用户源码，只在完整原行末追加 ` // AI: ` 与说明；原字符和作者注释保留。同一行已有本轮生成的尾注时不叠加。空白、纯注释及未闭合块注释内部行不补；原行含作者注释且仍执行代码时，按当次逐行约定追加一次。用户要求原样源码时不加尾注。原行已有 `//` 作者注释时，新增标记放在该原行全部字符之后；它只是同一行注释内的来源分隔，不是第二条可执行语句或新的词法注释起点。新增标记用于区分说明来源，不意味着源码可以直接投运。

## 条件逐行尾注示例

下例为自造教学片段；约定 `xPreviewEnabled` 为预览许可、`xPreviewHold` 为暂停预览、`xPreviewClear` 为清除请求，`xPanelPreview` 只表示面板显示标志，不代表物理动作。条件不通过时如何处理由实际分支决定，不凭空添加复位。

```st
IF xPreviewEnabled // AI: 检查面板预览是否获准
AND NOT xPreviewHold THEN // AI: 预览未暂停时才允许刷新显示标志
    xPanelPreview := TRUE; // AI: 标记面板预览开启
ELSIF xPreviewClear THEN // AI: 前述显示条件未选中时再检查清除请求
    xPanelPreview := FALSE; // AI: 清除面板预览标志
ELSE // AI: 显示条件与清除路径均未选中时采用默认显示状态
    xPanelPreview := FALSE; // AI: 默认路径关闭面板预览标志
END_IF;
```

IF 与 ELSIF 按顺序选路；即使清除请求为真，前面的 IF 已成立时也不会执行清除分支。这里的 `AND` 只说明组合条件，不承诺平台短路求值。样例仅作纸面逻辑说明，未执行 PLC 编译、仿真或硬件验证。

## 自查

1. 注释里的对象和动作能在语句或已给资料中找到依据吗？
2. 不看长篇正文，能知道这行正在处理什么吗？
3. 有没有把值的赋入写成真实设备已完成动作？
4. 有没有只写“执行赋值”“条件成立”等没有具体对象的空话？
5. 有没有把应放正文的一整段分析塞进行尾？

准确、清楚的业务说明判为合适；简短的结构承接单独识别，不声称有额外业务信息；对象、方向或条件讲错则返工。源码保真、覆盖与表达质量分别验收，自动检查不能替代语义判断。

## 示例与隐私边界

配套文件 [自造示例](inline-comment-examples.md) 仅展示注释写法。所有对象、变量、条件和场景为教学合成；不代表用户工程，也不用于现场控制。

借鉴私有工程时只提炼句式、信息选择和注释位置。示例须另选场景与数据流，独立编写，不能仅给原代码改变量名、改编号或同义改写原注释。禁止把私有源码、原句、项目标识、设备映射、现场参数、路径或归档作为技能素材、附件、测试夹具或运行依赖。相似性检查记录在技能目录之外，检查报告不回显私有命中原文。
