# 读者递进式讲解：模板被判“空泛”时的重建

用于现有讲解模板未能解释清楚代码、需要按第一性原理重新组织教学时。问题在阅读路径与因果组织，不在栏目数量、表格多少或字数。

## 先定交付边界

- 交付两份独立 `.md`：**候选模板**（写明“候选预览、未替换正式 Skill”）与**真实代码试讲样稿**。不直接改已安装模板或渲染器。
- 用户只给方向、还没看到效果时，不要顺手接入技能、不要改编排器、不要写 CHANGELOG。样稿通过用户判断后才谈落地。
- 不把“重新设计的版式”说成已通过验收；证据等级只说脚本真跑过的部分。

## 用户交来自己的模板稿时

用户明确指定模板 `.md` 时，**该文件是当前任务的唯一口径**；其他候选骨架不自动并入，不擅自调整其结构。

- 先逐条抄出它的**条件句与可选句**（“只在变量关系复杂时出现”“按难点选用，不强迫每段写满”“最后一个单元不编造下一段”），这些是它区别于旧模板的关键，落地时最容易被压成硬性必填。
- 已有的机器契约（如固定的八字段、五个栏目）可以承载实现，但**不得反向把该模板明确排除的义务加回去**：不强制四加粗字段、不要求每段写满反向追因、不强制变量表出现在正文。适配层说不清就别声称“严格按此模板”。
- 模板规范化须统一 **Skill 的模板资产、生成规则与校验要求**；仅重排某份样稿不算机制修订完成。
- 规范化完成的判据是一次**真实生成**：拿冻结源码走一遍渲染、通过结构/源码门禁、交出 `.md`；不能只用一份手写样稿说明效果。

## 一段代码的递进骨架（按此顺序写）

1. **真实问题开场**：用一句现场问题建立阅读目标（“车已经到位，为什么还不能启动？”），再说本段实际做什么。不要先堆变量定义，不要把推测的设计目的写成需求事实。
2. **带着问题读源码**：先只给读懂这段必需的 3 个量（各自是什么、下标/单位含义），再贴完整源字符 + 追加尾注。边界声明紧贴：本条注释/表格来自本节某行范围。
3. **把条件分组成“门”**：每道门写“源码在问什么 / 不通过会怎样”。分组必须对应真实表达式、不改运算优先级；并在段落里点明“不通过＝这次没置位，不等于写 FALSE”这类最易误解处。
4. **连续执行轨迹**：同一组具体输入走至少 3 次调用，表头固定为“第几次 / 关键输入 / 是否进入 / 执行前值 / 本次写了什么 / 执行后值”。**必须包含“条件回落但输出保持旧值”的那一次**——这是把“置位语句”与“条件实时映射”区分开的唯一有效手段。
5. **单因素对照**：只改站号或只改一个结果位，说明表达式作用；明确它证明的是表达式语义，不是现场需求。
6. **双向反查**：结果没出现 → 确认本段是否执行、逐门检查当次输入、再看后面的清除写点；结果仍存在 → 不能倒推门槛仍成立（引第 4 步的保持那一次作反例）。
7. **收束并抛问题给下一段**：一句话收住本段，再写一个真实未解决的问题，指出下一段去哪找答案。合格：“这里把启动位置 TRUE，却没有在条件失效时清它。下一段看谁撤销启动？”不合格：“通过以上分析掌握了逻辑，下面继续学习下一节。”并声明这是阅读路线，不是工程调度顺序。
8. **查阅层后置**：完整声明与类型、写点索引、风险、假设、验证记录放文末或附录；影响当前推理的未知就近写，不全部塞进附录。

## 退化反馈的处理

用户评价新稿不如原模板时，停止推广和继续改写新骨架；回读指定提交的原模板，逐项比较教学职责、因果解释、示例与交接，而不是用格式测试通过回应质量反馈。读者递进是分析与衔接方法，不等于把“真实问题／本段结论／范围／概念／观察边界”全部写成新栏目。优先保留原模板便于查阅的结构，仅将真实输入、判断、写入结果、具体示例和必要承接融入正文；不要把方法论展示和审计措辞变成阅读负担。回退前保留当前改动，恢复范围必须可辨，不用整仓回退抹掉已具备的长文能力。

## 写作纪律

- 第一性原理、系统交接、时间线、反向追因、单因素对照**融进因果说明**，不各占一个栏目，也不在标题写“本节使用 X 思维”。
- 只比较代码可证明的差异。无需求或测量依据时不写“更安全/更优/更高效”，也不为现有代码强行找优点。
- 未提供的成员语义（如某结果位代表什么）写未知，不用“首检失败”一类现场含义填空；注释掉的表达式不参与判断，不与有效分支重复计算。
- 教学表、关系图明确标注“不是可下载源码”。纸面推演不得称为 Run、仿真或 PLC 执行。
- 每句须提供新信息：同一事实在“开场/门表/正文”三处重复时保留一处。

## 设计依据（可引用，须说明是设计依据而非本模板的实验验证）

- PRIMM（Predict-Run-Investigate-Modify-Make）：先读程序再追踪与比较；原项目明确不要求每节覆盖全部阶段，故只借“先读→追踪→比较”。
- NSW CESE《Cognitive load theory in practice》：完整示例、剔除无关信息、必要信息相邻呈现——据此把源码与说明、难点与例子就近组织。
- CMU Eberly Center 学习原则：知识组织方式影响迁移，分项能力与整合练习都需要——据此增加章间承接与整体回接。

## 出稿验证（每份样稿都跑）

1. **源码逐字符对账**：拼回源码块，剥离追加尾注（` // AI: …` 或稿内约定的标记）后与归档原文 `==` 比较。
2. **归档清单哈希口径**：`归档校验.json` 的 `sections[].sha256` 是对节文本**去掉末尾换行**后的哈希；直接对含尾换行的切片做 sha256 会全部不匹配。这不是来源变更，用 `s.removesuffix('\n')` 复核后再判定。
3. **纸面模型断言**（Python 标准库即可）：把条件写成布尔函数，断言三类——全组合真值表（含特例站/旁路）、各项门槛单独置 FALSE 时结果必须为 FALSE、边界值（0/1/上界/上界+1）；再跑连续轨迹断言前值承接。报告里写明“纸面模型，非 PLC 执行”。
4. **成品结构**：围栏计数正确、无未替换占位符（`${…}`）、模板与样稿的文件哈希记入验证 JSON。
5. **渲染失败先定位到字段，不要读命令行那句话**：`render()` 对八个字段逐个做“非空、无标题、无围栏”检查，任一不满足就抛 `ValueError('field:<键>')`；而命令行把一切异常压成 `render-invalid-or-output-exists`，并把“输出已存在”和“字段非法”混成同一句。所以调试时**在 Python 里直接 import 调用 `render(unit, fields)`**，异常会点名是哪一栏；同时注意 CLI 用独占创建（`open('x')`），同一路径第二次写入也报这句，与内容无关。
6. **字段为空多半是切片锚点没命中**：用 `doc.split(起始锚)[1].split(结束锚)[0]` 从旧稿搬运段落时，锚句一字之差就静默返回空串，随后才在字段校验处炸开。搬完先断言每段 `len(...)>0`，并把 `annotations` 的键集合与 `annotation_lines(source, start)` 的结果对照断言，别等到渲染报错才回头查。

## 交付话术

正文只说：这版按什么顺序读、改动取舍是什么、脚本真跑了哪几项、哪些尚未验证（语义审校/PLC 仿真/实机）。末尾提**一个**具体的反馈问题（“哪一处仍会卡住”），不要罗列多选项清单。
