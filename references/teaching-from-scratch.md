# 从零带练：让新手自己写出 PLC 框架

用户有真实代码且要求「带我一步步写出这个框架」时，以归档源码为参照做**教学重建**：设计可亲手逐段实现的阶梯，交付**一份** Markdown 教程。

## 与读程序路线的分工

| 用户意图 | 路线 |
|---|---|
| 看懂、讲解、审计已有程序 | 手册/结构/代码解读（SKILL.md 主线） |
| 只要原样留档源码 | `references/source-archive.md` |
| 从零写、边写边学、练编程能力 | 本文件：教学重建 |

交付**教学版框架**，不称原始源码、可下载现场程序或已编译工程。原归档仅供对照，缺段（如节 6 后半、节 7 前半）不补造；另行设计须标教学版。

## 源码深讲模式（读真实工程时加载）

六槽位是理解内容要求，统一融入五部分：功能定位与进入条件→源码→代码块整体讲解→形象示例→程序交互与段间交接。关键变量在首个源码前介绍；逐句细节由有效行内注释覆盖，正文说明整块因果、跨扫描、误解与多写方，不重复逐句列表。现场动作、进入退出、状态变化与交接内容不能因去掉列表而省略。

读已有代码以源码、调用顺序、可见边界为事实，不把教学协调器/接口/练习回填原工程。由问题、事实、约束推导条件/状态必要性，用真实变量及明确假设推演，再核源码因果；只知代码行为时不声称知道原作者真实意图。每个可读原块保留短原片段、变量名/下标/原注释语义、来源定位，紧接六槽：**现场/业务动作**、**进入与退出/前置条件**、**代码块整体讲解**、**跨扫描变量变化**、**容易误解、执行顺序与多处写入**、**交给哪个B块/外部对象**。前两槽讲问题/约束/必要性，现场未知仅讲代码问题，不编机械背景，不以标签代推导；未要求深讲的 A/B 不套六槽位；局部逐行深讲仍覆盖这些教学内容。

有效行内注释覆盖全部状态/数据/输出写入，正文按整块说明因果，纯闭合可合并；每个效果讲触发、写入对象、后果。扫描表至少含正常/边界两个周期。空段标空，截断标“资料缺失”，不补造 ST。证据等级：`已确认`限可见文字/定位，`推断`给根据/替代解释，`未知`列缺资料；目标环境未编译、Trace 或现场验证则待验证。

深讲先现场画面/角色/双向信号/数组方向/调用运行边界，再逐 B 块，末尾汇总数据流、跨段依赖、多写点、疑点、调试、自测。区分工位号/动子号/检测下标/物料副本，`FALSE` 不等于未加工，常量不证明周期。B3 保留原括号/AND/OR，拆子命题、有限真值表、至少三扫描时序；B5 回读可见 leader/共享写入，不以教学中央仲裁器冒充原协议。

教学重建仍遵守以下独立验收：每阶段给当前可运行的调用入口；协议给唯一所有权转移点、请求撤销与完成确认、逐扫描竞态反例，以及超时后中央/本站的**恢复闭环**；练习给独立的迁移验收；对 B3、物料生命周期与 B5 信号链进行回读。阶段责任过多就拆分，失败诊断表须让学习者能定位等待原因。

## 交付形态

- 单一 `.md`，正文写进文件，聊天只给路径和三五行结论。分章保存、只发聊天、发压缩包都算未交付；反之也不能以“要单文件”为由跳过逐步带练、一次倾倒整套代码。
- 元信息写 `工程：` 与 `讲解深度：`（如 `从零编写`），单文件目录、稳定标题、代码围栏闭合。
- 委托外部编码代理代写时，在指令里指定**唯一正文路径**，只读输入列出具体文件，禁止改动既有归档，并要求它自己跑围栏/表格/一致性检查。
- 代理长教程用生成器拼正文，目标已存在即退出，防覆盖校对稿。除最终版，按阶段累积变量表查每阶段 ST 标识符均有声明，不能以最终通过掩盖中间漏项。Python 扫描模型覆盖到位撤销、启动保持/复位、结果仅存一次、免加工、不安全不请求、超时、退自动、发车等待、参数边界；交付注明不等同 ST 编译。

## 阶梯设计

一次只新增**一个可验证的行为**，顺序按依赖不倒置；对象、实例、扫描这些前置概念必须在第一段代码之前讲清：

1. **职责与边界**：这个 FB 协调谁和谁，不管什么；工位 ≠ 动子，FB 类型 ≠ 每个工位自己的实例。
2. **最小同步**：两个 BOOL 的到位通知，输入 UP → 输出 UP，撤销 → 撤销。
3. **加工握手**：请求/启动/完成/结果/复位，讲清置位点与复位点。
4. **状态与记忆**：跨扫描保持、步序、退自动与初始化复位。
5. **数据**：当前动子编号、物料数据副本、结果保存；结果 FALSE ≠ 未加工。
6. **免加工与异常**：跳过加工的分支、超时、诊断位。
7. **离站协调**：许可、目标、请求、反馈四类信号分开写。
8. **参数化与多工位**：每工位独立实例；跨实例共享状态必须走明确的中央协调或外部接口。
9. **人机与节拍**：HMI 交互、周期时间统计。

可调整合并，不先倾倒 83 变量及整套结构体；多发协同等另作进阶模块，注明未并入主 FB，不称复刻原工程。

## 每阶段必备字段

1. 一句话需求、输入输出（TRUE/FALSE 行为）、约束，说明为什么需要本阶段的条件或状态；先用真实变量、假设初值、输入序列推演，再给代码增量。新设计标教学设定，回读原工程限于源码证据。
2. **当前可运行的调用入口**：本阶段实例名、周期程序（任务）完整调用、模拟输入/初值、监视输出。仅 FB 正文不算入口，纸面扫描表不证明实跑。第二阶段起列保留的变量/调用；最终调用不倒灌早期阶段，避免参数不符。
3. 增量变量表：变量名、类型、方向、初值/说明；欧姆龙在变量表声明，正文只放 ST。
4. 代码增量：先介绍关键变量与本段新增变量，说明写在哪、替换还是保留；分小段源码后紧邻代码块整体讲解，再给形象例子与程序交互。正文不建逐行复述列表；第一性原理自然融入设计依据、关键逻辑与例子，不单列理论。
5. 关键行因果注释：为什么这个条件存在、输出在这里置位/复位。
6. 扫描推演：连续几个周期的输入序列 → 输出序列，含信号撤销后的行为。
7. 边界与复位：没有 ELSE 会保留旧值的对照、断电保持 ≠ 跨扫描记忆。
8. 短练习 + 可核对答案；答案放在练习之后，不伪造用户答复，也不因用户没答就停止写教程。
9. 结束语标明这是教学版、未做 Sysmac 编译/仿真；桌面逻辑推演或 Python 扫描模型验证要写明“不等同 ST 编译”。

## 通用检查提示（仅在当前源码有证据时采用）

- `SINT` 范围是 −128～127，不能表示 128；也不要凭空宣称“USINT 超限自动回绕”。
- `IF 条件 THEN x := TRUE; END_IF;` 没有 ELSE 时不会自动复位，旧值会保留到别处改写。
- 同一标量与两个不同常量的等式若用 AND 连接，结果恒为假；先核实括号与完整父条件，再说明受影响的分支。
- 结果位为 FALSE 不能推出“未加工”，要区分“没加工”和“加工了但结果不良”。
- 记录字段、设备编号与数组索引可能代表不同对象，关联关系需要声明或实际赋值证据。
- 时间累加使用固定增量时，先核对该值的单位、任务周期及调用条件，再判断累计时长。
- 条件中出现数组访问，不能证明该元素就是当前实体；追踪索引来源与身份映射。
- 多工位共用一个 FB 实例会串内部记忆；无保护的跨实例写目标预占会在同周期后写覆盖。

## 教学重建的自查

行数、变量数、600 项静态检查或 30 个扫描模型用例不证明新手能从零实现。下列门槛缺一，仅称“参考实现 + 逐阶段说明”，不称“可从空白工程逐步实现并验证”。

- 最终汇总的变量表、结构体成员、数组边界、FB 正文、调用示例互相一致，没有未定义变量与 TODO 占位。
- 每个阶段都能被用户按顺序敲出来、**不翻到最终汇总**就能运行并看到同样的推演；存在“跳步才能运行/编译”的段落即失败。
- 单阶段责任可控；类型、多索引、多变量、快照、沿实例、身份保护、跨扫描保存不同时引入，否则难以用已有不变量排错。拆成 04a/04b/…，每步给必要变量、当前调用、正常序列、反例。
- 协调器不整块倾倒 29 变量 113 行：单请求单路径 → FOR 建路径（逐轮下标/掩码）→ 第二候选/统一提交 → 在途保持/释放/复位；各版沿用前版输入表验证。
- 练习验证**迁移**：新需求（如等待超 2 秒报 112）、新时序（接单/离位同扫、接单后撤许可、超时/完成同扫），自行写状态/接口/ST、填轨迹，附核对不变量；答案齐全不等于学习闭环。
- 明确写出已知源事实 / 新设计 / 未知工艺三类，不为原代码推断机械动作。

### 目标平台基线验收记录

教学重建记录下表基线；缺字段/环境填“未验证”，等级为**参考实现/未验证**，可交源码讲解，不称可编译/运行。指定目标实测齐备才升级；Python模型/静态契约不替代Sysmac构建或Trace。

| 字段 | 最低记录内容 |
|---|---|
| 目标NJ型号 | 控制器完整型号/固件，未知则未验证 |
| Sysmac版本 | 软件完整版本/更新级别 |
| 库解析 | 使用库、命名空间、版本、解析结果（含TON/Clear等） |
| 任务周期 | Task、周期、优先级、POU调用顺序/实例绑定 |
| 变量/初值录入 | 类型、数组边界、变量方向、实例、初值与逐阶段录入记录 |
| 构建结果 | 最小阶段与最终版本的构建日期、结果、错误/警告及证据位置 |
| 离线Trace | 输入序列、监视变量、扫描轨迹、预期与实测差异、证据位置 |

分析已有程序时，先列可核实的材料与缺件；未提供的实例调用不能自行补造。逐块校验应覆盖模板字段、表达式与下标、推演表数值和引用范围，空白或截断的例外必须局限于对应缺口。脚本完成这些检查后，仍需人工复核解释是否准确。

## 跨模块协议与恢复（教学版最容易假通过的部分）

单 FB 自洽不证明与中央协调器的事务一致；多模块阶段须交付：

- **所有权转移点唯一**：`Accepted` 只取一个含义（如输送所有权转交）；消费有效接单后，不因新许可/到位状态否认已接单，避免中央已接单而工位报“接单前丢车”。
- **请求撤销不是接收确认**：`Req=FALSE` 不证明消费；完成反馈须独立确认或可核验状态，并解释 Done 保持整扫描仍可能漏消费。
- **常规表无法证明无竞态**：正常时序（等工位到 50 再撤销）可能绕过问题，通用边界须写限制；每处“上扫描反馈 + 本扫描动作”都给逐扫描边界反例。
- **单站超时后不能独立重开旧事务**：本站 111/900、中央 10、预占 TRUE 可同时成立。须给闭环：停新接待 → 输送确认中止 → 中央 90 → 核对停止/占用/Complete 低 → 释放预占 → 清本站故障 → 允许接待；解释中央 10 不响应离线复位，仅清本站会使下轮误消费旧 Accepted。
- **等待原因可定位**：给一张按代码分支顺序排列的只读排查表（使能 → Complete/Fault → 参数范围 → 组请求 → 源占用 → 安全 → 各路径占用/交叠），每项列监视变量；只加一个“忙”灯不能让人区分为什么请求为真而接单为假。

## 从教学版回读原工程

教学可简化，**已知源码**仍须展开，不能因复杂只让读者自写真值表；缺口仅指未收到部分（如节 6 后半、节 7 前半）：

- 已收到的判定分支原样摘一段，拆成有明确含义的子命题，填六行左右真值表，走一遍“本扫描读旧结果 → 更新工位副本 → 判定 → 下一扫描才影响启动”的两三扫描轨迹，并标出置位/清除的唯一可见点。
- 加一张生命周期表：教学库、原动子记录、中间数组、工位副本、码记录各自的索引、可见写入点、清除触发条件与未知归属；讲清“离位清副本”≠“清动子库”，以及为什么不能断言交换恰好发生一次。
- 发车前段给一条有精确位置的信号链（请求 → 取配置编码 → 换算偏移 → 选 leader → 沿途/目标占用检查 → 覆盖写入 → 此处源码缺失），并用一组假设走一次；同时点明教学中央方案与原 leader 方案不同，不能从未知 CASE 反推原版具备同样原子性。
- 每个原工程简化处都标“这不是你的线/这是重建设计”，并给出教学阶段 ↔ 原模块的对应与不对应表。
