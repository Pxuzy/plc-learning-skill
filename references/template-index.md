# 模板总索引与路由 🗂️

本索引是模板 ID、职责、适用条件、组合关系和版本的唯一登记来源。输出文档记录实际使用的 ID 与版本；同一字段只按其共享来源定义一次。`templates/index.md` 只是按适用条件选择模板的路由，不得另设未在本表登记的 ID；`templates/` 下的局部讲解与导航模板是本表登记的兼容呈现，字段与门禁以其权威正文为准。

| ID | 版本 | 文件 | 类型 | 触发条件 | 可组合模板 |
|---|---|---|---|---|---|
| HBK | 3.0 | `references/template-handbook.md` | 共享基底 | 需要交付项目手册或对象讲解文档 | FB, ST, STATE, INTERFACE, FLOW |
| FB | 3.0 | `references/template-mfb-xml.md` | 对象模板 | 需要讲解 FB/FC/MFB/POU 定义、接口或调用实例 | HBK, ST, STATE, INTERFACE, FLOW |
| ST | 3.0 | `references/template-st-xml-framework.md` | 对象格式层 | 对象含可读 ST，并需按总框架到程序段分层说明 | HBK, FB, STATE, INTERFACE, FLOW |
| STATE | 3.0 | `references/template-state-machine.md` | 可组合专题 | 请求状态机、步序、转移条件、等待或复位路径 | HBK, FB, ST, INTERFACE, FLOW |

共享字段的唯一来源是 `HBK`：工程/对象元信息、资料范围、证据等级、源码范围、覆盖状态、模块讲解顺序（功能定位与执行条件→源码→代码块整体讲解→形象示例→程序交互与段间交接）、缺口和交接。扩展模板引用这些字段，不重定义列名、状态词或规则。FB 专有定义属性由 `FB` 定义；所有接口字段及实例参数映射仅由 `INTERFACE` 定义，FB 模板链接并复用该字段集合；状态转移表由 `STATE` 定义。

讲解代码的共同推导路径以 `SKILL.md` 选择器及 [代码解读](code-reading.md) 为准：A/B 也从问题、事实与约束推出条件或状态的必要性，作具体推演再对照源码，只压缩篇幅；完整手册和各扩展模板按此展开，教学新设计标明设定，纯源码归档不插讲解。此处同步讲解内容要求，不改变模板 ID、版本、字段或组合。

## 呈现模板登记（局部讲解与导航）

局部讲解与导航的 ID、版本和权威正文同样只在本文件登记；`templates/` 下的两份文件是可复制的兼容呈现，不构成第二套注册表，也不得新增、删除或改名正式字段。呈现文件与权威正文冲突时，以权威正文为准，并同步修正呈现文件。

| ID/版本 | 权威正文（唯一） | 呈现文件 | 适用条件 | 呈现边界 |
|---|---|---|---|---|
| CODE@1.0 | `references/local-code-explanation.md` | `templates/code-explanation.md` | 用户要求讲解已选定范围的 PLC 代码 | 兼容呈现四行元信息、`### Mxx`、`#### 1～5` 五部分、粗体四字段、源码定位与范围映射、批判性审查与验证状态；只替换占位内容 |
| NAV@1.0 | `references/workflows/project-navigation.md` | `templates/project-navigation.md` | 工程跨多个对象、框架复杂或用户尚未选定范围 | 兼容呈现总览、结构地图与可选对象；用于选范围，不代替逐段讲解 |
| BOOKSET@1.0 | `references/template-handbook-index.md` | `templates/handbook-index.md` | 用户要求完整多对象手册，且实际输出拆为两本或更多 | 同版只允许一个正文；呈现文件以 `template-compat` 标注引用该正文，保留自身分册字段，不另立第二份定义 |

呈现文件保留自身模板声明（`<!-- template-id: ID@版本 -->`）；非权威正文的呈现文件另写 `<!-- template-compat: ID@版本 -> 权威正文相对路径 -->`，使同一版本号唯一对应一份正文。新增或改版呈现模板须同步本表、路由与 `evals/check_foundation.py`。

## 路由规则

先服从用户指定的交付类型，再按现有资料能证明的对象形态选择。默认顺序为：`HBK` 共享基底 → 一个对象模板（需要时）→ 零个或多个专题。每个模板组合须在“可组合模板”列中双向登记；`OVR`、`MAP`、`BOOKSET` 是独立交付，不叠加到对象讲解文档。

| ID | 用户请求 / 资料触发 | 输出组合 | 选择边界 |
|---|---|---|---|
| HBK | 完整项目或选定程序对象的通用讲解 | HBK | 按适用章节填写；不适用内容省略，不用空表凑结构 |
| FB | FB/FC/MFB/POU 定义、接口、实例或内部逻辑 | HBK + FB | 分清定义与调用实例；SMC2 XML 是一种来源，不假定所有工程都有 XML/EID |
| ST | 可读 ST 单元，需按调用框架和逻辑层次解释 | HBK + ST | ST 是代码组织层；与 FB/POU 对象同时出现时组合，不重复源码段 |
| STATE | 状态机、步序和转移问题 | HBK + STATE | 只记录有证据的状态、条件、动作和退出路径 |
| INTERFACE | 接口、调用者、实例及参数差异 | HBK + INTERFACE | 定义与实例分别登记；缺调用方资料则标未知 |
| FLOW | 工艺动作、信号链或两者关系 | HBK + FLOW | 保留现有工艺/信号模板；不由代码推定机械事实 |
| OVR | 用户只要一页总览 | OVR | 按 `template-overview.md` 单独交付 |
| MAP | 用户只要结构图或对象清单 | MAP | 按 `template-structure-map.md` 单独交付 |
| BOOKSET | 多个手册需要拆册 | BOOKSET | 与各册 HBK 文档配套，不替代分册内容 |

混合对象按证据组装，例如可读 FB、ST 和状态机用 `HBK + FB + ST + STATE`；同一源码段只出现一次，其它专题提供可点击引用。若输入只有工艺或信号问题，可直接聚焦 `HBK + FLOW`，不用补写无证据的任务树、接口或内部实现。

## 资料不足与降级

- 有接口、无本体：登记可见接口、调用点和输出去向；内部状态和实现标为未知/受保护，不猜测。
- 有局部源码、缺调用者或外部信号：先交付可证实部分，缺口列为最小追问；不把未知章节伪装为已完成。
- 只有截图或片段：只覆盖可辨认范围，标清不可辨认内容和不能进行的源码对账；不要求完整工程章节或全量 manifest。
- 识别不到平台、对象类型或源码形态：保留原始命名，列出尚缺的最少资料后再选对象模板；不得按相似 PLC 项目补齐事实。

资料不足不阻断有证据的局部讲解，但任何未确认结论仍保持“未知”或“推断”，不升级为“已确认”。受保护对象只说明外部可见信息，遵循只读边界：不改 PLC 程序、不下载、不强制 I/O、不旁路安全保护、不做产线试错。

## 模板资产格式验收

- 运行 `python3 -B scripts/validate_template_format.py .`，机器读取可加 `--json`；退出 0 为格式通过，退出 1 为失败。完整仓库和独立运行包均可运行，依赖 `assets/template-format-contracts.json` 及同包 Python 辅助脚本。
- 静态契约检查 9 份正式模板和 3 份兼容呈现的必需标题层级/顺序/数量、字段和表头，并进入可复制 Markdown 围栏内部检查。围栏未闭合、空小节、越界路径、缺失资产、未登记模板和缺兼容声明均拒绝。
- `template-compat: ID@版本 -> 权威正文` 是兼容视图的机器标记。`template-authority` 仅为阅读提示。BOOKSET 的五节导航视图与八节权威正文通过表字段映射保持契约；时机和后果分列，类型与段数不得遗漏。补回权威正文已要求的字段属于修复不完整呈现，不另立新格式。
- 机器规格不是第二注册表：ID、版本和路径以本页为准。禁止日常校验时从当前文件自动重建规格以掩盖漂移；格式变更按下文版本策略同步登记、规格和正反用例。新检查不追溯证明历史版本变更已合规。
- 此 CLI 检查模板资产，不判断生成文档的 PLC 语义、源码保真或字段真实性；生成局部讲解仍运行专用源码/版式检查器。

## 版本策略

- 当前共享版式为 3.0：关键变量前置，正文块级说明替代逐句复述；新稿声明 `讲解版式：块级`，五部分使用 Markdown 分级标题。当前可复制样例为[块级手册](example-block-handbook.md)；[兼容样例](example-handbook.md)仅作其它格式的回归输入，不作为新稿格式依据。模板格式版本用于校验文档结构，不代表技能发布版本。
- 每个源码块把来源标记紧贴开围栏，来源附注统一为 `来源/对象`；保留唯一完整源块，重复教学源码改成锚点和源行范围。局部成品明确范围与三种状态，缺口移到范围外专节仅限确实范围外对象；自测可选。推荐 ST/FB 专题标题保留，不改成 HBK 编号。
- 核对行旁解释时，补充源码能证实的当前作用，执行行与结构闭合行缺 AI 业务短注释须补齐或标明未完成，只豁免空白、纯注释及块注释内部行，不得登记省略理由代替尾注，再做源码对账和逐块审查。已有成品不自动升级；未经重新对账和审查，不声称通过当前契约。
- 本注册表是当前模板版本的唯一来源；模板文件和成品中的模板 ID/版本必须与此处一致。同一 `ID@版本` 只能有一份权威正文，其余文件是标注 `template-compat` 的兼容呈现，不得出现第二套字段定义。
- 文字修正、示例调整或不改变字段语义的增量兼容修改升级次版本（`1.0` → `1.1`）；不改变现有内容的错字修正可保留版本并记录在变更日志。
- 移除/重命名必需字段、改变共享状态词或更改组合契约时升级主版本，并提供旧版到新版迁移说明；不得静默重排已交付文档编号。
- 新模板先分配唯一 ID，列出触发、资料、组合及替代项，再接入技能入口、样例、索引校验和行为用例。
- 历史文档记录其生成时的版本；需要迁移时注明迁移前后版本、受影响章节及未迁移字段，不自动改写用户旧稿。
