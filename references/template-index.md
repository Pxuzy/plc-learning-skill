共享字段的唯一来源是 `HBK`：工程/对象元信息、资料范围、证据等级、源码范围、覆盖状态、模块讲解顺序（功能定位与执行条件→源码→代码块整体讲解→形象示例→程序交互与段间交接）、缺口和交接。扩展模板引用这些字段，不重定义列名、状态词或规则。FB 专有定义属性由 `FB` 定义；所有接口字段及实例参数映射仅由 `INTERFACE` 定义，FB 模板链接并复用该字段集合；状态转移表由 `STATE` 定义。

讲解代码的共同推导路径以 `SKILL.md` 选择器及 [代码解读](code-reading.md) 为准：A/B 也从问题、事实与约束推出条件或状态的必要性，作具体推演再对照源码，只压缩篇幅；完整手册和各扩展模板按此展开，教学新设计标明设定，纯源码归档不插讲解。此处同步讲解内容要求，不改变模板 ID、版本、字段或组合。

## 路由规则

先服从用户指定的交付类型，再按现有资料能证明的对象形态选择。默认顺序为：`HBK` 共享基底 → 一个对象模板（需要时）→ 零个或多个专题。每个模板组合须在“可组合模板”列中双向登记；`OVR`、`MAP`、`BOOKSET` 是独立交付，不叠加到对象讲解文档。

| ID | 用户请求 / 资料触发 | 输出组合 | 选择边界 |
|---|---|---|---|
| HBK | 完整项目或选定程序对象的通用讲解 | HBK | 按适用章节填写；不适用内容省略，不用空表凑结构 |
| FB | FB/FC/MFB/POU 定义、接口、实例或内部逻辑 | HBK + FB | 分清定义与调用实例；SMC2 XML 是一种来源，不假定所有工程都有 XML/EID |
| ST | 可读 ST 单元，需按调用框架和逻辑层次解释 | HBK + ST | ST 是代码组织层；与 FB/POU 对象同时出现时组合，不重复源码段 |
| STATE | 状态机、步序和转移问题 | HBK + STATE | 只记录有证据的状态、条件、动作和退出路径 |
| INTERFACE | 接口、调用者、实例及参数差异 | HBK + INTERFACE | 定义与实例分别登记；缺调用方资料则标未知 |
| FLOW | 工艺动作、信号链或两者关系 | HBK + FLOW | 保留现有工艺/信号模板；不由代码推定机械事实 |
| OVR | 用户只要一页总览 | OVR | 按 `template-overview.md` 单独交付 |
| MAP | 用户只要结构图或对象清单 | MAP | 按 `template-structure-map.md` 单独交付 |
| BOOKSET | 多个手册需要拆册 | BOOKSET | 与各册 HBK 文档配套，不替代分册内容 |

混合对象按证据组装，例如可读 FB、ST 和状态机用 `HBK + FB + ST + STATE`；同一源码段只出现一次，其它专题提供可点击引用。若输入只有工艺或信号问题，可直接聚焦 `HBK + FLOW`，不用补写无证据的任务树、接口或内部实现。

## 资料不足与降级

- 有接口、无本体：登记可见接口、调用点和输出去向；内部状态和实现标为未知/受保护，不猜测。
- 有局部源码、缺调用者或外部信号：先交付可证实部分，缺口列为最小追问；不把未知章节伪装为已完成。
- 只有截图或片段：只覆盖可辨认范围，标清不可辨认内容和不能进行的源码对账；不要求完整工程章节或全量 manifest。
- 识别不到平台、对象类型或源码形态：保留原始命名，列出尚缺的最少资料后再选对象模板；不得按相似 PLC 项目补齐事实。

资料不足不阻断有证据的局部讲解，但任何未确认结论仍保持“未知”或“推断”，不升级为“已确认”。受保护对象只说明外部可见信息，遵循只读边界：不改 PLC 程序、不下载、不强制 I/O、不旁路安全保护、不做产线试错。
