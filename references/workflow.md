# 学习流程、覆盖状态与完成标准

SKILL.md 只写“怎么做”的主线；本文件写阶段、状态、验收和单次/系统学习的边界。

## 学习生命周期

```text
接收程序
→ 判定输入形态与学习意图
→ 平台识别
→ 程序清点
→ 建立项目地图
→ 按原生对象与业务关系分组（有工位证据时按工位切分）
→ 建立 I/O 与地址表
→ 列出学习对象
→ 按依赖建立学习路线（用户可指定对象或跳转）
→ 生成/更新对应的深度讲解手册
→ 阶段理解检验与后续对象建议
→ 推荐后续对象
→ 按需更新覆盖与复习记录
```

复杂讲解按项目依赖和证据检查点推进，不按日/周排课程；仅勾选适用阶段，缺输入标缺口，不用泛例补齐。用户表达要看懂复杂框架、整体拆解、带学或讲透并整理手册时，默认进入系统学习，不要求用户使用“系统学习”等固定口令；只问一个事实或局部代码时仍走最小范围答复。

复杂讲解开始前，复制这份清单并逐项确认；未适用项标明原因：

```text
讲解进度：
- [ ] 1 输入形态已判定，资料范围写清
- [ ] 2 平台与版本已确认（欧姆龙另报任务/程序/段数量）
- [ ] 3 对象已清点并按原生层级分组；工位不存在时不套工位地图
- [ ] 4 覆盖清单已建，状态字段填全
- [ ] 5 深度已按用户选择写单一值
- [ ] 6 文档已过校验器，必改项清零
- [ ] 7 理解检验（可选）已出题并记录结果，或登记未自测/已跳过
```

四条顺序规则：

- 先判输入形态，形态决定能讲什么。
- 平台识别在清点之后、讲解之前。
- 按原生对象分组在 I/O 表之前；只有工程实际存在工位时才按工位切分，不造不存在的层级。
- 流程深度优先按“工艺 → 信号 → 代码”组织；用户点名代码段或信号链时直接深读，不要求先走其他维度。

完整项目首轮仅给总览：输入形态、资料范围、平台、初步地图、工位逻辑清单、可选对象、推荐深度、限制；不逐行讲。

## 单次讲解与系统学习

| 模式 | 触发 | 包含 | 不包含 |
|---|---|---|---|
| 单次讲解 | 「讲工位 2」「这段代码干嘛的」等单一、边界明确的问题 | 按所问范围解释 → 可选理解检验 → 后续对象建议 | 全项目覆盖矩阵、跨模块学习路线、整机综合验证 |
| 系统学习（复杂框架默认） | 「帮我看懂整套框架」「带我拆解」「精讲并整理手册」等跨模块/整体理解意图；不要求固定口令 | 依赖驱动的分阶段讲解、覆盖状态、阶段理解检查、跨模块关系分析，以及按手册规范交付的学习文档 | 不把推测补成工程事实；不宣称未验证或尚未回答检查题的内容已理解 |

单次讲解不得因为“没做审计”而拒绝交付；复杂框架请求不得只丢给用户一串对象/深度选项，应先据现有资料建立全局地图并开始第一阶段。系统学习不得跳过阶段验收直接宣称理解；阶段检查用于发现误解，不阻塞手册交付，未作答只记为未验证。

## 覆盖状态

对象状态（学习进度）：

| 状态 | 含义 |
|---|---|
| `已识别` | 确认对象存在 |
| `已分类` | 确认属于哪个任务/模块/工位/动作 |
| `已讲解` | 已生成学习文档 |
| `已理解` | 回答理解检验且无关键误解 |
| `待验证` | 证据不足或检验未通过 |
| `未分类` | 发现但无法确定归属 |
| `未开始` | 已分类但未生成文档 |

程序段覆盖状态（清单专用）：`已讲`、`待补资料`、`共用模块引用`、`受保护`、`未讲解`、`预留`。两套词不能混用；`已讲` 不等于 `已理解`。

覆盖矩阵（系统学习时按项目实际建立；没有的路径标“不适用”）：

| 对象 | 工位地图 | 自动流程 | 手动 | 初始化 | 工艺步 | 信号流 | 代码 | 报警恢复 | 交互 | 理解状态 |
|---|---|---|---|---|---|---|---|---|---|---|
| `<对象>` | 未开始/已完成/不适用 | 同左 | 未开始/已完成/不适用 | 同左 | 未开始/已完成/不适用 | 未开始/已完成/待验证/不适用 | 未开始/已完成/不适用 | 未开始/已完成/待验证/不适用 | 未开始/已完成/不适用 | 待验证/已理解 |

项目术语表：一个项目一张表，一个对象一个叫法；发现漂移立即纠正并把旧叫法记备注；只收易混对象，不超过 30 行。

## 完成标准

三种状态分别报告，不互相代替：

- **本次交付**：完成 / 未完成。只有声明范围内的源码与讲解、来源和适用门禁都完成，才登记完成。
- **项目源码覆盖**：全覆盖 / 部分覆盖 / 无法对账。可检索全量源与 manifest 六项全 0、覆盖率 100% 才称全覆盖；受保护、缺源或范围外内容仍在索引登记，不能由局部完成推成全项目完成。
- **用户理解**：未自测 / 已跳过 / 待验证 / 已理解。自测可选；只在用户回答或复述验证后登记已理解，文档交付不以答题为前提。

局部成品可跑 `validate_handbook.py --final`，元信息须有 `交付范围：局部`、非空 `本次覆盖`、`本次交付：完成`、`项目源码覆盖：部分覆盖`（无源可对账用 `无法对账`）。范围内不得留受保护/待补资料/未讲解；范围外统一列 `## 范围外缺口`：对象、原因、理解影响、所需资料。仅豁免范围外状态，全文注释、逐块来源、语义审查仍检查。未明确声明局部时，final 拒绝全文任何覆盖表/状态字段中的未完成记录。全项目完整性 final 仍拒保护块、伪源码、未覆盖；局部用 `--only-units` 限定已声明批次，不称全项目通过。

`已讲解` 表示对应范围已有文档；满足对应理解验证标准才能标 `已理解`。

- I/O 与地址表：地址类型、含义、证据来源齐全，未确认项已标。
- 公共模块：目的、主要输入输出、对工位的约束、一个典型运行条件。
- 工位：职责、程序组成、启动条件、正常步骤、输入输出、交互、关键动作链、异常处理。
- 流程/代码深度均清点可检索范围全部可读段，合并列全网络号，共享段可追溯，缺口标 `待补资料`；未讲、缺源、保护块不称完整覆盖。流程深度呈现全部源码，深讲关键段，其余讲用途/状态；代码深度逐段深讲。
- 工位完整理解：覆盖自动/手动/初始化/报警中实际存在的部分，并完成一次整机回接复盘。
- 工位外部接口：HMI/操作层、参数/配方、跨设备通讯、安全逻辑与普通互锁边界中实际存在的部分均已说明。
- 状态机：步转移表完整，每步退出条件含反馈，分支有汇合，已与工艺步映射。
- 代码解读：每小段有关键变量前置、功能条件、源码、整体说明、示例及交接；逐行/逻辑单元有效行内解释，执行行缺解释须补齐或标未完成，仅纯闭合行可登记理由省略；逐块语义审查有依据/理由，列指令语义、陷阱、工艺/信号对应。
- 工艺动作：工序主线 + 动作序列表（执行元件与完成信号）+ 并行节拍 + 手动/回原点。
- 信号流：逐跳表有地址或变量名，握手五类方向已确认，断点已列。

缩范围或仅有截图/片段且未要求深讲时，A/B 用几个自然句讲问题/目标 → 事实/约束 → 条件/状态必要性 → 推演 → 源码因果/边界；局部手册按对象结构 → 主流程 → 可确认信号链 → 可选自测。只缩范围，不省因果；缺资料列最小未知、未覆盖范围与续讲边界，不要求无法取得源码的 manifest 或全量对账。

## 整机回接与综合验证

每个工位说明整机位置：任务/主程序调用、工艺位置、公共条件、前后交接信号、异常影响对象。

```text
前置工位 → 当前工位 → 后续工位
              ↓
        公共条件与异常影响
```

主要工位讲完一轮后至少验证一个整机场景：当前工位/状态、许可、输出/等待反馈、下游影响、缺反馈停点、复位续行；未通过仅标“已完成部分梳理”。

## 理解检验与结论修订

自测可选；用户未选择时登记未自测，选择跳过时登记已跳过，不阻断本次文档交付。

分层出题，每次只问一个：

- 项目框架：调用顺序或结构关系；I/O 表：现场动作 → 地址与有效电平。
- 公共模块：公共条件对工位的影响；工位：复述正常步骤或判断交互。
- 状态机：给定当前步与缺失反馈，判断停在哪里；代码段：改一个输入，问输出与下一状态。
- 工艺：给异常场景，问操作员看到什么；信号链：移除一跳，问停在哪里。

用户答错或答不全：保持 `待验证`，先重讲再验，不只打“错”字。用户说“继续”而未答：标“理解检验已跳过”。

新证据推翻结论：原结论 → 新证据/位置 → 修订原因 → 当前结论 → 标记受影响单元重验；不静默覆盖。

## 复习检查点（仅系统学习）

- 在依赖关系复杂、结论有冲突或用户检验未通过时回看相关对象，用原题重问。
- 答错则从 `已理解` 回退为 `待验证`，重讲后再验。
- 优先顺序：交接信号 → 关键动作链 → 报警恢复 → 次要步骤。
- 基础概念在其影响当前项目推理时复查，不按固定工位数量排程。
- 复习记录写进矩阵备注并标证据与状态变化。

## 完整性审计（用户要求时）

单独输出审计文档，检查：输入形态、执行入口、I/O 表、公共框架、工位地图、切分完整性、状态机与工艺映射、工艺流程、信号流与握手、代码覆盖、HMI/参数/配方、跨设备通讯、安全边界、程序版本、报警恢复、手动/自动路径、术语一致性。

未覆盖或标 `待验证` 的内容，不得声称完整理解。

## 进度卡（无文件能力时）

不得声称永久保存。用户说“保存进度”时输出进度卡；新对话粘贴后继续，没有进度卡就说明无法确认旧进度。

## 主动引导

按当前状态理解“继续”“接着讲”“我没听懂”“先讲工位 2”“讲细”“信号走到哪”，不要求用户记命令。识别复杂框架学习意图后，先给简短路线和资料边界，再直接开始全局执行框架/调用关系；用户可随时指定对象、改变深度、暂停或跳过当前阶段。不要把路线说明变成必须先回答的冗长问卷。

开始复杂框架学习时，按工程依赖推进：运行框架与调用关系 → 代表工位的完整周期 → 第二工位对比 → 全部可读模块 → 段间关系、异常与恢复 → 手册整合和理解检验。代表工位用于先建立心智模型，不替代其余可读范围的覆盖；缺少任务/调用/实例证据时标明缺口并继续独立可证部分。单次讲解只需给出最相关的后续选项。结尾最多 3 个自然语言选择，不列命令。


## 入口下沉：逐步学习、保护与证据

### 逐步学习路径

项目逐步学习按**工程依赖**：运行框架（对象、任务、扫描、调用关系）→ 选一个代表工位推演完整周期 → 与第二工位比较共性和差异 → 工艺/信号交接与接口/实例 → 全部可读源码覆盖 → 段间逻辑、异常与恢复 → 整理可复习手册。代表工位是教学顺序，不是覆盖范围；完整手册仍须按资料覆盖全部可读部分。前层缺证据列缺口/影响，继续能独立证实的局部；不造前置关系，不阻断已有资料深讲。

- 不排天/周或工时课表，未指定时长不补造；按“检查点 + 达标证据”推进：能用本工程变量/步号推演正常与边界结果。
- 每步由实际材料与已掌握情况驱动：先看现有资料与上次产出，再定下一单元；缺资料标 `待补资料`，不用泛例填空。
- 顺序调整要说明原因（新资料、前置不足），不悄悄重排。
- 复杂框架的最终学习成果是按现有手册拆分规范组织的 `.md` 手册（单工位一册；多工位含总览与分册）；长内容先自动清点全部可读代码，在聊天中按 workflow 分段并连续完成，最后合并为 Markdown 成品。只有用户明确要求暂停/逐批确认时才停；阶段反馈可用于调整，默认不作为等待条件。
- 手册默认附简短理解检验；阶段答题可用本工程变量和状态检查回忆、预测与定位能力。只有用户实际作答并通过相关检查，才登记“已理解”；未答或跳过记为未验证，不影响交付。

### 受保护的 FB/FC（密码块）

- **说清楚**：打不开、导出为空、只有接口时标 `受保护`，只列块名、接口、调用者、输出去向。
- **给选择**：A 使用对应厂商工程软件自行合法导出（密码不进文档/记忆/聊天）；B 只走可见接口，不爆破、不绕过授权。
- **失败就停**：列出试过什么，不编内部逻辑；受保护块计入未覆盖，写清“N 个块受保护”。

### 证据与表述

- 关键结论标四级之一：`已确认`（指出依据位置）、`推断`、`未知`、`不适用`；不用笼统的“待验证”，结构文档与手册共用同一套等级。
- 不编造变量名、网络号、机械动作、维修结论；变量保留原文，首次出现给中文说明，之后不换叫法。
- 用“程序表明……”“当前资料无法确认……”，不用“肯定”“就是”。
- 工程术语首次定义，变量/方向/条件/时序精确；类比仅放块级说明后并标边界，不代替证据，语言规则见 `references/handbook-guide.md`。
- 同一变量只保留一个中文叫法；需要别名时只写一次“（简称：X）”。步号在步表、状态图、正文三处必须一致。

### 长文本分段输出

- **简约模板与章与模块两级目录**：先建章→功能模块→逻辑单元的稳定清单，目录链接到实际章节及每个模块锚点；每个单元沿用简约五部分、前置六列变量表、业务短注释、四字段、具体示例与交接，审查及验证状态不缺。目录是外层导航，不合并或删除段落栏目。全书公共说明写一次，局部专属边界在首次依赖处简注。
- **父全子小、参考先行**：每次只生成一个可核对小单元，分析上下文保留完整父结构、声明及跨段依赖；独立请求携带风格参考摘要、匹配的自造案例、命名推断方法与模板正文，不让模型凭路径猜模板。新批次确认参考仍可见，压缩/换模型/恢复后重新读取；避免为省上下文切掉外层条件。
- **落盘与恢复**：每个已接收单元单独保存，状态文件记录源范围、已完成/未完成编号、下一起点、源码与模板摘要、参考版本及各项验收状态；恢复前核对来源、模板和参考未变，已接收内容不重写不重发。规则或输入变化时拒绝混用旧批次，保留旧结果并另立重生成清单。只重试未接收单元，最终合并由清单驱动，机制细则见 `handbook-build-toolchain.md`。

- **先清点，再拆段**：自动从真实资料提取全部可读对象、代码段和源范围，建立唯一编号、先后顺序、来源与状态的覆盖清单；总量过大时仍须保留完整清单，不能只挑代表模块。源码不完整、受保护或不可读的范围单列缺口，不猜写。
- **按逻辑自动分段**：以完整闭合结构、模块边界和教学依赖切分，保留源码逐字符完整、解释与对应源码相邻；不按固定字数删内容，也不在 IF/CASE/注释/围栏中间截断。长闭合结构保留一次并按锚点分段说明。
- **连续推进**：批首标批次/总批次、本批编号与源范围；批尾记录已完成、未完成和下一批起点。助手自动继续剩余批次，不等待用户逐段回复“继续”；只在用户明确要求暂停或平台强制截断时停下，并保存可续接断点。
- **防止长文失规**：每一批都沿用所选模式的模板、因果推导、源码保真、证据等级和版式规则；不得以“前文已讲”“其余略”替代本批必要内容。上下文不足时优先完成一个完整逻辑单元，记录剩余范围，不假装已覆盖。
- **逐段质量验收**：覆盖与源码逐字保真只证明“范围交付”，不证明“代码已讲解”。每个可执行逻辑单元都须贴着源码说明目标/事实/约束（未知就标未知）、关键变量怎样参与判断、条件真假路径、具体写入与本次不写、状态保持/复位边界；挑选关键条件给出具体初值和至少三次连续执行的状态账本，并用只改变一个因素的删改反例验证必要性。只列变量、概括功能、贴回源码或反复写“未知”都不算完成。某段缺上下文时，讲清可见代码能证明的行为，把不可证部分列为待审；该段不得标记为“已讲解”，更不能用段标题或源码完整代替说明。
- **双重完成状态**：每个编号分别记录“范围交付状态”和“讲解质量状态”。范围交付可为已清点/源码已对账/存在输入缺口；讲解质量只能为未开始/进行中/通过/未通过。讲解质量未通过或待审的段保留源码和部分分析，但登记“讲解质量未通过”，不得标记为已讲解；总覆盖率与逐段质量通过率分别统计，有一段未通过就不能报告整体讲解通过。
- **最终合并**：全部批次完成后按稳定编号合并为一份 Markdown；复核源范围与覆盖清单一一对应、模块/段编号不跳不重、术语和交叉链接一致、源码无缺失/重复/改写/截断，再运行适用校验。最终交付前分别报告覆盖状态与未解决缺口；有未读源码、保护块或资料缺失时只能称部分覆盖。

### 对象讲解硬约束

必须：

- 一次只讲一个对象；先答“这段是干嘛的”，再讲条件、指令、扫描结果。
- 段间关系必须写到“哪个变量/状态从哪段到哪段、什么时候、丢了会怎样”，不能只写“然后执行下一段”。
- 用户要“剩下的概括一下”时可以不展开，但必须逐段列 `单元 | 状态 | 原因` 并标 `未讲解`；正文不得出现“其余略/略过/未展开”。
- 用户要“整体/从哪开始”时先给全貌；改版重讲先跑差异，未变单元标 `未变`、编号不重排。

禁止：

- 状态词含混：已识别 ≠ 已讲解 ≠ 已理解；地址含义只能来自符号表，没有就标 `推断`。
- 把扫描到的重复写入直接判“双线圈错误”，必须回代码确认执行顺序。
- 把中文注释混进可执行代码块，或声称注释版可直接运行。
- 下维修诊断结论，或输出 LAD/ST/SFC 三语言对照。

## 常见失败与维护对策

| 失败 | 对策 |
|---|---|
| 注释写成 `// 条件成立进入分支`、`// 结束判断`、`// 把右边赋给左边` | 改写本处意图、条件分组、数值依据与状态后果；门禁只能拦有限空话，不能证明语义，详见 `references/comment-quality.md` |
| 负例替换未命中 | 变异前断言唯一原文锚点，之后断言输入已改变，并验证坏例被拒；样例变化时同步锚点，防止空跑 |
| 把不要无用注释误解成简单语句无需解释 | 执行行均须解释可证实作用，仅无新语义闭合行可登记理由省略；禁止字段翻译、重复空话和万能“未知”，逐块语义审查后才合格 |
| 只有段落讲解，没有段间关系 | 补关系表：变量/状态、来源段、目标段、时机、丢失后果 |
| 只有代码，没有工艺 | 补动作序列表：执行元件 + 完成信号 + 节拍 |

| 一段写成几十行小作文 | 讲解 ≤10 行，超了拆段 |
| 用表格讲概念或时序 | 概念用短段落，表格只放清单与数据 |
| 文档代码与源程序对不上 | 建 manifest、标 `<!-- src: -->`、跑完整性校验，最终稿 `--final` |

| 只改模板，样例与断言没跟上 | 改呈现规则（提要、标题、必填小节）须同步规则/模板/样例/校验器/断言；查结构与实质语义，变异命中当前样例，同义改写不削弱检查；提交前跑全量回归 |
| 用户样例目录跳号（六章后直接八章）就自行补一章凑连续 | 保留用户原编号，不补章凑连续；校验器按章节签名判型。改名同步模板、样例、校验器签名与断言 |
| 对成品手册连打十几处定向补丁后直接交付 | 检查每模块四个固定粗体小标题存在、唯一、顺序，拒绝写成 heading；核对模块标题与锚点数量，防止重复或吞标题 |
| 新增对象模板后索引没登记 | 在 `references/template-index.md` 登记唯一 ID/版本/文件/路由并跑索引校验；共享字段仅在 HBK 定义，专题只写差异 |
| 危险动作词表只登记名词短语 | 按“谓语 + 对象”覆盖修改程序、旁通安全、试运行、在线改参；否定式放行，但/可以/建议/需要等正向转折不放行，保留正反例 |
| 换默认讲解版式后，旧校验器仍按已删除的旧字段判失败或旧稿被判不合格 | 双轨校验：文档开头声明版式字段（如 `讲解版式：块级`），校验器据此分流——声明新版式的只查新必填字段，未声明的旧稿继续按旧版式查；同时把旧样例首行标“历史兼容样例，不作新稿格式”并指向当前样例，否则检索会把旧样例当模板照抄。新旧各补一对必过/必拒用例 |
| 交付压缩包只在本机原目录跑过回归就发送 | 按本文件“交付包复测”执行独立解压、回归与逐字节核对 |
| 用户发截图示意“以前是这么写的”就凭图臆写 | 先搜旧版真实文本再动笔：用户指定的技能外历史归档、可用的 `.curator_backups/` 或本技能 git 历史；找到的那版作结构参照，结合截图调整，没有旧版才新写 |

**红旗：** 想直接贴 20 行代码；想用“标准八工位线”开头；想说“其余略”；想只讲代码不讲段间关系与工艺。

借口按上表处理，不单独增列；同一借口反复出现时改规则，不加章节。

## 交付校验与维护细则

### 局部产物校验

仅在有工具且实际校验模式 B 产物时读取本节，无需通读 workflow；普通讲解不做 Git 或技能维护回归。B 输出规则以 `references/local-code-explanation.md` 为权威，本节只承载执行和解析方法，不另定义输出签名。

按“固定骨架→填正文→CLI 校验→按错误局部修正→整稿重验”执行：先写完整草稿，再直接运行下列已提供的 CLI，最多 3 轮；仍有 CLI ERROR 时须报告未通过，不称完成交付。执行校验无需读取校验器源码、导入依赖、遍历工程目录或复跑技能全量测试；只有 CLI 本身报异常或用户要求维护时才诊断实现。草稿写出前不研究维护层规则，不能因语义尚未签字而一直不出稿。每次保留原始稿、错误输出和修正稿，原始与修正后格式统计分开；此为代理执行流程，不自动发远程/付费模型请求。宿主无工具时明确记“CLI 未执行”，不能自报检查通过。

下面命令仅适用于 ST/SCL 文本；LAD/FBD 不运行 ST 专用 CLI，按局部参考的图形语言分支人工核对网络拓扑、坐标和来源；其它非 ST 方言同样记录工具未覆盖的检查，不能为过门禁改写成 ST。混排时分别记录每类单元的实际检查和待审状态。

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -B scripts/check_local_explanation.py <文档.md> --source <原始ST> --allow-ai-tails
```

CLI 的 ERROR 必须先修；“结构/源码检查通过”只证明可确定项。待审清单未完成时，不称语义合格或教学验收完成。源文件为当前输入的完整副本，不凭子串或删原注释刷绿。字段和表列共享定义在 `scripts/local_explanation_contract.py`，仅维护契约时读取；两份骨架须填实后交实际检查器验证，维护者不只查词。段末标记的输出约定依正式局部参考。

**一份文档只承载一个 Mxx 模块**：该 CLI 按“一次一个 Mxx”校验，把多个样本写进同一份文档会同时报“须且仅含一个 Mxx 模块”与“有源码但没有 Mxx 模块正文”。多样本测试先拆成单模块文档逐份过 CLI，全部通过后再合并成交付稿；合并后要再对合并稿本身分模块核对，不能拿“各份单独通过”宣称合并稿通过。

单模块文档缺任一项即 ERROR，第一次出稿就按此骨架写：

- 元信息块四项非空且各出现一次：`工程`、`讲解深度`、`讲解版式`、`模块编号`。
- 模块标题**之前**恰一张关键变量表，列固定 `变量 | 数据类型 | 方向 | 含义 | 谁写谁读 | 证据等级`；放到标题之后、或出现第二张，都报错。
- 模块标题之后、第 1 小节之前恰一行 `**一句话说清**`，不含变量名与 `IF/CASE`。
- 第四部分执行示例表列固定 `阶段/执行 | 输入与原状态 | 本段处理 | 执行结果`，只此一张，每组轨迹至少三个不同执行序号或时刻。
- 标题不跳级：文档 H1 之后模块为 `### M01`，小节为 `#### 1. …`；从 `##` 直接落到 `###` 之外的层级会报“标题层次跳级”。

**模式 B 注释版的校验**：追加注释版直接使用 `check_local_explanation.py <文档.md> --source <原始ST> --allow-ai-tails`，逐行只允许完整原码之后追加非空 ` // AI: `，原作者注释和字符串中的标记不截断；原样代码不传该参数。分别报告实际新增尾注与原注释保留情况，不把源码/结构通过当注释语义通过；B不跑整册 validate_handbook.py。

局部门禁按轨迹 A/B 分组，要求每组至少三个不同的执行序号（如 `A第1次`、`A 第二次`、`A 第三次`）；同一数字的中文/数码写法不重复计数。纯时刻标签如 `0ms/100ms/200ms` 也可采用，每组同样须有三个不同时刻。这个数量底线不证明时序连续、状态承接或因果正确，仍须逐项人工审查。

**正文覆盖映射与标记解析**

在第三部分每段对应说明前写源范围映射，例如 `<!-- explanation: L1-L1 -->`，下一行紧接该范围的具体说明；行号从当前输入片段第一行起，含空行/原注释，不冒称工程行号。跨多个源码围栏按原序连续计行。暂未说明或未核对的范围写 `<!-- unreviewed: L7-L7 -->` 并在下一行说明待查对象，列入未审清单；零基础口径两者均无则 CLI 报覆盖错误。默认口径只要提供了标记，仍校验范围、位置与对应正文；空标记、只有标题、借用下一必填字段或源码内伪造标签不能充当解释。实际说明可以使用 `**末行**：具体说明……` 这类非契约字段的粗体引导。范围覆盖只是机械映射，真实作用、概念理解与因果仍需人工逐项审阅，不能因为出现“未知”而放行。

**源码围栏拼接与 EOF 处理**

**逐字符比较，不以行数或关键字计数代替。** 从讲解产物提取承载源码的代码围栏，按原顺序拼接，与当前输入片段比较；空白、缩进、原注释、变量拼写、括号和语句顺序都在比较范围内。按行计数和关键字计数只能辅助定位，不能证明未改写；例如 ` THEN` 改成 `THEN` 时各类计数完全一样，仍不满足逐字保留。本 CLI 不统一 CRLF/LF，也不使用 strip()、缩进归一化或移除原注释来刷成相等。各源码围栏的物理内容行按序直接拼接，末尾换行也参与比较；原输入末行无换行时，在最后源码围栏闭合行后紧邻单独写 `<!-- source-eof: none -->`，只排除为闭合围栏添加的一个末行换行，其他末尾空行全部保留。输入有末尾换行就不写该标记。无末尾换行时，可复制以下结尾：

````markdown
```st
(* 原始源码最后一行 *)
```
<!-- source-eof: none -->
````

标记行自身允许尾随空格或制表符；源码围栏内容与原始源码仍逐字符比较，不去除任何源码空白或归一 CRLF/LF。比较结果出现“输出比输入多 1 字符、差异位置落在末字符”时，先查是否漏写 `<!-- source-eof: none -->`，而不是判定源码被改写：从归档围栏抽出的源码块通常没有末尾换行。

### 完整手册与归档产物校验

完整手册、结构与源码归档按实际产物选择下列命令；普通 B 只执行上一节的局部校验，不运行技能维护命令。

```bash
python3 -B scripts/validate_overview.py <00-总览.md>      # 一屏约束、六块必备、分册索引
python3 -B scripts/validate_structure_map.py <10-结构.md>   # 章节、段索引、关系表证据与等级、阅读顺序
python3 -B scripts/check_structure_drift.py --doc <10-结构.md> --manifest <manifest.json>  # 只报漂移，不改文件
python3 -B scripts/validate_handbook.py <手册.md>          # 按适用章节、证据标记和源码覆盖校验
python3 -B scripts/check_plc_comments.py <文档.md> --require-every-line  # 用户要求整册逐行注释：非空执行/结构行（含闭合）须有有效尾注
python3 -B scripts/validate_handbook.py <手册.md> --final --comment-review <逐块审查.json>
python3 -B scripts/check_plc_comments.py <文档.md> --final --comment-review <逐块审查.json> --require-every-line
rg -c '^#### M[0-9]+' <手册.md>; rg -c '^<a id="m[0-9]+"></a>' <手册.md>  # 模块数=锚点数，防补丁插重复/吞标题
python3 -B scripts/check_markdown_format.py <文档>          # 表格列数、围栏、元信息
python3 -B scripts/check_document_layout.py <文档>         # 目录顺序、标题命名、围栏配对、表格与段落可读性
python3 -B scripts/validate_st_rendering.py <文档>         # ST 围栏边界、语言标签与未闭合/非法块行号
python3 -B scripts/check_content_consistency.py <文档> --strict  # 术语叫法、步号、空章节、重复段落
python3 -B scripts/make_manifest.py <导出文本> --out manifest.json
python3 -B scripts/check_code_integrity.py --manifest <清单> --doc <文档>   # 分批 --only-units，最终 --final
```

- **整册注释版**：用户要求每行代码加注释时，必须额外运行 `check_plc_comments.py --require-every-line`；每条非空执行/结构行（含闭合行）有有效尾注，空白/纯注释行不重复补注，已有清楚注释不冗余追加。先核原码与原注释前缀，再核遗漏、低价值和重复问题；五部分正文保持，不另建逐行表。普通局部 B 默认业务短尾注版，局部校验使用 `--allow-ai-tails`；要求原样时不用该参数。
- ST 源码/示例必跑渲染检查，非法/未闭合围栏报开栏行号；手册再跑手册、注释、格式/版式/一致性检查，final 绑定逐块审查。执行单元解释、闭合行省略与记录见 `references/comment-quality.md`；逐块检查覆盖、证据和因果质量；源码解释沿用行内注释规则，未审/有错不合格，静态通过不证明语义。
- 源码来源语法与逐块绑定见 `references/comment-quality.md`。代码完整性仅在具备匹配源文本与 manifest 时运行；六项（缺失/重复/多余/改写/截断/归属）全 0，最终覆盖率 100%。受保护/待补资料存在时结论只能是“部分覆盖”。
- 每个源码块独立绑定紧邻来源标记，无有效 `<!-- src: -->` 标注按未归属处理；若声明 `适用章节`，只允许声明范围内的章节，目录、矩阵、状态图与源码模块只在文档实际包含时校验。
- 新增规则同步规范/模板/样例/校验器/正负用例；模板查索引/链接，成品查适用性，不将占位符当项目内容。每项至少合法必过、非法必拒一对，先拒绝用例后校验器，先红后绿；变异锚点唯一、文本确变、坏例确拒。`validate_skill.py --strict` 报 `SKILL.md` 超 200 行时，细则移 `references/` 并登记 catalog，不压缩规则或忽略警告。`适用章节` 等声明须实际过滤校验范围，仅打印不算校验。

### 交付包复测

仅制作或审计交付压缩包时执行；同义要求合并在本节。

运行包与维护仓库分别验收。维护仓库归档保留 evals、维护脚本与登记，解压后执行完整回归和严格检查；独立运行包按用户分发范围排除这些维护资产，解压后执行 `scripts/validate_skill.py . --strict --runtime`、模板索引与包内实际运行工具的正反例，不要求不存在的 evals。`--runtime` 仅豁免明确的维护资产，仍须检查所有包内引用与登记，不得忽略包内运行资产的缺失。两类包都断言 `testzip()` 通过、条目清单与获准源文件集合相等、每条字节相同，实际外发字节经过隐私扫描；复测结果与包路径、哈希一并报告。成品手册包按所含产物执行适用检查，不当作技能仓库执行回归。

### 技能维护回归

仅修改/审计技能时，以 `evals/run.py` 为唯一回归入口，完整运行并读取结果；四条维护校验如下，不用于普通代码讲解：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -B evals/run.py
PYTHONDONTWRITEBYTECODE=1 python3 -B scripts/validate_skill.py . --strict
PYTHONDONTWRITEBYTECODE=1 python3 -B scripts/validate_template_index.py
git diff --check
```

优化以实际讲解中的证据、因果与阅读缺口为目标，不以文件体积或规则数量代替质量。

全量回归有失败时先分类再动手：断言指向本次未触碰的模块（批次元数据必填性、CLI 错误文案期待、轨迹计数边界），且失败与本次改动无关，就把测试名、断言差异和所属模块单列成“既有失败”，不计入本次通过/失败；窄范围修复授权下不顺手改它们。改动之后才出现的失败默认归因本次改动，先复现断言再定位，禁止混报通过或把无关失败写成“回归全绿”。

### 版本与 Git 管理

独立 worktree 可以对单条 Git 命令临时设置 `privacy.originalHooksPath` 为已核实的候选项目钩子；必须保留宿主 `core.hooksPath`，并在相同进程配置下执行 `scripts/hooks.py doctor --effective`。该诊断验证实际宿主与委托字节，不声称取得安装器所有权，也不豁免历史隐私。共享配置不为单个 worktree 覆盖；未通过诊断不提交，不用 `--no-verify`。`doctor` 原安装状态检查与 `doctor --effective` 的实际链检查分别报告。

仅维护技能时加载；日常讲解不读本节，也不替用户提交或推送。

- 仓库就是技能目录本身，主干分支 `main`，默认只做本地提交；推送、打标签、发布另需当前任务的明确授权。
- `.gitattributes` 固定 `text=auto eol=lf`，夹具目录整体关闭文本转换，保证夹具源码逐字节保真。换行变化属于缺陷，不是格式噪音。
- `.gitignore` 排除本地产物：`.ai/`、`_preview/`、`_backup/`、`__pycache__/`、`*.pyc`、`.pytest_cache/`、`*.log`。测试副本、冻结包与审计日志留在技能目录外，不靠忽略规则掩盖已误加入库的文件。
- 新克隆先设 `git config core.hooksPath .githooks` 与 `git config commit.template .gitmessage`。`pre-commit` 先扫描整个真实暂存树（不是工作区或增量 diff），再跑严格结构、模板索引和暂存区空白检查；完整回归可用 `SKILL_PRECOMMIT_FULL=1`，隐私检查不能跳过。
- `commit-msg` 要求英文 type（feat/fix/docs/refactor/chore/merge/perf/release/revert/test/build/ci/style）、英文小写 scope、含中文标题（至多 100 字符）、空行后至少一条 `- ` 分条正文，同时扫描消息隐私。仓库自带 hook 负责执行格式与隐私检查；测试只在临时仓库中复制并调用 repo-local hook，不依赖调用者的全局 Git 配置或 home 目录下脚本。
- `pre-push` 对拟推引用的全部祖先内容与提交/标签消息扫描，禁止删远端引用、非快进及移动已有标签；未知远端对象先 fetch。首次推送前执行 `python3 -B scripts/git_privacy_gate.py audit`，包含不可达对象。
- 私有源码、个人资料、真实 IP、本机绝对路径、凭据与本地产物不得进仓库；只用明确合成夹具。策略仅保存哈希指纹，改名或去掉功能块名不能解除已知源码片段拦截；`git add -f` 也检查。不得用 `--no-verify`、更换 hooksPath、删改策略或跳过变量刷绿；门禁失败须修复。
- 本地钩子不能对抗有权限者主动绕过；添加远端须经授权，并启用分支/标签保护和 CI 同等检查。清理历史必须先核对远端；不得用 force 覆盖已存在的远端历史。
- 日常开发在 `CHANGELOG.md` 的“未发布”记录，不自动升版；仅在用户确认发布时确定本技能的发布版本。模板格式版本按模板索引单独维护，不与技能发布版本混用。
- 一个提交只承载一类变化：规则与其配套模板、样例、测试同属一次；测试输出、压缩包、审计记录不进提交。
- 提交前用 `git status` 与 `git diff --staged` 自查暂存范围，确认没有临时脚本、备份目录或注入本机绝对路径的文件；提交后核对 `HEAD`、文件清单与工作区干净。
- 不用 `reset --hard`、`clean -fdx` 或强制推送清理现场；需要回退时用 `git revert` 或从目录外备份恢复，并保留原提交。
- 备份不是提交的替代：改动前仍按「技能维护与成果保护」把整份技能复制到目录外，并按文件记录 SHA-256。

### 入口与契约回归

改 A–E 选择器或源码确认门禁前后跑 `evals/test_entry_routing.py`、`evals/test_first_principles_contract.py`，最后跑 `evals/run.py`。前者查模式行/最小范围/安全/维护隔离/标题边界，后者查第一性原理与源码确认暂停的静态变异，均不证明会话表现。不按正文 B/C 单字切片，不跨行贪婪匹配标题。

契约测试检查块内非空内容及对应来源，不只查标签；坏例至少覆盖空节、删真值/扫描数据、教学协调器冒充原 leader、只有一个块有六槽位、Result 残段漏讲。变异前断言唯一锚点，之后断言输入确已变化；拒绝用例先红后绿，禁止删检查或放宽安全消错。

### 行为微测的验收口径

仅在技能维护/审计且本轮授权行为微测时，用固定脱敏夹具跑同一提示词多次生成，原稿保存不改；不自动发起远程/付费请求，不扩大采样。格式层与语义层分开报数，不合成一个“通过”。

- 每批先冻结当前 `SKILL.md` 与对应参考，记录各文件及合成系统指导的 `system_sha256`，将实际请求内的系统文本随原回答保存；评分前重算并对照该批冻结副本。原回答只证明该批版本；期间技能有修改则将旧批标为历史迭代，不能冒称最终版本验证，另对最终文件开启新批。
- 格式层从产物独立提取，不采信生成方自述：围栏按原顺序拼接后与夹具逐字符比对（不拿行数或关键字计数代替）、五部分顺序、关键变量前置、标题表情、有无新增教学注释；模块的四个粗体字段要各自存在且唯一。
- 语义层必须重推导再签字：把示例里的布尔表达式逐条代入求值（`FALSE OR (NOT TRUE AND TRUE)` 为假，常被误判为真），核对每次扫描写的是否为同一数组元素，核对正文声明的条件个数与实际枚举项数是否相等。
- 长文按源单元计数：报告“范围交付完成数量 / 逐段质量通过数量 / 待审或未通过数量”。覆盖率不能代替讲解质量；有一段未通过就不能报告整体讲解通过。质量审查要对照源条件、逐步重算状态账本、核验单因素反例；标题、模板字段、关键词、源码哈希和模型自评均不能代替语义证据。
- 报告内嵌的冻结哈希随技能文件一起失效：出稿后又改过 `SKILL.md` 或参考文件，必须重算并替换报告里的对应哈希，再重新逐字对账嵌入的源码块与夹具归档、核对单元计数与反例数量，然后才谈交付；哈希指向旧文件的报告不得发出。旧稿被判不合格且已获授权时，删除旧稿按新规则重做，不在旧稿末尾追加“修正版”“补充说明”，原始输入归档保持只读。
- 跨端/协议类结论用独立实现复算，不靠通读后签字：把模型给出的字节序列用自己写的编码器重新组帧并逐字节比对，再把模型声称的分步轨迹逐步喂给真实消费端代码（解析器/FB 调用），比对每步产出的帧数、缓存字节数与错误计数。两级都对上才算语义通过；只对上文字结论不算。
- 请求完成、格式合格、语义合格是三个数，分开报。请求报错、正文为空、`finish_reason=length`、一批只要到部分样本，一律记 `failed`/`incomplete` 并写清已验证的完整产物数；不同 variant 或不同提供方的批次不互相补数，也不把“请求返回”写成“讲解合格”。同一失败批次只留档一次、不重复发起同一请求；后续延迟到达的旧通知只核对已存证据并标为历史批次。
- 删掉聊天执行前言只是第一行：清理后的文本要重跑完整版式门禁（源码块超过分段上限、字段缺失、标题层级仍在），在清理稿上通过才可报格式合格。
- 按样本记 `accepted` 与 `issues`，用 `文件名:样本` 定位；`issues` 写触发规则的那句话，不写“质量一般”。
- 结论分栏：格式 5/5 只证明格式，语义 0/5 就写 0/5；聚合回归全绿不构成输出可用的证据。
- 夹具是脱敏样例，不代表用户真实工程，一批样本也不证明长期稳定。先完成本轮规则修改再冻结测试输入；测试期间新增修复进入下一批并保留旧批失败，不边改指导边把结果合计。测试不构成提交、推送或发布授权。

### 测试夹具与真实归档的可行性预审

用户要用"复杂真实代码"验证新增规则时，先审输入本身；把"归档存在"当成"源码完整"会让整轮验收建立在错误前提上。

- **逐段抽取再计数**：用围栏正则把归档拆成独立代码块，记录块数、行数、字节与 SHA-256；块数为零或围栏不配对时先修抽取，不进入静态检查，也不用行数/关键字计数代替逐字比较。
- **对账哈希前先确认口径**：逐节 SHA-256 与当前围栏内容算出的值不一致，说明清单按别的归一化或别的文本生成，不能拿它证明各段逐字保真；整文件哈希一致只证明文件未变。
- **区分原始源码与教学重建**：把每个归档块原文在讲解/教程文档中做精确子串查找；命中率低（如十段只命中两段）即证明文档是重写而非逐字覆盖，不能充当"完整覆盖"的答案键。
- **读归档自己的缺口声明**：标 `partial` 或未与原始 XML 核对的节必须带着缺口进测试，验收标准写成"完整清点并标出缺口"，不写成"完整覆盖并通过编译"。
- **合成夹具不当可编译 POU**：`evals/fixtures/complex-st/FB_StationCell.st`、`evals/fixtures/complex-st/FB_LineScheduler.st` 这类夹具可缺 `END_FUNCTION_BLOCK`/`END_METHOD`；`check_st_logic.py` 严格模式对它们报错属夹具形态事实，不是技能缺陷。静态门禁以该检查器自身单测加合法片段必过用例为准，不拿整套夹具的严格结果当长文功能的通过条件。
- **片段语料先过 survey**：`survey_program.py`/`make_manifest.py` 依赖 network/section/pou 标记，纯片段拼接会报"未识别到程序单元"；需要时显式 `--pattern section` 或按源格式补标记，不据此判定语料不可用。
- **关键词测试不替代行为测试**：只断言规则文案含关键词的用例（如长文分段契约测试）证明的是文案存在；行为合格须按上一节冻结 `system_sha256`、真实生成并分开报格式层与语义层，未跑就写"未执行行为测试"。
- 预审结论分三栏：输入完整性、现有工具能覆盖什么、必须新增什么；只做审计时明确"本轮未改技能与参考资料"。

### 审查与用户成果保护

仅教学重建或用户明确要求完整审查时，先审后发。按原始问题逐条给 `满足` / `部分满足` / `不满足`，阻断项优先，说明新手能做和不能做的事；`部分满足` 视为未完成。缺运行入口、恢复或交接证据只能称待验证；逐阶段盲走方法见 `references/teaching-from-scratch.md`。

独立审查/修复分两轮：只读发现用 D/E/U/S 编号、`路径:行号`，区分事实/解释/未知；修复按编号先复现负例。审查前后取全部输入 SHA-256，保护归档/旧报告。委托进程异常重复输出即停进程、留成果、实跑验证；缺报告不等于失败，不据此回滚或重做。

### 技能维护与成果保护

仅维护本技能时加载本节；日常讲解依据当前规范与选定模板，不读取历史对话、变更记录或维护报告来拼装执行规则。

- 先固定当前任务的验收目标、适用模式与保留项；已有明确修复授权就按该范围实施；一次“提交”授权持续到用户撤回或另有限制，仅提建议、预览或新会话不自动构成提交授权。
- 改前核对版本、CHANGELOG 顶部、Git 状态与已有未提交成果，整份备份到技能目录外，按文件保存 SHA-256。不得 reset、clean 或覆盖先前成果；不因评价旧版更好而自动回滚，恢复旧版须有明确对象与授权。
- 讲解质量改造用同一段真实或固定脱敏难例作前后对照，覆盖时间、保持、故障与恢复。明确所解决的那一句解释和具体失败，不用目录体积、字段数量代替质量。

- 改后运行本文件“技能维护回归”的四条校验，检查实际受影响样例；同题行为微测仅在授权时执行，分开报告静态和语义结果。历史归档与输入只读保护；子代理自报须核实，不因缺总结回滚或重复实施。

旧工位说明书、审计报告、结构深度写法、完整变更记录如另有归档，使用用户实际提供的位置；没有归档时按手册格式重做，不另写旧制或整批加回；入口保留手册主线。
