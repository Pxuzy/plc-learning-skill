# 结构梳理文档写法 🗺️

结构文档是手册前置导航：**先摆清程序结构与阅读路径，再逐段读代码。**

## 一、生产者与消费者 🔄

- 产出：一份 `结构梳理.md`，字段固定、表格可核对。
- 用途：定位对象、判断影响范围、决定阅读顺序。
- 不写：逐段代码讲解、工艺细节推演、控制逻辑结论。这些属于手册。

## 二、层级与字段 🗂️

按工程实际组织，自上而下不跳层：

| 层 | 必含字段 |
|---|---|
| 任务 | 名称、类型、周期、工位调用顺序、公共条件 |
| 工位（POU） | 名称、职责、段构成（按工程命名）、主要输出、关联工位 |
| 段 | 段号、名称、类型、功能定义（一句）、输入、输出、行/网络范围、覆盖状态 |
| 变量 | 名称、类型、写入点、读取点、跨周期与否、地址或映射来源 |

段类型采用工程命名：映射段、手动段、自动段、报警段、通讯段、参数段、初始化段。工程没有的类别不列。

## 三、关系表的写法 🔗

每条关系一行，字段固定：

| 字段 | 要求 |
|---|---|
| 类型 | 调用 / 数据 / 步序 / 互锁 / 异常 |
| 来源 | 工位 + 段号 |
| 目标 | 工位 + 段号 |
| 载体 | 变量、结构体成员、FB 实例或映射地址 |
| 时机 | 同周期 / 跨周期 / 条件触发 |
| 后果 | 该关系缺失或顺序颠倒时的表现 |
| 证据 | `<!-- src: 起-止 -->` 或网络号 |
| 证据等级 | `已确认` / `推断` / `未知` / `不适用` |

规则：

- 无证据不建边。仅凭命名相似推断的关系，证据等级写 `推断`，并说明依据。
- 多处写同变量，列全写入点/先后；顺序不明标 `未知`，缺口列所需顺序证据，不判双线圈。
- 跨工位信号注明是映射区、全局变量还是通讯缓冲区。

## 四、阅读顺序 🧭

按依赖关系排序，不按文件顺序：

1. 公共条件与模式切换（决定其余逻辑是否执行）；
2. 映射段（外部信号如何进入内部变量）；
3. 自动段的主步序（按步号顺序）；
4. 手动段与回原点（与自动的互斥关系）；
5. 报警段与复位路径；
6. 通讯段与上下游工位交换；
7. 参数段与配方（影响阈值与时序）。

每步列段、先看变量、应答问题；这是**阅读顺序**，不排教学计划。

## 五、证据等级与漂移 🔍

- 证据等级四级（对应通用结构梳理技能的 observed / inferred / unknown / not applicable）：
  - `已确认`：有源位置可直接核对；
  - `推断`：有结构或命名依据，但无直接代码证据；
  - `未知`：证据缺失，无法判断；
  - `不适用`：该对象不涉及此维度（例如工位无通讯段）。
- 不使用“待验证”笼统代替四级；确实存在冲突时写 `推断` 并在缺口章列明冲突双方。
- 文档头记录 `source_sha256`；工程换版本后，未变工位标 `未变`，变化工位标 `待复核`，不静默沿用旧结构。
- 图码不一致，以代码为准列差异，不为自洽改结论。
- 漂移检查独立执行，只报告不改文件：`python3 scripts/check_structure_drift.py --doc 10-结构.md --manifest manifest.json`。

## 六、借鉴范围 📚

仅借鉴以下四项，不引入通用结构技能的解析器/工具链：

| 借鉴点 | 来源做法 | 本技能落地 |
|---|---|---|
| 一页入口 | 索引文件控制在约 2000 tokens | `00-总览.md` 限一屏，细节留在结构分册 |
| 阅读顺序 | 按依赖给出先读哪些文件 | 结构文档“阅读顺序”章：读哪些段、先看哪个变量 |
| 证据分级 | observed / inferred / unknown / not applicable | `已确认` / `推断` / `未知` / `不适用` |
| 漂移检测 | `check` 只报差异不写文件 | `check_structure_drift.py`，输出未变/新增/删除/摘要不符 |

## 七、质量线 ✅

- 执行树能复述“上电后先跑哪个工位、再跑哪个”；
- 段索引条数 = 工程实际段数，缺项标 `待补资料`；
- 关系表每条都有证据列与四级证据等级；
- 变量表能回答“这个变量谁写、谁读、是否跨周期”；
- 阅读顺序覆盖全部工位，且顺序有依赖依据；
- 文档不出现“其余略”“同上”。
