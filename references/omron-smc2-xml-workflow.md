# 欧姆龙 SMC2 XML 分析工作流

**状态：方法参考，不表示已验证所有 Omron 工程或版本的解析支持。** 仅在已确认品牌为 Omron、产品线为 NJ/NX、来源为 Sysmac Studio SMC2，且本次容器/字段结构适用时加载。品牌相同、后缀相同或已经解包都不够；控制器与软件版本未提供时记录未知，按当前样本核对，不能推广为全版本支持。其它品牌/格式回到[通用工程读取](workflows/read-project.md)和[厂商经验入口](vendors/README.md)。

## 一、条件适用的读取顺序

```text
核实来源、版本线索和真实容器结构
→ 安全清点归档（或清点用户已解包目录，注明未核对原归档）
→ 读取工具支持时直接读取归档成员；否则先受控解包一次到独立副本（已解包目录直接读取，不重复解包）
→ 检查当前样本中的 .oem / 其它工程描述及真实 schema
→ 若 .oem 确实承载对象层级与引用，据此恢复原生工程树
→ 按真实引用映射 .xml / .json / .st 或样本实际的代码与配置对象
→ 回读声明、程序体、调用和变量，核实映射与缺口
→ 回到原定导航/局部讲解/完整范围路线
```

`.oem` 是本方法预期检查的描述文件，不是所有版本必有的固定 schema。未发现它、它不含层级引用、或字段与经验冲突时，不凭文件名拼树；记录差异，检查实际描述/引用，必要时索取最小工程树或目标导出。不臆造专用解析器，不把描述字段当 ST 程序体。

## 二、单目标 FB/POU 快速定位

按输入形态和用户明确任务选最小读取范围。可读 `.md`/`.st` 等文本直接读取相关内容。已确认 SMC2 中用户只要求单个 ST FunctionBlock 的声明或程序体时，才使用当前只读定位器；它不先做通用清点或解包，不调用批量清点器、不写工程，也不做目录全文源码搜索。完整工程范围仍走通用清点。当前合成回归覆盖 `sysmac schemaVersion="1"` 下同一 namespace 的顶层 `Entity` 树，或根 `ChildEntities` 容器中的 `Entity` 树，以及 `type="FunctionBlock"`、`subtype="StructuredText"`/`"ST"` 定义；两种根布局混用或目标相关 `Entity` 落在其它容器中都视为 `unsupported_layout`。OEM 中 `name` 用于筛选定义候选，不能作为唯一键；不得把名称当唯一键或覆盖重名候选。`type` 区分类别，`subtype` 提供语言/载体线索。以 `id` 结合 namespace、父子归属和显式引用核对身份与作用域。角色按定义的直接同 namespace `ChildEntities` 子实体 `type="Variables"` 或 `type="PouBody"` 识别；`name` 仅是显示信息，允许本地化或缺失。相同角色类型出现多次时保留歧义，显示名恰似英文角色但 `type` 不符时不选为角色。上述是窄布局假设，不表示真实工程或厂商版本支持；其它对象类别与未知布局须先核对样本结构，不推测 schema。

### 默认：直接导出一份可续读的 Markdown

已确认品牌/产品线/格式后，默认用脚本绝对路径调用，不依赖 `PYTHONPATH`，不安装名为 `scripts` 的包，也不在任意目录尝试 `from scripts...` 导入。带中文和空格的路径作为独立参数传递；已有输出需选新文件名，不覆盖原件。

```bash
python3 -B "<技能绝对目录>/scripts/smc2_locate_pou.py" "<工程绝对路径.smc2>" "<精确FB名>" --output-md "<输出绝对路径>.md"
```

技能工作流默认采用 `--output-md`，CLI 原 JSON 调用保持兼容。`--part` 仍按本次请求选 `both`、`body` 或 `variables`；默认两分支。导出时不必叠加 `--include-source`，即使叠加也只回简短摘要，不打印全文。Markdown 中按中文章节展示来源、中文变量表、程序体、校验结果和完整原始声明；变量表只转换已识别字段，不猜类型/方向/初值。原文本及未知字段完整保留，围栏按源码动态选择。

发布前实际回读文件，校对请求范围、源码字符/换行/末行、变量表与既有严格 Markdown 渲染；相关依赖沿用 `scripts/requirements-markdown.txt`。摘要分别报告定位状态、导出状态、已核验文件位置与章节。提取不完整、写入/渲染失败时不发布伪完整稿，已有文件、链接目标、输入目录或技能内部路径均不覆盖。

完成导出不等于完成用户任务：只提取/发文件就按宿主能力交付；要求讲解、分析或修改时，从这份只读底稿按章节读取必要范围继续，结果另存，并执行[对应产物校验](output-validation.md)。不重复加载整套技能、不先打印长源码，也不因工具回显截断重新定位。文件存在不等于附件已送达，交付不强制某个平台语法或固定输出根。

备用方式：已在技能根目录时，可以 `python3 -B -m scripts.smc2_locate_pou` 携同一组参数运行。以下保留兼容的 JSON 调用与候选查找示例；不用它们打印长源码再由模型抄写成文件。

从技能根目录运行：

```sh
python3 -B scripts/smc2_locate_pou.py <工程.smc2> <精确FB名>
python3 -B scripts/smc2_locate_pou.py <工程.smc2> <精确FB名> --part body --include-source
python3 -B scripts/smc2_locate_pou.py <已批准解包目录> <精确FB名> --part variables --include-source
python3 -B scripts/smc2_locate_pou.py <工程.smc2> <名称片段> --fuzzy
```

默认 `--part both`，JSON 默认只含坐标、映射依据、证据和状态；仅 `--include-source` 输出所请求且已核验分支的源码。变量分支保留完整 SLWD 文本，并只要求可靠的 `[SLWD version=1.0]` 头及可读声明载荷；这不表示已由真实工程证实 SLWD 语法。ST 分支必须唯一解析到 `StructuredTextModel` 的直接 `Text` 子节点；输出是 XML 节点解码后的逻辑文本，保留有意义的空白，XML 换行按 XML 规则归一化。内容指纹只核验内容形态，不是目标归属证据。

定位器先只读成员清单/目录元信息，校验全名、原始归档路径、GUID 基名、重复/不安全路径、链接、普通文件属性及成员数、总量、单文件预算，然后只打开唯一 OEM 和目标请求分支。目录不得含符号链接、硬链接或非普通文件。默认预算沿用清点工具：5000 成员、512 MiB 总声明量、256 MiB 单成员；OEM/XML 实际解析受 8 MiB 上限约束。可用 `--max-members`、`--max-total-bytes` 和 `--max-member-bytes` 调整预检预算。拒绝 DTD/ENTITY。`--fuzzy` 只列 ST FunctionBlock 定义候选，即使候选唯一也不打开源码。

对象身份与内容成员分别核对：定义 ID 选择 OEM 中的目标定义；角色 ID 是其直接子 `Variables`/`PouBody` 的 ID，定位结果以 `role_id` 记录；定义和所选角色 ID 均须是有效 GUID；Holder ID 只标识 Holder 实体；内容成员是经验证的 ZIP 成员路径。当前快路径只在上述合成覆盖布局中，按所选角色 GUID 的 XML 基名查唯一 `<GUID>.xml`；不使用定义 ID 或 Holder ID 拼文件名，也不因内容相似证明归属。Holder 不默认作为必经步骤。可验证回退只接受所选角色本身或类型正确的唯一 `SourceHolder`/`PouBodySourceHolder` 上明确给出的安全相对 `SourcePath`、`FilePath` 或 `URI`，并按完整相对成员路径精确匹配；Holder 显示名不参与身份判定。错误类型的 Holder 不参与回退。重复角色/Holder、重复成员、危险或歧义路径、多个字段冲突，以及显式引用与 GUID 直读指向不同内容时，返回 `reference_conflict` 或保留对应失败状态，不静默忽略。

上述快路径不得把名称当唯一键或覆盖重名候选；定义、角色或内容成员缺失或不唯一时，分别保留未找到、缺失或歧义状态，不自动改查别的对象。

对象类别和内容映射须按本次样本核对：

| 对象类别 | 分类与只读核对（候选判据，官方 schema 和真实版本映射待验证） | ID、归属、引用与内容指纹（载体不能仅凭 `.xml` 后缀或 `type` 判定） | 当前自动提取范围 |
|---|---|---|---|
| 代码 | `FunctionBlock`、`Function`、`Program`、`PouBody` 是定位定义或程序体的线索。`name` 筛候选，`type`/`subtype` 提供类别与语言线索 | 核对定义或角色 ID、父子归属、显式引用及成员唯一性。FC、Program、段/网络均按样本核对。ST XML 和 Ladder JSON 按实际内容及边界确认，Ladder 未新增解析器 | 仅单个 ST FunctionBlock 的程序体，限已覆盖的合成布局 |
| 声明与变量 | `Variables` 是声明节点线索。用父子归属、声明组和引用区分局部与全局，不能仅凭 `type` 推断作用域 | 核对角色与所属定义、组、引用和内容成员。SLWD 按实际内容指纹和声明结构确认 | 仅单个 ST FunctionBlock 的声明，限已覆盖的合成布局 |
| 数据类型 | `DataType` 是类型定义线索 | 区分全局变量、DataType 类型定义及其引用关系。XML 仅为候选载体，须核对样本内容与成员归属 | 本 CLI 未支持 |
| 任务/程序关联 | `NexTask`、`NexAssociatedProgram` 为用户报告的候选标签，需在实际样本上核验 | 核对任务与程序实例的 ID、归属和显式关联。同名不能证明调度绑定 | 本 CLI 未支持 |
| 硬件配置 | `AxisSettingEntity`、`NexEcatConfiguration` 等为用户报告的候选标签，需在实际样本上核验 | 核对配置归属和引用，硬件元数据不能作为代码 | 本 CLI 未支持 |
| 组织/持有节点 | `Group`、`ChildEntities`、`SourceHolder` 提供层级或持有关系线索，不作为程序体 | 核对父子归属与显式引用，Holder ID 不一定对应内容文件 | 本 CLI 未支持 |

变量声明成员先识别 `[SLWD version=1.0]`。现有定位器保留原 `VAR…END_VAR` 合成载荷兼容，并识别制表符分隔的 `+GN=` 组和 `++D=` 声明记录；声明须有非空类型 `D`、名称 `N` 及明确或继承的组。已知元数据、未知扩展字段和换行按原文保留，不把 SLWD 转成 ST；空声明、缺必要字段、重复字段、截断或 NUL 内容拒绝。这里只验证已覆盖的合成结构，不声明完整 SLWD 语法或真实厂商版本支持。

Ladder 载荷须先验证实际格式；单个 JSON、逐行 JSON 或连续 JSON 按样本中的真实边界解析，不能默认逐行。TXT 仅代表可见文本片段，不等于完整图形或完整引用分析。可建议按 `id`、`name → list`、`type/subtype`、父对象和成员 GUID 建立分类索引；这描述定位流程，现有定位器的内部映射不构成通用列出或全文搜索接口。性能未实测，不能宣称所有查询为 O(1) 或小于 0.2 秒。

顶层 `complete` 表示请求分支均完成；`partial` 保留可用分支并显示分支状态。其它顶层状态区分 `object_not_found`、`ambiguous_definition`、`duplicate_id`、`unsupported_layout`、`missing_oem`/`ambiguous_oem`、路径/预算拒绝和 XML 错误；分支状态区分角色缺失/歧义、成员缺失/歧义、引用冲突/未解析及异常内容。退出码 `0` 仅用于 `complete` 或 `candidates_only`；定位不完整、拒绝或错误使用退出码 `2`，参数错误遵循 argparse 非零退出。单变量请求在变量分支完成或失败后停止；单程序体请求不读取声明；双分支完成/失败后即停止。只有用户另行要求依赖、实例调用或完整地图时才转入相应通用范围，不把它们并入单目标快路径。

## 三、归档清点器的真实能力

有 Python 和真实归档时，可在技能根目录执行：

```sh
python3 -B scripts/inspect_smc2_archive.py <工程.smc2> --json
```

该脚本检查 ZIP 成员、扩展名数量及 XML/JSON 的可解析状态；**不解包、不重建工程树、不提取程序体、不推断对象调用关系**。已有合成容器回归，不证明真实工程语义或厂商版本支持。无脚本环境可使用已获准的工具/用户侧输出，但要准确区分亲自执行与接收他人结果；工具缺失不阻断已有可读代码的讲解。

预检拒绝重复成员、盘符/越界名与编码 DTD。默认预算为 5000 成员、总解压声明量 512 MiB、单成员 256 MiB；元数据每文件最多解析 8 MiB，可用 `--max-metadata-bytes` 显式调整，其他参数查 `--help`。读取结果的 `metadata.complete` 和逐文件状态；`incomplete` 不能称完整解析，`xml-ok` 只证明 XML 可解析，不证明是有效工程、含源码或映射完整。清点通过后若需受控解包，仍须由受控解包工具校验实际写出路径、大小和内容；不修改原工程。

## 四、核对真实结构并建立映射

按本次范围记录：

- 来源名、清点/解包方法及实际结果位置；文件总数和各扩展名数量（仅在确实完整清点时给总数）。
- 工程软件/版本、控制器型号及证据；未提供就写未知。
- `.oem` 或实际描述文件的编码、根节点、命名空间/版本、层级与引用字段；给 XML 路径或对象 ID。
- 每个目标节点到源码、声明、类型、变量表和配置的映射依据；导出/副本行号与原件坐标分开。
- 程序体是否真实可读，是否混有 ST、Ladder 或其它语言；不把整个工程统一称为 ST。
- 断链、重复/孤立对象、同名实例歧义、空节点、保护/加密、截断与部分映射。

可能看到任务、程序单元、段或网络，但只保留当前工程实际表达的层级，不造 `Task → POU → Section` 节点。XML/OEM 的文件或节点排列不证明调用顺序；任务登录、实例调用绑定和代码内部顺序分开取证。

每条关系记录来源对象、目标对象、调用/引用位置、可见输入输出、时间/顺序证据及结论强度。区分定义与实例、工程组织与运行调度、直接 ST 文本与 XML 结构推断、已确认工程事实与现场用途推断。详见[定位与追踪](locating-and-tracing.md)。

## 五、FB/MFB 与 ST 的按需阅读

这部分只是取证清单，不另定讲解格式：

- FB/MFB：定义、库/版本与实例归属；各输入、输出、IN_OUT 和实例变量的声明；调用点与实参绑定；输出消费者；可见状态、异常和复位。Execute/Busy/Done/Error 等指令语义须查匹配平台/库资料，不能仅按名字套通用语义。
- ST：先把握所选对象职责和完整父结构，再分解子块；按源代码顺序分析条件、写入/不写、后写覆盖及上下游。跨扫描结论必须具备实际调度/调用证据或明确条件假设。
- 受保护或仅接口可见的块，说明可见接口/调用与未知内部，不猜实现，不绕过保护。

## 六、交回主路由，不覆盖模板和范围

本方法只负责定位和取证，不规定每个对象拆一份文件，不强制写 `00-项目索引.md`，不以品牌格式覆盖用户已选对象或源代码确认门禁：

- 未选范围时，用[工程导航](workflows/project-navigation.md)呈现总览与可选对象，按其选择规则继续。
- 已选局部对象时，带来源映射回到用户已选的任务与交付：只要求提取就只提取，不因定位成功强制讲解或加载讲解/源码归档全套；只有用户明确要求讲解，或未说明任务而默认进入讲解时，才按 A/B/C 路线执行。无需重新请求选择，也不强制建立全工程索引。A/B/C 现有讲解模板不变。
- 已明确完整范围时，仍按用户原任务交付；要求整工程讲解时才按[代码讲解流程](workflows/explain-code.md)及原定手册路线连续覆盖，局部深讲沿用[局部讲解参考](local-code-explanation.md)。模板/分册仍由既有入口决定。

来源映射、已读范围和未解析缺口随实际导航或讲解交付；是否另存索引遵循主路由及用户要求。新样本确认了差异时按[厂商经验记录契约](vendors/README.md#每条格式经验的记录契约)登记适用组合、实际结果和已知限制，隐私材料留在获准位置，不复制进公开技能。
