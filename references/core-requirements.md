# 核心强规则（已确认交付契约）

这十一条是已确认的交付承诺，优先级高于“精简”“格式修复”“自动流水线”的便利。与 `SKILL.md` 或其它参考冲突时按本文件执行，并同步修正下游文件；不得据此反向放宽已确认项。

| 编号 | 规则 | 硬性要求 |
|---|---|---|
| R1 | 源码完整、顺序保真 | 请求范围内全部可读源码与原作者注释逐字符保留，顺序、缩进、表达式不变；新增解释只追加在完整原行之后，去掉尾注后须与来源逐字符对账；不得用省略号、代表片段或“其余相同”替代 |
| R2 | 注释是默认交付内容 | 行式源码默认逐行追加 ` // AI: `，执行行、跨行条件和结构闭合行均覆盖，只豁免空白行、纯注释行与块注释内部行；不需要用户再次要求；不得把解释全部挪到围栏外后交付无注释源码；仅当次明确要求原样源码或仅归档才例外，并在交付说明写明模式 |
| R3 | 注释写实际作用 | 简短中文写对象＋动作＋结果，必要时加条件；准确的“保存、提交、清除”本身有价值；禁止无对象套话，禁止把请求或记录写成设备动作已完成；推断标“推测” |
| R4 | 五部分与字段不缩水 | 功能定位与执行条件 → 源码 → 代码块整体讲解 → 形象示例 → 程序交互与段间交接；关键变量六列表前置；整体讲解四字段、批判性审查、验证状态齐全；格式修复、精简、拆批都不得改名、合并或删除 |
| R5 | 讲解落到真实因果 | 用实际条件、前值与写点讲清输入 → 判断 → 顺序 → 写入或不写 → 结果；第一性原理融进具体解释，不另堆方法论标题；无设计依据时不替现有写法证明必要、最优或安全 |
| R6 | 示例与交接具体 | 示例用真实变量与具体初值，至少三次连续执行并承接前值，区分写入、不写、保持与复位；交接写清来源、消费者、时机、清除点与边界；无证据不假称每扫描执行或编造复位模块 |
| R7 | 先整体后局部、完整范围自动完成 | 先给有证据的执行框架与主线，再按逻辑段深入；长任务自动清点、分批落盘、记录断点并连续完成，全部结束后按原编号合并，不等待逐段“继续”，不只讲代表段 |
| R8 | 通俗但不删关键内容 | 每模块先一句话说明本段做什么，术语首现给白话解释；删重复与免责声明，保留条件、索引对象、顺序、写入与保持、来源与边界；不能以字数或表格变短证明已看懂 |
| R9 | Markdown 必须实际可读 | 标题、表格、说明直接作为正文，整篇不包代码围栏；围栏开闭各自独立一行，闭合围栏不得拼在源码末尾；逐表核对真实渲染节点、表头、分隔行、列数与转义竖线 |
| R10 | 分项验收 | 源码保真、注释覆盖、注释表达、五部分字段、教学因果、示例交接、Markdown 渲染分别验收；默认注释缺失不得被格式通过抵消；机械检查不证明语义正确，未执行项如实标注 |
| R11 | 修订不得破坏已确认需求 | 修复只改获准范围，不得顺手删源码、注释、栏目或有效样例；改前存基线、改后逐项对账；规则、模板、样例与检查器保持同一口径，并用缺注释、删字段、缺表头的反例验证拒绝 |

## 与检查器的对应

| 规则 | 自动检查 | 仍需人工判断 |
|---|---|---|
| R1 | `scripts/check_code_integrity.py`、`scripts/check_local_explanation.py` 的逐字符对账 | 是否拆在逻辑边界、是否漏读范围 |
| R2、R3 | `scripts/check_plc_comments.py`（默认逐行；`--original-source` 原样源码；`--legacy-selective` 仅历史夹具） | 业务含义是否讲对、是否把请求写成动作 |
| R4 | `scripts/validate_template_format.py`、`scripts/validate_handbook.py` | 栏目内容是否真的讲清而非占位 |
| R5、R6 | `scripts/check_local_explanation.py` 与手册校验器的结构断言 | 因果是否成立、示例数值是否自洽 |
| R9 | `scripts/markdown_syntax.py`、`scripts/check_markdown_format.py` | 排版是否真有助阅读 |

自动检查只证明形态与对账，不能替代语义审查；未执行的检查和未验证的平台行为必须标注“未执行”。

## 变更纪律

确认稿与实现必须逐条对齐：新增或修改规则时，同步更新对应的模板、样例、检查器与反例测试，三者口径不一致即视为缺陷。用户确认前不得把建议写成已确认需求，也不得用“测试通过”替代用户对教学效果的验收。
