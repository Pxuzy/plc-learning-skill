# 程序学习手册写作规则 📘

仅在 C（完整手册）、明确深讲或跨多个模块需 HBK 时加载；A/B 不套完整章节和模块门槛。

交付手册须让读者说明执行顺序、各工位职责、各段功能及实现依据。

## 一、三层结构 🧱

按工程实际组织逐层展开，不跨层跳讲：

```text
大程序（任务）
└── 工位（POU）
    └── 程序段（映射 / 手动 / 自动 / 报警 / 通讯 / 参数 …）
```

| 层 | 必须先说明 | 再展开 |
|---|---|---|
| 任务 | 周期、工位调用顺序、公共条件 | 各工位 POU |
| 工位 | 控制职责、段构成、与其他工位的关系 | 本工位段清单 |
| 程序段 | 要解决的问题、目标、输入输出与约束 | 先推演具体情境，再看实现与状态变化 |

段分类采用工程自身命名，不强行套用固定类别；共用段单独列出并注明调用方。

## 二、章节与适用内容 🧭

C/HBK 顺序：工程与边界 → 执行框架 → 工艺主线 → 对象地图 → 模块详解 → 段间关系 → 关键 MFB/FB（适用时）→ 异常与恢复 → 未确认与证据 → 理解检验。仅保留有资料且有助本请求的章节；HBK 的 `适用章节` 列 ch 编号，ST/FB 按专题标题组织，不按中文编号套 HBK；省略不适用项，不造空章。

第七章只登记关键 FB 定义、实例、调用者和本体可见性；接口成员和参数差异用 FB/接口专题，避免重复字段。

### 讲解深度

C/HBK 路线未指定时使用**代码深度**；用户要求多讲代码、讲细或全部讲时，不得自行降为流程深度。A/B 未要求深讲时不加载本段深度门槛；明确逐行深讲的局部使用代码深度，只缩范围。元信息中的深度只能写单一值。

| 深度 | 覆盖内容 |
|---|---|
| 结构深度 | 组织、调用关系、职责、关键输入输出 |
| 流程深度 | 结构 + 工艺/状态、信号、接口、异常；全部可读代码入清单，深入讲关键代码 |
| 代码深度（默认） | 流程深度 + 全部可读程序段逐段解读；按理解价值说明非显然逻辑、扫描与输出归属 |

**深度要求：** 代码深度覆盖全部可读程序段，按块级五部分模板讲清非显然逻辑、扫描与输出归属。正文依次为功能定位与执行条件、源码、代码块整体讲解、形象示例、程序交互与段间交接。说明当前作用、后果与证据边界，不翻译语法。源码过长时按逻辑边界分批讲解，完整代码只保留一次并以锚点导航；见 `references/code-reading.md`。逐块语义审查见 `references/comment-quality.md`，完成判定见 `references/workflow.md`。

### 关键变量必须给数据类型（硬性）

关键变量表**必须含「数据类型」列**，不能只写名称与含义。要求：

- 类型写全：`BOOL`、`INT`、`DINT`、`UINT`、`USINT`、`REAL`、`STRING[n]`、`ARRAY[1..128] OF <类型>`、`STRUCT <名>`、`FB <名>`（实例）。
- 数组必须写下标范围与元素类型；结构体必须写成员路径到使用的那一层，不写"结构体"三个字了事。
- 声明可见时类型写 `已确认`，未见时类型列写 `未知`；**不得按变量名前缀猜类型并当成已确认**。允许结合前缀、英文词段、作者注释和读写关系推测变量用途或命名约定，放在含义列标 `推断`，不从推测补出数组范围、整数位宽、接口方向或真实作用域。方法见 `inline-comment-style.md` 的“变量命名辅助推断”。
- 类型会影响结论时必须点明：例如 `USINT` 上限 255，`+170` 对工号 >85 会超界即溢出；`SINT` 与 `<=128` 比较不一致。
- 表列固定为：`变量 | 数据类型 | 方向 | 含义 | 谁写谁读 | 证据等级`。
- 标识符、成员路径与已知类型用行内代码；用途、条件或写读方不同的关键变量分行列出，各格只写对应列信息。公共数组声明与范围可在相邻小表集中列明，成员行保留完整路径及成员类型状态；共同假设在首次使用前说明，不在每格重复长段落。表头、分隔行和表体连续，列数一致。

### 布局与通俗解释（新稿必守）

**布局**（解决"章节层级混排、模块编号不统一"）：

1. 模块编号方案在文首一次性声明（如 `模块编号：B0、B1…` 或 `M01、M02…`），全文不得混用两套。
2. 章（`##`）只放工程级内容：图景、变量、工艺、地图、关系、疑点；**模块一律 `###`**，模块内部小节一律 `####`，不得让模块与章同级。
3. 模块内固定顺序：一句话说清 → 功能定位与执行条件 → 源码 → 代码块整体讲解 → 通俗示例 → 交互与交接。顺序不得调换。
4. 表格只放"成组、可比"的信息（条件、信号、扫描轨迹、证据等级）；叙述性内容不进表格，避免整篇表格化。

**通俗解释**（解决"术语堆砌、看不懂为什么"）：

1. 每个模块开头一句**一句话说清**：用现场语言说这块在干什么、给谁用，不含变量名、不含 IF/CASE。例："有车、夹具没屏蔽、也没人在等它完成，才允许给工作工位发启动。"
2. 专业术语首次出现给一句白话解释，再上术语；不要用术语解释术语。
3. 每条关键逻辑配一句"翻译"：先讲人话结论，再讲代码依据，例如"换句话说：条件没了不等于命令撤销，启动还留着，得由后面那块清掉。"
4. 禁止用"执行判断""条件重要"这类空话充数；通俗不等于含糊，结论仍要给依据与证据等级。

### 交付形态

详细讲解与手册最终必须合并为 `.md` 文件并回报路径。长文本可按 `references/workflow.md` 自动分段连续发在聊天里，全部段落完成后再合并成一个文件；聊天分段不是最终交付。短局部详细讲解可直接写文件；只有用户明确要求纯聊天答复时才不建文件。

### 标题层级、表情与阅读辅助

标题层级决定字号，不用加粗伪造层级：

| 层级 | 用途 |
|---|---|
| `#` | 文档名（每份文档仅一个） |
| `##` | 章（一、二、三…） |
| `###` | 工位（`W01 夹紧站`）；单工位可省略 |
| `####` | 模块（`M02 夹紧控制`） |
| 模块内分级标题 | 五部分：功能定位与执行条件、源码、代码块整体讲解、形象示例、程序交互与段间交接；字段用普通粗体，独立分行 |

单对象模块用`### Mxx`，五部分用`#### 1～5`；多工位多一层时模块`####`、五部分`#####`，不跳级。

- **每个模块标题必须带一个表情**；正文关键提示（易混淆点、注意、缺口、危险动作）可用表情。表情要克制但有存在感——整篇没有表情按版式缺陷处理。
- 提示行句首可用 `> ⚠️ 受保护块计入未覆盖`、`> 💡 该步可并行执行`；列表项句首可用 `- ✅ 已确认：…`、`- 🚧 待补资料：…`；状态列使用纯文字 `已讲`、`待补资料`、`受保护`、`未讲解`。
- PLC 围栏及信息串、行内代码、变量/对象 ID、证据等级、元数据值、表格字段禁用表情，表情不替代结论。先查禁区，再处理正文引号内的规则引用；引用外实际键值仍检查，不因“规则/反例”字样放行。含 ID 的普通标题/提示属阅读辅助，键值中的 ID 属数据字段。
- 同一文档内同类标题用同一组表情（如模块标题 🔍、示例 🧪、缺口 ⚠️、交互 🔗），避免连续堆叠，也不让表情替代文字。
- 模板与样例围栏供复制，围栏内所有数据与代码字段保持纯文本；但**新稿缺少标题表情按版式缺陷处理**，不得以"表情非强制"为由省略。

- 每份手册在标题后给 `## 目录`，至少列出各章锚点链接；章节标题前放 `<a id="ch5"></a>`，模块标题前放 `<a id="m02"></a>`。
- 正文交叉引用其它模块一律写 `[M03](#m03)`，链接必须跳到真实锚点；不写“见后面那个模块”。
- 工艺主线必须给步转移表；自动流程达到 3 步及以上时附 `stateDiagram-v2`，节点名含步号（如 `步20_夹紧`），并与步转移表逐项对应；任一处变更都同步更新。
- 第八章报警矩阵列为：报警码、报警/异常、触发条件、影响对象、输出处理、复位方式、恢复起点、证据；复位方式区分自动、手动、断电复位。

## 三、单模块的分步写法 🧩

### 简约逐段模板与长手册装配

各逻辑单元沿用局部模板的“简洁写作提示词”及五部分骨架，读取 `local-code-explanation.md` 相应区段用于表达与字段参考；手册的全局章节、目录和覆盖规则仍由本指南及HBK定义，不把整本手册当成一次局部CLI输入。每段前置六列变量表，源码一次完整呈现，四字段各讲一件事，一个具体示例和最短可核实交接；保留段落审查与验证状态，共同缺口和全局验证集中列一次。默认短句讲清，长手册增加的是段数，不让每段越来越长或后段退化为摘要。

每批写注释前按 `inline-comment-style.md` 的“注释前置参考”加载规则与 `inline-comment-examples.md`；拆命名、看原注释、查读写、对照声明。命名推断可帮助解释用途，类型/作用域未见仍为未知。真实工程成品留在技能目录外，不成为模板样例。

模块默认五部分：**功能定位与执行条件 → 源码 → 代码块整体讲解 → 形象示例 → 程序交互与段间交接**。元信息声明`讲解版式：块级`。完整手册和单对象专题共享此版式，短答按范围压缩。

### 关键变量前置

每个逻辑单元源码前列六列关键变量表：变量、数据类型、方向、含义、谁写谁读、证据等级。方向依据声明，未见填未知，读写角色另列。允许结合命名及上下文推断用途并标推断，不据此确认类型、范围、作用域或物理动作；共享声明缺口集中说明一次。

### 1. 功能定位与执行条件

由已知事实与约束、问题/目标推出条件或状态的必要性，写入**功能定位**、**代码职责**、**设计依据**。目标仅能推断时注明，不声称原作者意图。进入条件表说明必要原因与不成立行为；不另开第一性原理章节，不用口语大段穿插。

### 2. 源码

来源标记紧邻围栏；保留原字符、原注释、原语言，只追加有效行内解释。每个执行单元覆盖与语义审查按 `references/comment-quality.md`；不取消注释门禁，不为切短拆断IF/CASE或块注释。

### 3. 代码块整体讲解

正文不设逐行讲解或逐句列表。用**处理过程**、**关键逻辑**、**写法好处**、**状态变化**说明整块输入到结果、条件组合、这种写法的收益、扫描保持／复位、顺序与多处写入。复杂段补**易混淆点**，简单段每字段一句。推导融入内容，不机械为每句重复注释。

**具体要求**（必须做到）：

- **处理过程**：明确写出"输入是什么 → 经过什么判断 → 得到什么结果"。用源码真实变量串起输入、条件组合、中间结果、写入或跳过与已见消费者；关键变量在链中交代角色，不能只在表中点名。下标选择哪个对象、实例记住什么、状态供谁使用分别说明；同构作用可对照讲，不逐行复述注释。不能只写"执行判断"或"按条件赋值"。

- **关键逻辑**：由已给目标、事实与约束说明所需行为，再对应实现；不预设当前写法唯一或所有条件必要。选择一个条件、状态或顺序作单因素反例，保留其他因素，用具体输入说明原版/改版差异；冗余、缺陷或必要性未知均如实说明。

  示例：在“接收后保留记录”的教学目标下，直接赋值 `xRun := xRequest AND xPermit` 会在请求撤销时清掉记录；条件置 TRUE 且无 ELSE 的写法本次不清除。在同实例可保持、无其他写入假设下才延续前值，不能据此推出真实设备动作。

- **写法好处**：只说明有证据的局部收益、代价与适用需求；不能确认时写“本片段不足以确认比较优势”。不从局部证明全工程单写入、单复位、扫描无关或安全。

- **状态变化**：写清本次写入与跳过；跨调用保持先声明存储、同实例、无其他写入与重初始化假设。逐项核对本段实际的 FALSE 写入及条件；只有确实未见时才写“本段未见 FALSE 写入”。其他清除来源缺证据时标“实际清除点未知”，不保证别处一定复位。

### 4. 形象示例

在块级说明后列**场景设定**、**初始状态**和正常/变化/边界的输入—处理—结果表。使用真实变量、明确假设；纸面推演不称PLC实测。类比可选，采用时标变量对应和不适用边界，不代替技术事实。

**易混淆点**（复杂段补充）：在相同输入与假设下比较原版和单因素改版的行为，不预设未给需求下谁对谁错。示例：
```
原版：IF xRequest THEN xClampRequest := TRUE; END_IF;
改版：xClampRequest := xRequest;
差异：同实例可保持、无其他写入时，请求撤销使改版清 FALSE，原版本次不写。
边界：若需求是跟随当前请求，改版可能适用；若需求是接收后保持，原版具备记忆行为，但实际清除点仍需核查。
```

注意：条件失效只是跳过写入，不等于复位；不要把它解释成"输入撤销所以输出关闭"。
不要机械逐行设问；只补充最有助理解的一个删改反例。

**具体要求**（必须做到）：

- **场景设定**：用真实的变量名（不是"变量A""输入B"），说明"在什么情况下看这段代码的行为"。示例："工件从传送带进入工位，观察启动命令如何建立和保持"。

- **初始状态**：明确写出假设的初值（不是"假设为真/假"，要写具体的变量名和值）。自造示例："假设 `xFeedRequest=FALSE`，`yFeeder=FALSE`，`xBufferBusy=FALSE`，扫描周期 20ms"。

- **扫描序列表格**：至少 3 个扫描（仅有执行证据时改称3次执行），逐步承接前值；涉及定时须写清时间间隔，不能重置后下一次无间隔到期。表格列出每步的：
  - 输入变量值（真实变量名 + 值）
  - 本段的判断结果（条件满足or不满足）
  - 执行的操作（赋值、跳过、保持）
  - 输出变量值（执行后的结果）

  示例表格：
  | 扫描 | xRequest | 条件 | 执行 | xClampRequest 后值 |
  |---|---|---|---|---|
  | 1 | TRUE | 满足 | 赋值 TRUE | TRUE |
  | 2 | FALSE（输入撤销） | 不满足 | 跳过 | TRUE（在同实例、无其他写入假设下保持） |
  | 3 | TRUE | 满足 | 再次赋值 TRUE | TRUE |

- **理解要点**：明确指出这个例子说明了什么关键点（不是"变量变化了"，而是"变量为什么这样变化"）。示例："扫描2是关键：当前请求失效但本段不写；在已声明的保持假设下前值延续，是否满足工艺需求仍须核实"。

- **形象类比**（可选）：如果用类比，必须说明：
  - 类比的对应关系（变量A对应现实中的什么）
  - 不适用的边界（类比在哪里失效）
  - 明确说"类比不代替技术事实"

### 5. 程序交互与段间交接

表格记录来源、目标、关联变量、实际作用；补时机、保持要求与缺失后果。无证据写未知；同程序内部关系不冒称跨程序调用。下一段承接只写真实依赖，无直接依赖就如实说明。

### 3b. 生成器装配与门禁排错

多模块手册用生成器装配，不手抄源码：一份模块表（编号/标题/源行范围/五部分正文）+ 一份行内注释表（源行号→注释）+ 一个渲染函数；渲染时按行号切片、原样复制源行、只在行尾追加注释，逐字符保真由代码保证，改稿只改数据表。排错按以下已知机制处理：

- **切片范围避开围栏行**：源是 Markdown 时，范围常把 ``` 开/闭行算进去；渲染跳过以 ``` 开头的行，否则成品出现连续两个开围栏并被判未闭合。
- **注释键用源文件绝对行号**：键错一两位会让整段注释前移，表现为尾部若干行“缺少行内注释”+中部“重复粘贴”；逐条对回源行号修正，不靠改措辞掩盖错位。
- **新增注释独立核对**：检查器取最后一段以 ` // ` 分隔的追加说明，兼容历史“教学补充”格式；新稿不用该前缀。真正不同作用要据上下文区分，不靠行号或同义替换制造唯一措辞。
- **单行单动作可简注**：完整非嵌套、单简单赋值 IF 可用一句触发条件与业务说明；真正多动作仍用 `// 单元1：… | 单元2：…` 对应，细则见 `references/comment-quality.md`。
- **原文重复注释照原样保留**：恰当原注释不为去重改写或重复追加。重复诊断逐处审查实际作用并如实记录，不通过拆块或装饰措辞消错；相同源码跨块复用正确说明仍逐处核对。
- **结构校验的用语与锚点**：`validate_handbook` 把“强制”当指导性用语拒收，描述代码行为改写为“无条件写回/直接置 FALSE”；同一个 `<a id>` 只能登记一次，装配时去重。
- **分层报告实测结果**：行内注释、ST 渲染、版式、结构校验各自跑、各自报；结构校验或语义审查没通过就写没通过，不以注释门禁通过代替整体通过。

### 4. 与其他程序的交互

仅写有证据的跨程序调用/信号/状态/通讯，无确认交互写无/未知。内部模块关系放第六章，不称其他程序。

## 四、源码块覆盖清单 📋

已讲行用稳定模块 ID（Mxx）关联模块正文，不能用表格行号代替。只有可读源码、有效行内注释和五部分块级说明都交付才登记已讲；仅摘要不能算已讲。正文不再逐执行单元配对bullet；覆盖对账仍检查真实源范围、行内注释和模块正文。

每个工位在段讲解之前先列本工位源码块覆盖清单，格式：

| 编号 | 模块 / 段 | 对象 ID | 范围 | 覆盖状态 | 备注 |
|---|---|---|---|---|---|
| M01 | 车辆定位 | obj0 | 1–40 | 已讲 | 无 |
| M02 | 读码打码 | obj1 | 41–96 | 已讲 | 无 |
| M03 | 物料判定 | obj3 | 97–150 | 已讲 | 无 |

规则：

- 编号按模块递增（M01、M02…），对象 ID 用原值；确定后均不变，后续按编号引用。
- 全项目清单条数须与实际模块数对账；局部交付仅列本次范围，其余模块逐项登记范围外缺口，不能静默缺失或计为已讲。
- 合并讲解时列出覆盖的编号，例如“M01–M03 合并讲，覆盖网络 1–150”。

## 五、段间逻辑关系 🔗

不得用“然后执行下一段”代替。每条关系说明四要素：变量或状态、来源与目标、时机、丢失或乱序后果。

| 类型 | 要写清 | 示例 |
|---|---|---|
| 数据依赖 | 变量从哪段写入、哪段读取、同周期或跨周期 | `xClampDone` 由 S03 写、S05 读，同周期有效 |
| 顺序依赖 | 执行先后要求与被违反时的结果 | S02 未执行时 S04 读取上一周期值 |
| 状态/步序依赖 | 步号推进条件与回退路径 | 步 20→30 需 `xClampDone AND NOT xAlarm` |
| 互锁/许可 | 允许条件与禁止条件 | 自动模式方允许 S07 输出 |
| 异常传递 | 报警中断范围与复位起点 | S09 报警清除 S05 输出，复位回步 10 |

补充要求：

- 一行一条关系，变量名保留原文，标注证据位置。
- 同一变量多处写入时列出全部写入点与执行先后；证据不足标 `未知` 并在缺口中说明要核对的范围，不直接判定双线圈。
- 跨工位、跨任务信号单独成表，注明映射变量、共享变量或通讯缓冲区。
- 关系表与图文一致；存在环路、断点或孤立变量时显式列出。

## 六、工艺写法 🏭

1. **工序主线**：逐步写清进入条件与退出条件；
2. **动作序列表**：每行同时给执行元件与完成信号；缺反馈列为未知，并说明影响与需要补充的证据；
3. **并行与节拍**：并行步骤、同步点、节拍约束；
4. **手动 / 回原点 / 复位**：单独成表，不与自动流程混写；
5. **安全与联锁**：安全回路与程序互锁分层说明，程序互锁不替代安全回路。

工艺有程序无或程序有工艺未描述，列一致性表，以已确认/推断/未知记现状与核对项，不强行映射。

## 七、语言与表述规范 ✍️

- 使用工程术语：扫描周期、上升沿、互锁、许可、保持、复位、步序、映射区。
- 首次出现的术语给出定义或说明，之后沿用同一表述。
- 技术结论不得依赖比喻；块级说明后可增加“形象理解”，使用具体生活/生产场景帮助建立直觉，并标明对应关系与不适用边界。
- 证据等级统一为 `已确认`、`推断`、`未知`、`不适用`，并给出依据位置；`待验证` 仅表示交付状态，不作为证据等级。
