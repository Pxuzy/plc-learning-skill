# 定位与追踪：从问题到可信证据链

讲解之前先把代码找对、把关系追清。本文只管“证据怎么来”，讲解写法见 `code-reading.md`。

## 一、定位顺序

1. **明确查询对象**：符号名、工位名/POU、FB 实例、地址或用户给的行号范围。一次只查一个对象，追清楚再换下一个。
2. **限定材料范围**：列出实际读取的目录、文件、导出单元；写明哪些材料未提供、不可读、受保护。
3. **字符级命中**：先用工具/检索拿到“哪一行出现”，不急着下语义结论。
4. **回读上下文**：命中行前后各取数个语句，判断它是声明、置位、清除、读取、调用参数还是注释/字符串。
5. **消歧**：同名符号可能属于不同 POU、不同 FB 实例或不同局部作用域；核对声明归属与实例绑定，未核实就写“可能关系”。
6. **记坐标**：每处证据记 文件/对象 + 行号或 XML 路径 + 行号类型（源文件行、导出文件行、Markdown 材料行）。派生文件必须给出到原件的行号映射；只说“第 42 行”而不说哪套行号，读者无法复核。

## 二、追踪链（按需，不总是全展开）

问题决定要追哪几段，不是每次都跑完整清单：

- **声明**：类型、方向（VAR/VAR_INPUT/VAR_OUTPUT/VAR_IN_OUT）、数组维度、结构体成员。
- **写入点**：置位、赋 FALSE 复位、间接写入（数组下标、指针、HMI/通讯写入）。
- **读取点/消费者**：谁在本 POU 之外用这个值；跨 POU 时说明是映射区、全局变量还是通讯缓冲。
- **调用点与绑定**：FB 定义与实例调用是两件事；实参→形参的方向必须核对声明。
- **任务与顺序**：调用顺序、扫描周期证据；没有 Task 证据时，跨段因果只能说“若按此顺序调用”。

停止条件：足以回答当前问题即停；缺口列最小必要材料，不擅自索取全工程。

## 三、工具边界（`scripts/survey_program.py`）

`survey_program.py` 产出的是**候选统计**，不是已确认事实。使用它时的四条硬约束：

- **片段先成单元**：`auto` 需要 NETWORK/SECTION/POU 标记；一段没有标记的 ST 片段会直接报“未识别到程序单元”。要么用 `--pattern` 显式指定，要么在**独立副本**里加一行标记，并在文档里注明这行不是原工程结构——绝不在原文件里加。
- **`write_sites` 含形参**：FB/定时器调用里的 `IN:=`、`PT:=` 会作为写入目标出现。回读该行确认左侧是实参形参还是真实变量，形参不得计为外部变量写入。
- **行号是导出/副本行号**：`write_sites` 的 `line` 指被扫描文件的行号。从 Markdown 材料里截取片段时，必须把 `导出行号 + 截取起点偏移` 换回材料行号再引用。
- **读不全要声明**：`lexical_errors`、`syntax_limits`、间接寻址、图形网络、外部/HMI 写入都在统计之外。有限范围没找到只写“本次范围内未发现”，不写“不存在”。

## 四、结论强度

| 证据 | 可以说 | 不能说 |
|---|---|---|
| 只有词法命中 | “此处出现该符号” | “这是唯一写入点” |
| 命中 + 回读确认执行行 | `已确认` 的读写点与门控条件 | 作者的原始意图 |
| 缺调用/任务证据 | “若由该 POU 按此顺序调用，则……” | “每个扫描周期都这样执行” |
| 缺实例绑定 | “可能指向不同实例” | 强行给出唯一对象 |

定时器设定值（如 `PT:=T#10MS`）不推出“下一扫描就完成”；条件变假只说明该次不写入，不等于复位。同一变量在一段内先置后清时，必须同时写明执行顺序假设（同实例、串行、无其他写入）才算完整结论。

## 五、交付定位摘要（短，进正文开头）

```text
对象：<符号 / POU / 段>
证据位置：<文件>:<行号类型>:<范围>（保持原文，不改写）
已确认：<读写点 + 各自门控>
推断：<依赖调用顺序/扫描周期的因果>
未知：<未提供的调用者、外部消费方、Task 证据>
```
