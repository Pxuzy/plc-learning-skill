# 工艺动作流程与信号流 🔄

<!-- template-id: FLOW@3.0 -->

这是两个可组合但不同的知识：工艺回答“工件和机构应该怎么动”，信号流回答“程序靠什么把它连起来”。两者都不能用代码或无证据的机械想象代替。需要其一时只交付其一；同时请求两者时组合 `HBK@3.0 + FLOW@3.0`，共享字段遵循 `template-handbook.md`。如为信号证据附教学源码，尽量逐行给贴合上下文的行内解释，并逐块语义审查，见 `references/comment-quality.md`。

## 一、工艺动作流程 🏭

### 目标

把程序还原成车间里看得见的动作顺序，而不是程序结构。

### 两个产物

产物 A：工序流程（工序级，不是代码级）

```text
上料 → 定位 → 夹紧 → 加工 → 检测 → 松开 → 下料
```

以下地址、变量、步号和时间值均为写法示例，不代表实际工程。

产物 B：动作序列表

| 步 | 动作 | 执行元件 | 到位/完成信号 | 允许下一步条件 | 超时/异常 |
|---|---|---|---|---|---|
| 10 | 夹紧 | `Y10` 夹紧阀 | `X5` 夹紧到位 | 到位且允许加工 | `T10` 2s 报警 |

### 硬规则

- 每个动作必须同时有**执行元件**和**完成信号**两列。缺完成信号的一律标 `待验证`——没有反馈的动作在程序里无法闭环。
- 只写程序或工程资料能支撑的动作；机械推测标未知并提出需补的图纸/资料，不建议产线试错。
- 动作序列表里的步号/状态变量必须能在程序里找到对应，对不上就是漏了分支或走了别的块。
- 手动、回原点、复位单独一套序列表，不与自动流程混着写。

### 节拍与并行

- 标出哪些工位是串行、哪些并行。并行工位共用一个节拍时，必须找出同步点（共同等待的信号）。
- 单独讲一个工位时，它的节拍要与前后工位对齐，否则“为什么等”讲不清。

## 二、信号流 🔌

### 单条链的固定路径

```text
传感器 → 端子/模块 → 输入地址 → 中间逻辑（含互锁） → 输出地址 → 执行元件 → 机械动作 → 反馈信号 → 状态推进
```

### 信号链表

一条链一张表，每跳必须有地址或变量名，不能写“经过一些逻辑”。

| 跳 | 位置/地址 | 含义 | 证据 |
|---|---|---|---|
| 1 | `X5` | 夹紧到位光电 | 符号表 |
| 2 | `M30` | 到位确认（含滤波 `T5`） | 程序推断 |
| 3 | `Y10` | 夹紧阀输出 | 注释 |
| 4 | `X6` | 夹紧到位反馈 | 待验证 |

### 工位间握手

握手信号只有五类，逐类确认有无：

- **请求**（我要工件 / 我要放行）
- **允许**（可以取 / 可以放）
- **占用**（工位有料）
- **完成**（本工位动作结束）
- **释放**（清空占用）

方向必须标清。只单向有请求、没有允许或完成的，标 `待验证`——这通常是丢了一段逻辑或丢了另一个工位。

### 常见断点

- 信号进了程序但从未被使用（预留或漏接）
- 信号被另一处逻辑覆盖（输出归属冲突）
- 有效电平与现场相反（NPN/PNP、常开/常闭）
- 握手只单向，缺允许或完成
- 反馈信号存在但超时未处理，卡在等待态

## 三、三者一致性检查 🔍

代码、工艺、信号流讲完后必须对齐一次，不得默认一致。

| 检查项 | 一致 | 不一致时怎么写 |
|---|---|---|
| 程序有动作，工艺里没有对应工序 | | 可能是预留、调试用或已废弃逻辑 |
| 工艺需要动作，程序里找不到实现 | | 可能在其他块实现，或程序缺失 |
| 动作序列表的完成信号在信号链里对不上 | | 反馈可能来自其他传感器或上位机 |
| 握手信号缺方向或缺失一方 | | 可能是分段程序，缺另一段资料 |

不一致必须显式列出并标等级，禁止自动“补成一致”。

## 输出

模板见本节末尾两节。只请求工艺或信号时用对应专题；同时请求两者时组合输出并通过交叉引用连接，不重复共享字段。
