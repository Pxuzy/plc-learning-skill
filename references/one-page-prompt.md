# 一页讲解模板（复制即用）

> 模式 B 的正式输出规则权威是 `references/local-code-explanation.md`；本页仅兼容呈现同一契约，不另定义规则，也不省略标题、必填字段、原码或假设边界。
> 用法：把 `【代码】` 换成你的真实代码，整段发给模型。
> 模式 B 一个完整局部片段视为一块，原码只保留一次；长 IF/CASE 保持闭合，用分支锚点导航，不按数字机械切断结构。

【篇幅与去重】
按 references/local-code-explanation.md 的“简洁写作提示词”默认简明讲清：各栏各讲一件事，同一结论只解释一次；变量表用短语，四字段通常各1～3句，示例用一个场景和一张三次轨迹表。完整源码、六列变量表、五部分、四字段与专属假设不减；不叠加真值表、第二套案例、重复风险与免责声明。明确深讲时增加独立信息，不重复已有解释。

【硬规则】
1. 源码逐行完整输出：不删行、不截短、不用「...」「略」「其余同上」代替。
   模式 B 的完整局部片段只在第二部分贴原码一次；长 IF/CASE 保持闭合，不机械拆断，用分支锚点导航。多个独立逻辑块或完整手册才按逻辑拆成多段，保留全部行。
2. 模式 B 按五部分顺序，第二部分完整原码、第三部分解释执行范围与整块因果，不拆开同一片段反复贴码；代码 → 讲解 → 再下一段代码的交替仅用于多个独立逻辑块或完整手册。
3. 第三部分“代码块整体讲解”固定 4 个字段，不设统一句数；明确深讲时按所问范围展开每个执行单元的作用、条件、结果与边界，不替代其余四部分：
   **处理过程**：输入是什么 → 经过什么判断 → 得到什么结果；正文源范围用 <!-- explanation: L1-L1 --> 映射，不把正文推演塞进行内短注释
   **关键逻辑**：由已知目标/事实说明所需行为，再用单因素删改反例比较结果；允许条件冗余或必要性未知，不替现有写法辩护
   **写法好处**：只写有源码依据的局部收益与代价；看不出比较优势就明确未知，不补造唯一写入或复位位置
   **状态变化**：本次写入/不写，跨执行保持先给假设；清除点有证据才定位，否则写未知
4. 禁止这些废话：执行判断、条件判断、满足条件则赋值、条件很重要、变量变化了、详见代码。
5. 模式 B 及长手册各段按简约五部分骨架。每次写注释前加载 inline-comment-style.md（含命名辅助推断）和 inline-comment-examples.md；保留完整原码与原注释，默认追加短业务尾注，要求原样源码时不追加。逐行问题在第三部分对应解释，风险与保持分析不塞进尾注。
   完整手册/教学重建仍须有效行内注释；用户当次明确要教学注释版时也照此，解释「为什么」而非复述语法。
6. 不知道就写「未知」，不要编造任务周期、地址、机械动作。

## 为什么弱模型会截代码

| 原因 | 表现 | 对策 |
|---|---|---|
| 规则太多 | 只来得及做一半，先砍代码 | 六条仅作呈现摘要；具体规则仍以正式局部参考为准，不省略必填项 |
| 把阅读长度当作删码上限 | 代码块突然变短 | B 保留完整片段一次；需拆批时保留全部源码，不机械截断长结构 |
| 五部分标题太长记不住 | 漏段、并段 | 标题给死，让它照抄 |
| 要求「讲得深」 | 讲解变长，代码被压缩 | 深讲按范围展开，不按句数封顶；篇幅不足按既有分段规则交付，不删原码或推导 |
| 没有锚点 | 越写越自由 | 给完整骨架，只让填空 |

## 自检（发出去之前看一眼）

- [ ] 每个代码块行数 = 原始代码对应段行数（没少行）
- [ ] 没有「...」「略」「同上」
- [ ] 第三部分保留 4 个字段（含「写法好处」），对应第二部分的完整原码解释，不机械拆码
- [ ] 模式 B 的代码围栏与输入逐字符一致，原注释保留；完整手册/教学重建的行内注释写的是为什么，不是「条件判断」
