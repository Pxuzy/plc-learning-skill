# 代码深度解读 💻

目标：由问题、事实与约束推出条件/状态必要性，用具体输入核对源码因果，让新手解释必要性、成立时机、变量变化与失败后果。推断目标须给依据与最小未知，不声称作者意图。

## 核心原则：一次只讲一小段

- **一个逻辑点 = 一小段。** 一条 `IF`、一个赋值、一个定时器、一个 FB 调用、一个线圈，都可以是一小段。
- **教学一次聚焦约 5 行。** 长 IF/CASE 等闭合结构的源码保留一次，按源行号范围逐分支精讲；长度不作为截断、复制或改写源码的理由。
- **先问题与依据，再推导条件和状态。** 据事实说明判断/记忆必要性，再以示例核对源码；类比放块级说明后，不替代事实。
- **代码与解释交替出现。** 一小段源码（按逻辑约 3～8 行，单个教学代码块上限 25 行；不按行数硬切）之后**紧邻**这一段为什么这样写、换一组输入会怎样、删掉会怎样，再放下一小段；不把整块代码贴完再统一解释。分段的目的是让读者一次只消化一小段，不是为了把结构拆碎：不拆 `IF` 与 `END_IF`，不为凑短复制代码。**单一闭合结构**（一个 `IF`/`CASE`/`FOR`/`WHILE` 连同其全部嵌套）拆开必然要重复包裹语句，因此允许完整保留一次并超过 25 行，条件是至少给出两条分别指向现存锚点的步骤/分支链接；目录链接、孤立锚点和重复指向同一位置不算导航。没有这种分支导航的超长块仍判"一次一大段"并报错。并列语句堆叠、顶层赋值或顶层调用超过 25 行照旧判错。
- **一小段只回答一个问题。** 不要把“判断 + 计数 + 报警 + 复位”塞进同一段。

## 短代码问答（A/B）

**适用边界：仅 A 使用本节的自然句短答。** B 借鉴因果分析时仍回到 `references/local-code-explanation.md` 的五部分原码骨架，不采用本节省表格或追加注释的示例格式。标题保留作既有方法入口。

未要求深讲的短答用几个自然句推导，不套深讲层级、表格或逐行注释；明确深讲则按局部逐行路径完整展开，不以片段短为由简化；无代码的纯事实直接答，原样归档不讲解。下例虚构，不代表用户工程。

本段要解释的问题是：输入撤销后，置位结果为何还会保持。已知仅在 `xStart` 为真时写 `xRun`，没有 ELSE，也没有 FALSE 写入。因此 `xStart` 限定何时写入的条件与 `xRun` 承担跨扫描记忆的状态必须分开看。

假设同一实例每扫描执行本段，没有其他写入，初值 `xRun = FALSE`。第 1 扫描假设 `xStart = TRUE`，执行赋值使 `xRun` 为 TRUE；第 2 扫描假设 `xStart = FALSE`，跳过赋值，`xRun` 仍为 TRUE。条件 `xStart` 为假不等于对 `xRun` 复位；其他写入点和原作者真实设计意图未知，需要时只追问声明/复位来源，不能声称这是某种机械自保持。

<!-- src: none；来源/对象：A/B 短问答教学片段（假想示例，无真实源坐标） -->

```st
IF xStart THEN // 当前输入为真才进入本段唯一的写入路径
    xRun := TRUE; // 留下置位结果；输入随后变假时本段没有清除路径
END_IF;
```

## 每个小段的固定结构：关键变量前置与块级说明

**格式边界：** 下列 HBK 和行内注释规定适用于完整手册/教学重建；A 仅按当前问题取方法，B 的字段、原码与正文覆盖以 `references/local-code-explanation.md` 为准。

新稿声明`讲解版式：块级`，完整样例见[块级手册示例](example-block-handbook.md)，模板以[HBK](template-handbook.md)为准。

- **关键变量前置**：整体先给类型／方向、实际含义、有效条件和用途；本段只补新变量或本段用途，不重复整表。
- **固定五部分**：职责、进入条件、功能定位融入“功能定位与执行条件”；其后依次为“源码”“代码块整体讲解”“形象示例”“程序交互与段间交接”。使用分级标题、加粗字段、分行和表格，不用口语大段穿插。
- **代码块整体讲解**：用**处理过程**、**关键逻辑**、**写法好处**、**状态变化**说明输入到结果、条件必要性、这种写法的收益、保持/复位与顺序关系；复杂段再补易混淆点。小段源码之后紧邻整体说明，再给具体输入例子与交接后进入下一段。

  - **写法好处**说明有依据的局部收益、代价和适用需求；看不出比较优势就写“本片段不足以确认比较优势”，不凭片段保证单写入、单复位、扫描无关或整机行为。

  - **处理过程**写清数据流：输入是什么 → 经过什么判断 → 写什么或跳过什么，不用通用话术代替具体变量。
  - **关键逻辑**由事实和约束推导所需行为，再用单因素反例核对；条件可能冗余、实现可能有缺陷，不能预设必要或正确。
  - **状态变化**分开本次写入/不写与跨执行保持，保持先说明存储假设；清除来源有证据才定位，未见就写未知。
  - **易混淆点**比较相同假设下的行为差异与适用需求，不给需求未知的不同方案强贴错误/正确标签。

  自检参照 `references/quality-checklist.md`，格式和语义分开记录。
- **取消正文逐行复述**：每行细节由源码中的有效行内注释体现；默认不建“逐句看”或“逐行讲解”列表。只在用户当次明确要求逐行答疑时对所问语句展开，不能把这个例外当默认。
- **第一性原理自然融入**：问题/目标 → 已知事实与约束 → 条件/状态必要性 → 关键因果与删改后果。推导写进设计依据、关键逻辑和示例结果中，不单列理论标题、不逐条报幕；不假定当前写法是唯一方案。
- **形象示例**：源码与块级说明之后，用真实变量、假设初值、输入变化与结果表解释正常和边界。类比可选且须标不适用边界，不当作证据。
- **表情与证据**：标题与必要提示适量使用表情，代码／表格／变量内不用。未知调用、任务周期、复位或物理含义标明未知；纯归档不插讲解，A 短答不强套全部标题；B 保留专用五部分。

## ST 精讲的层级顺序：总框架 → 大框架 → 小框架 → 逐段

完整手册或明确深讲 ST 先全局执行脉络后细节；局部深讲只缩范围，相关范围仍说明完整条件因果；未要求深讲的 A 不强制分层；B 按专用局部范围组织。模板大标题不等于逻辑框架，不能各写概述即跳走。

1. **总框架**：讲 ST 任务/程序入口、周期/执行顺序、主块、数据/状态归属、实际自动/手动/初始化/报警路径、关键调用/信号关系；缺项待确认。
2. **大框架**：按程序块、POU、完整状态机/工艺阶段或完整职责区域，讲职责/边界、调用/进入条件、输入输出、状态/分支、前后关系、异常/复位及源码范围；讲完才转下一框架。
3. **小框架**：按子流程/网络组（许可、动作、反馈、超时等）说明如何组成当前大框架，再展开代码。
4. **逐段精讲**：按源序覆盖可读 ST 清单，讲目的、整块条件/结果、变量变化、扫描/保持、边界/误读，回链大小框架。

**阶段门槛：** 总框架清楚后进大框架，大框架讲完再进小框架；职责、路径、接口、状态/分支、异常关系完整才转下一大框架，内部小框架与程序段登记覆盖后才称精讲完成。资料不全可分批，须标层级、已完成框架、未讲范围，不以稀疏标题冒充全讲。

**组织方式：** 先按逻辑分组，组内按源序；不把 NETWORK/POU/模板标题各写两句即跳走，不为分层重复源码。逐段完整性只对账覆盖清单。

## 代码块怎么切

先看语法，再看逻辑，长度服从这两条：

- **语法完整：** 保留完整赋值、含参数 FB 调用、结构（`IF…END_IF`、`CASE…END_CASE`、`FOR…END_FOR`）或网络/梯级，不拆 `IF` 与 `END_IF` 首尾、不截条件。
- **逻辑完整：** 一个小段只表达一个判断、一个动作、一个计数或一个报警。无关的赋值不塞进同一块。
- **两者冲突时保留完整源结构一次**，教学按逻辑范围拆分，不能复制 IF/CASE 头或补造 END_IF 来制造短源码。
- **长度：** 短块优先；长闭合结构先文字分支导航（非源码），再放唯一教学源码块，带锚点、完整 src 范围、逐行有效注释。小段链接源行，如 `[等待分支，源 L5–10](#source-main)`，仅解释该范围，不复制源码。
- **不按行号硬切**，也不为了短而把一个条件拆得读不懂。
- **状态机图、信号流图放 ```mermaid 围栏**；写成 ```st 会被注释/源码门禁当作 PLC 源码检查，也误导读者以为是程序。

## 按理解价值写说明（注释只能追加）

**注释适用边界：** 完整手册/教学重建以及用户明确要求的教学注释版执行本节注释门禁；A 按问答范围取方法。B 默认不追加注释，按 `references/local-code-explanation.md` 在第三部分正文覆盖执行单元，不以本节替换其原码。

- PLC 源码逐行配有效解释，逐项查简单赋值、声明、调用、组合条件和分支；结构行按条件范围说明。不因简单省略、不堆注释凑覆盖，概述不替代行内说明。

仅空白、原注释、纯闭合行可豁免；闭合后有语句仍须注释。不以语法翻译充数，通过自动门禁后仍逐块语义审查，见 `references/comment-quality.md`。

局部问题是：请求与普通互锁同时有效才写输出，任一撤销时输出怎样撤销？已知 `xEnable` 每次先从 `xRequest` 刷新，条件合取后才写 TRUE，ELSE 明确写 FALSE。因此需要 AND 同时约束请求与许可，并用 ELSE 显式清除旧值。

假设 `xRequest = TRUE`、`xInterlockOK = TRUE`，本扫描先刷新本地使能，再把 `xOutput` 写为 TRUE；下一扫描假设 `xInterlockOK = FALSE`，请求仍为真，合取条件为假，ELSE 把 `xOutput` 写为 FALSE。若删掉整个 ELSE 清除分支且无其他写入，条件为假时可能保留先前 TRUE。下面只演示这段数据流；互锁来源、安全等级及现场设备含义未知。

```st
// 本片段展示先刷新本地使能、再按普通互锁选择输出路径
xEnable := xRequest; // 下方判断在本次扫描中读取刚刷新的请求，不沿用上次扫描的本地使能
IF xEnable AND xInterlockOK THEN // 本地使能与互锁总许可都为真才进入；互锁来源未知
    xOutput := TRUE; // 两项许可同时满足时保持输出，任一丢失将在 ELSE 路径撤销
ELSE // 任一许可缺失时走输出清除路径
    xOutput := FALSE; // 进入此路径时明确撤销本段输出，避免保留旧状态
END_IF;
```

- 只追加合法注释，保留逻辑、变量、源字符/原注释；行内以简短业务含义加必要触发条件为主，清楚的原注释不重复补充，新增用 ` // <说明>`，不加“教学补充”前缀。完整单行单赋值 IF 可共用一句条件与动作说明，真正多动作仍分项；具体边界以 `references/comment-quality.md` 为准。详细机制与状态推演放围栏外；无法安全追加标待审，不称已覆盖。
- 代码块前标注 `<!-- src: 起-止 -->`；去掉追加注释后与源行不一致，`check_code_integrity.py` 判改写。
- 需要严格引用原文时，对独立原始源文本运行完整性 `--strict`；教学注释稿另做覆盖校验，不用未注释原文代替教学稿。
- 每个教学块标明“教学注释版”；原文保留在可定位的源文本中，缺源文本时写明只能核对可见片段。
- LAD/FBD 不能逐行注释：每个可辨网络/梯级说明输入组合、输出与状态后果，元件关键关系融入块级说明，不伪写ST或机械逐元件复述。
- 行内注释承担行级细节；正文只补整块因果、条件组合与后果，不把注释复制成列表。注释覆盖和源字符对账仍逐执行单元检查。
- 注释类型优先级：说明意图 > 条件分组含义 > 状态后果 > 时序/互锁/风险 > 数值/地址来源；复述字段、语句和“开始/结束”标记不写。
- 注释长短服从信息密度；不得用长度或关键词命中证明价值。每块记录审查依据、理由与未解决问题；未审查或有错不得称质量全部合格。

## CASE 怎么讲

- 先用文字列出各分支条件、动作和去向；骨架属于说明，不放在 PLC 围栏，不参与源码覆盖。
- 完整 CASE 源码保留一次，然后**一个分支一个小段**，链接源码锚点和源行范围，按顺序说明分支整体逻辑；不补写另一份所谓闭合的分支源码。
- 每个分支按五部分模板：功能定位与执行条件→源码范围→代码块整体讲解→形象示例→程序交互；分支源码只引用唯一原块，不重复复制。
- 每次只讲一个分支；分支内动作多时按动作拆教学范围，完整源块不拆、不重复。

## 每小段按第一性原理推导

B 只取本节适用分析方法：保留单因素反例与逐执行单元展开，按 `references/local-code-explanation.md` 将行级作用、条件、结果写入第三部分；下列行内注释分工只适用于完整手册/教学重建或明确要求的注释版，不改变 B 默认原码。

先读源码取事实，再由问题/约束推导条件/状态必要性；理解输入变化后核对源码，正文整体说明而不逐行复述。类比可选，不替代实例、证据或推导。

**切片边界先判定**：给的片段若停在 `END_IF`/`END_CASE` 之前，先标“片段不闭合”，只讲可见部分，不得据此断言“本段没有复位/没有清标志”——同文件后段可能就有。用户说“真实工程”时先确认是投产代码还是示例工程，别把方案包的示例文件说成现场代码。

**实际分析顺序：**

1. 分开列出已给需求、可见事实、未知与教学假设。类型、调用、变量保持和库行为各自取证；无调用证据按“每次执行到此处”描述。假设在首次使用前说明，不能只在文末免责。
2. 明确要满足的不变量与时间要求，再判断是否需要当前电平之外的信息：先前是否接收、持续多久、哪个分支优先。仅知代码行为时只推导行为，不反推真实工艺目标。
3. 将所需信息对应到条件、存储状态、计时或执行顺序。区分“需求需要这种行为”与“必须使用当前写法”；等价实现、冗余条件、不足之处和无法确认都允许如实说明。既有源码不是合理性证明。
4. 每个删改反例只改变一个因素，保留其余分支、输入、初值与假设，列原版/改版的不同结果。换掉整段实现同时改变计时、故障和保持，不能据此证明单个条件必要；在假设下删后无差异时，应承认该条件可能冗余。IF/ELSIF 的优先级由分支先后及互斥共同决定，不说“完全不依赖顺序”。
5. 示例先固定一条可重算的状态账本，再写解释：表格每行列出“时刻/距上次间隔、完整输入、调用前的关键状态、调用后结果”，下一行逐项承接。初始定时状态清零时，第一次输入变真只建立起点；给定连续时间区间才允许到期。故障、输入中断、恢复在账本中各自更新计时，不把另一条轨迹的 Q/前值搬来；支线示例另列自己的起点。时间不足就写未到期；时间未给就写结果待定，不用“可能已到期”替代确定计算。状态保持与定时滤波分别核对，不等同于抗所有抖动。
6. 用源码逐处检查上述推导，再核对未知点、恢复与消费者。不能确认收益时写“本片段不足以确认比较优势”；没有清除点时写“本段未见 FALSE 写入，实际清除点未知”。运行变量的赋值不直接证明设备已动作，反例也不默认是正确方案。

推导融入现有五部分，不新增固定栏目。出稿前用源码反查每行账本，先把定时起点、输入连续区间与到期值计算确定，再用它校对摘要、正文和结论；不要把“未计满”误写成“计时清零”，只有输入复位路径才清零。清除路径说明须覆盖本段已见的每个 FALSE 写入，未见“其他清除点”不能缩写成“本段没有 FALSE 写入”。一块未完成五部分和四个整体讲解字段，不标已完；需要拆批时在完整逻辑块之间停，不把示例/交接留到下一批。正式稿只呈现当前结论、证据与教学假设；不夹带历史修改对话、版本取舍或“按你的要求改成”等过程话术。

### 1. 目的与约束

用工程语言列问题、预期结果、输入输出、不变量，据事实/约束推导判断/记忆必要性。结论给源码/接口依据，推断目标与未知标明，不凭变量名猜动作。

### 2. 先核对关键变量

源码前介绍变量类型／方向、含义与用途。具体情境放在块级说明之后，列真实变量的假设初值、输入序列、执行过程与结果；需要时跨扫描比较正常和边界，有限假设不冒充现场。

### 3. 展示源码并说明整块逻辑

## 完整示例

### 示例小段：等3秒建立检查许可

#### 1. 功能定位与执行条件

**功能定位**：只有请求持续达到设定时间才建立检查许可。

**代码职责**：用独立定时器记住持续时间，而不是把当前电平当成已持续3秒。

**设计依据**：单次扫描只提供当前真假，不能证明持续长度；故需时间状态。时间达到也不证明设备稳定，工程意图未知。

| 变量名称 | 类型／方向 | 实际含义 | 有效条件／取值 | 主要用途 |
|---|---|---|---|---|
| `xExecute` | BOOL／输入（教学设定） | 当前请求 | TRUE计时 | 提供持续资格 |
| `tonDelay3s` | TON实例（教学假设） | 非保持计时状态 | 输入中断复位 | 记录3秒 |
| `xCheckEnable` | BOOL／状态（教学设定） | 检查许可 | 本段只写TRUE | 保存许可 |

| 进入条件 | 必要原因 | 不满足时的行为 |
|---|---|---|
| `tonDelay3s.Q` | 输入连续满足时间后才置位 | 跳过置位，不自动清除已有许可 |

#### 2. 源码

<!-- src: none；来源/对象：本文件虚构3秒TON教学片段 -->
```st

IF tonDelay3s.Q THEN // 时间资格成立才建立检查许可，不由瞬时输入直接决定

END_IF;
```

#### 3. 代码块整体讲解

**处理过程**：先调用TON更新时间资格，再依据Q建立检查许可。

**关键逻辑**：时间资格与保持许可分开；输入失效会让非保持TON复位，却不会自动清除另一个已置位变量。

**写法好处**：在“达到时间后保存许可”的教学目标下，计时与已建立的许可分别保存；代价是输入失效不清许可。没有真实需求或其他写方，不判断整机优势或复位是否完善。

**状态变化**：未到时时不写许可；到时写TRUE；输入中断后许可是否撤销，需要查其他写方。

#### 4. 形象示例

**场景设定**：请求尚未计满、连续计满、计满后又中断三种情境。

**初始状态**：纸面假设标准非保持型TON，初始Q=FALSE且计时清零，同实例按源序调用；`xCheckEnable=FALSE`且无其他写入。时间仅为假设输入序列，不是实测任务周期。

## 指令语义

指令只在首次出现时给一句基础语义，之后结合当前小段说明实际作用。下表是阅读提示，具体语义以当前平台手册与工程调用证据为准；未知平台不可断言执行次数、保持、复位、结果标志或寄存器形式。

解释 CMP/MOV 前逐项核对：平台与 CPU/软件版本是什么？指令形式是普通、脉冲/沿触发还是平台变体？条件/使能由谁提供、持续还是单次有效？执行时机由哪个任务、调用顺序和扫描路径决定，未到达调用时结果如何处理？缺资料时说明单次调用能证实的数据流，跨周期行为标为待确认。

| 指令类别 | 必须讲清的一句话 |
|---|---|
| 置位/复位（SET/RST） | 置位后保持，直到别处复位；不复位就永久为 ON |
| 上升/下降沿（PLS/PLF/边缘触点） | 只在跳变的那一个扫描周期有效，下一周期自动失效 |
| 定时器（TON） | 输入必须持续为 ON 才计时；条件中断则重新计时 |
| 计数器（CTU） | 到设定值后输出位为 ON，需单独复位 |
| 比较/传送（CMP/MOV） | 到达调用且满足该形式的执行条件时，按平台规定比较或传送；普通形式在周期调用路径中可能每周期执行，脉冲/沿触发变体须另查，不从名称断言次数或结果载体 |
| 移位/顺序器 | 每触发一次移一位，注意首尾处理 |

## 必须先识别的六种结构

- **自保持回路**：启动并联自身常开触点——讲清唯一的断开条件是谁。
- **置位/复位对**：成对出现时，讲清复位优先级和复位位置。
- **单按钮启停**：一个按钮交替启停，必须讲边沿和状态位。
- **步进控制**：步号比较、STL/SFC、步标志位——讲清当前步、转移条件、转移后旧步如何清除。
- **移位/顺序器**：讲清移位条件与工位数对应关系。
- **模拟量处理**：量程换算、滤波、报警阈值，离开量纲的数值没有意义。

## 陷阱清单（讲代码时必须主动检查）

- **多处写入**：逐一核对写入对象、实际执行路径、任务与先后；仅在同一串行路径且无其他写方时，后写值覆盖前写值。不能据此保证物理输出刷新或跨任务最终值。
- **置位未复位**：核对所有清除入口，不能把条件失效等同复位。故障清除是否自动恢复要同时推演请求已撤销与请求仍持续两种输入，不用单一序列断言有防重启动保护。
- **边沿位置错**：边沿指令放在条件之后还是之前，结果不同。
- **定时器条件抖动**：输入抖动导致永远计不满。
- **整数/浮点混用**：比较与运算类型不匹配。
- **扫描顺序**：读取获得该时刻的值；同一扫描更早写入、其他任务或外部写入均可能改变它。仅在已证实本次读取前没有新写入时，才可沿用上次值推演。
- **未使用的写入**：写了但从未被读，可能是预留或漏接。

### 单元怎么切

按导出结构切最小可判定单元，不按行数切：梯形图一个 network/rung（含并联支路）为一个单元，同一 network 里的 ST 指令框另立子单元；ST 一个连续文本块为一个单元；FBD 一个网络；SFC/STL 一个步或一个转移；受保护、只有截图、只有图形无文本者各自单列。

### 综合结论（清点之后才写）

必须回答四件事，不能只报"ST 和梯形图混合"：

1. **组成**：各语言单元数与占比，未知单列。
2. **主次**：哪一种是主控流程、哪些是辅助（依调用关系或工艺位置，不按数量多少）。
3. **分工与交接**：ST 单元算出的值，LAD 网络怎么用；跨语言读写点要能对上，这是混排最易错处。
4. **适用规则**：ST 用行内注释＋整块因果；LAD 用网络拓扑说明、不逐行注释、不伪写 ST；未知单元只报范围与缺口。

### 必须分开处理的七种情形

1. 整个 POU 单一语言。
2. 同一 POU 内不同网络语言不同 —— 逐网络标注。
3. 调用处与被调体内语言不同（LAD 调 ST 写的 FB）—— 两个独立单元，不能因调用处是 LAD 就把 FB 体按 LAD 讲。
4. LAD 网络里嵌 ST 指令框 —— 该框按 ST 讲，所在网络仍按 LAD 讲拓扑。
5. SFC/STL 步进、IL/AWL —— 各自规则，不套 ST 或 LAD。
6. 受保护块、截图、导出缺语言字段 —— 标未知。
7. 同一段既有图形又有文本 —— 文本为行为依据，图形只核拓扑；冲突时报冲突，不二选一。
