**注释的价值是让读者看懂这一行为什么这样写，也是默认交付内容。** 默认契约：对每条非空可读源行逐行追加简短业务尾注，不需要用户再次提出“逐行”；空白行、纯注释行和未闭合块注释内部行除外，结构闭合行也要用最短的准确说明交代所承接的范围。说明须写本行具体判据、写入值来源、索引含义、调用参数或本次未写后果；写不出就改写成该行特有后果，不能删注释或整行略过。避免把同一句模板机械套到成百行；覆盖率满不等于合格，低价值与重复仍判错。这是教学输出契约，不是生产源码行业规范。

## 覆盖范围与位置

- 检查全部章节/深度/对象的教学源码块，含 HBK、FB/FC/MFB/POU、ST、STATE、INTERFACE、FLOW，不限 ch5/Mxx。
- 逐项解释**每条非空可读源行**（执行语句、声明、调用、分支与结构闭合行）：本行条件排除了哪条路径、写入什么值给谁看、下标/常量来源、实例调用的可见参数与输出、走这条路时哪条分支被跳过；结构闭合行只交代它承接的范围。`IF`/`ELSIF`、`ELSE` 选路及其跨行条件（含 `AND`/`OR`、括号判据与独立 `THEN`）必须逐行追加 ` // AI: ` 说明当前判据或路径，不能只注释赋值；标记固定为半角冒号加一个空格，全角冒号、缺空格或小写写法按格式不合规拒绝；`CASE` 头/标签、`VAR_INPUT` 等按本行实际作用说明；结构闭合行同样要写最短的准确范围承接，但不能只写“结束判断”“条件判断开始”这类无对象套话。
- 判定“无效注释”：不含本行的具体标识符/常量/分支条件，且说不出本次写入、未写或跨扫描后果——三者皆无即套话。机械句式（“执行一次赋值”“延续上一条表达式”“控制结构边界”“调用一次功能块”）成批出现即按缺陷返工。判定动作：核对尾注是否准确说明该行对象、动作或所承接的范围；准确的保存、发送、清除本身有价值，不要求每条额外写风险或正文之外的新信息。
- 略过注释不等于略过讲解：被略过的难点（循环内每次赋值、后写覆盖、定时器输入与 Q 的区别、多分支优先级）必须写进块级正文与纸面轨迹。
- 空白/纯注释行不重复说明；纯闭合行（含跨行条件末尾只含 `)` 的行）也须用最短的准确说明交代所承接的范围，不能省略、不能只写“结束判断”。默认口径即逐行，`--require-every-line` 只作兼容别名保留，不必也不应等到用户再次要求；低价值/重复语仍判错——覆盖率满不等于交付合格。原作者注释逐字保留，但不代替新增说明；已在完整原行后追加过本轮 ` // AI: ` 的行不再叠加第二个标记。`END_IF; x := TRUE;` 的赋值仍单独解释，声明/条件/分支/调用不算闭合。
- 完整、非嵌套、只有一个简单赋值的单行 `IF 条件 THEN 赋值; END_IF;`，可用一句“必要触发条件＋业务含义”同时解释条件与动作，不强制写“单元1/2”。缺少闭合、嵌套、多动作或调用不套此例外；真正多动作的物理行保留逐字符源前缀，尾部用 `// 单元1：<第一单元作用> | 单元2：<第二单元作用>` 顺序对应。不插块注释破坏原字符；仅无外部原文的自造片段可就近合法块注释。
- 块级整体说明不能替代行内覆盖；行级细节留在代码注释，正文不再要求“逐句看”列表；空 `//`、空 `(* *)` 无效。同一行的 `(* ... *)` 可用，但跨行块注释不能替多个可执行行占位。
- LAD/FBD 不伪造文本源码：保留原图或原生拓扑，按可辨网络/梯级做网络级说明，关键元件关系融入网络整体说明，不逐行追加 ` // AI: `；文本网络按逻辑单元检查，图形拓扑/覆盖另行人工核对。

## 什么值得写

行内以**简短业务含义＋必要触发条件**为主，每条非空源行都要写；原有注释逐字保留并仍追加一次 AI 短句，不因原注释清楚而省略。简单赋值也说明该路径的实际作用，不只翻译赋值语法。代码围栏外再详细解释整块功能、原理、实现原因、执行顺序、覆盖关系和连续状态推演；不把这些内容或证据声明全部塞进每行注释，也不加“教学补充”前缀。

以下为虚构教学约定：`xPermit` 是本站启动许可，`astStation[i].xStart` 是本站机台启动请求；未约定物理输出或反馈。

```st
IF xPermit THEN astStation[i].xStart:=TRUE; END_IF; // AI: 获得本站许可后向机台发出启动请求
```

围栏外说明：许可为假时本次不写启动请求，并非自动清除请求。若要推演下次调用是否保留旧真值，还要明确同一存储目标、无其他写入或重新初始化等假设；发出请求也不证明机台已经启动。这样让行内读出业务，正文讲透机制与边界。下表是逐处分析问题，不是要求每行注释回答整张表。

| 位置 | 应回答的问题 |
|---|---|
| 声明 / 初始化 | 当前片段为什么需要这个状态；初值对入口或首次调用有什么影响；保持属性是否有证据 |
| 复合条件 / 续行 | 本子句排除哪条路径；与 AND/OR 的其它部分如何共同限定动作 |
| ELSE / ELSIF / CASE 标签 | 此路径何时被选中；与其它路径的优先级、保持或恢复后果 |
| 赋值 / 状态转移 | 哪个后续判断会看见新值；本次扫描与下一扫描的差别；保持/清除边界 |
| 定时 / FB 调用及参数 | 本次调用如何推进实例状态；持续条件、中断、调用先后与输出消费时机 |
| 常量 / 地址 / 下标 | 单位、来源、访问边界或结果用途；设备映射只从符号表/设计资料确认 |

缺工艺证据仍解释可证数据流/扫描后果，不凭 `xCycleFinished` 等名称猜上下游/动作；“未知”须指具体缺口与结论限制，不作万能后缀。

**同一个缺口只在块级正文说一次。** 把“本参数取值来源在此源码中未知”挂到每个实参上、“把本次 X 输出传给 Y”挂在每条赋值上，属于同一句事实的逐点复制，删除测试同样不通过：缺口集中写一次并标明限制了哪条结论，行内只留该处特有的后果（首次调用的初值、哪一侧先读、不走这条路径时谁保持旧值）。

### 教学语义边界：先核对证据再下结论

已给上下文可用：夹具约定 `xPartIn` 工件到位、`yClampValve` 夹紧命令、`xClampDone` 到位反馈时可据此解释，不扩展到未定义字段。不能凭名称补出业务含义：缺符号表/编码时，`wAlarm = 0` 不等于无报警，`xCheckEnable` 不证明许可或松开动作。

局部赋值不保证下一扫描：后续写入/初始化/调用前更新可覆盖。不能断言机构动作：命令写入不证明输出映射、阀型、反馈或解除方式。调用条件未知时说“本次执行到此行”或“若每扫描调用且条件成立”，片段末行不等于扫描尾。`yReady := FALSE;` 可解释撤销旧真值、赋值后读取为假，注明其它写入/业务未知，仍须行内解释。

同一夹具正反样例如下；反例不可用。未提供调用表、后续写入、`wAlarm` 编码、输出映射。

| 源码 / 位置 | 反例：越过已知边界 | 正例：按已知范围解释 |
|---|---|---|
| `yClampValve := TRUE;` | 解除夹紧由段外逻辑负责 | 本段不撤销 TRUE，物理解除方式未知 |
| `iStep := 30;` | 下一扫描 iStep 必不等于 20 | 若后续无改写且再次调用时值仍为 30，20 条件才不成立 |
| `wAlarm = 0` | 无报警条件 | 只确认与 0 比较，编码含义未知 |
| `xCheckEnable := xCheckEnable AND (wAlarm = 0);` | 扫描尾自动恢复许可 | 本次赋值只能保留真或写假，不能把旧假变真；业务用途未知 |
| `本段调用` | 每扫描执行 | 若每扫描调用且入口成立，才会每扫描写入；调用顺序未给出 |

这组内容契约只锁定教学规则与样例，不证明词法器理解任意业务。自动器只拦已知形式；逐块审查须将反例记为未解决问题，文末未知声明不抵消正文/行旁无条件断言。

以下为**正例，虚构的教学约定**：IsValid 返回读数有效性；TCScale/TCOffset 是通道换算系数，未提供单位或质量位的清除路径。

```st
IF IsValid(TCInput) THEN // AI: 有效性门控只保护换算路径，无效读数不会刷新温度值
    Temperature := TCInput * TCScale + TCOffset; // AI: 更新本次有效样本的换算结果，单位仍须由通道配置确认
ELSE // AI: 无效样本转入质量标记路径，旧温度值在此分支保持
    TCBadQuality := TRUE; // AI: 该路径只置异常标记，不能据此认定有效样本会自动清除此标记
END_IF; // AI: 闭合读数换算与质量标记的选路
```

正例：源码只给出数组范围，不能把 60 个元素推定为 60 个工位；未提供数组声明，合法索引边界仍需核对。

```st
FOR i := 1 TO 60 DO // AI: 本轮只处理 1..60 范围，范围外的旧结果不会被此循环刷新
    aResult[i] := FALSE; // AI: 为当前元素撤销旧结果，后续判定须重新建立本轮结果
END_FOR; // AI: 闭合本轮数组结果清除循环
```

正例：复合条件中的名称只作为符号，不擅自赋予上下游关系。片段仅展示入口条件，不是完整可运行结构。

```st
IF xPartIn = 1 // AI: 到位字段等于 1 是本入口的必要条件，与下方条件共同门控；不据此断言短路求值
AND NOT xClampDone // AI: 完成位会封锁本入口，其实际生产方需查写入点
AND NOT xClampAlarm // AI: 报警位也能封锁同一入口，两处数据的更新顺序需另行核对
AND NOT xManualClamp THEN // AI: 仅手动与报警都未介入时进入，已有任一状态会阻止自动判定
```

正例：已进入报警路径的状态后果。

```st
xClampAlarm := TRUE; // AI: 本分支锁存报警结果，具体复位点需查其他写入逻辑
xClampDone := FALSE; // AI: 清除旧完成结果，避免与本次报警状态并存
```

## 反例隔离（不得用于成品）

下面是**明确负例，仅展示应拒绝的写法**，故用 `text` 围栏隔离，不作为教学源码正例。

```text
yClampValve := TRUE; // yClampValve
yClampValve := TRUE; // 将 yClampValve 赋值为 TRUE
yClampValve := TRUE; // 执行当前操作
yClampValve := TRUE; // 处理本段逻辑，未知
ELSE // 条件成立执行
```

禁字段/值直译、`// 语句`、`// 条件判断开始`、`// 结束判断`、重复套话、万能“未知”；正确意图复制到所有行也不算逐处解释。跨块重复相同源码可沿用正确注释，不机械去重，仍审查各位置后果是否相同。

**逐行覆盖最常见的失败是把一句模板盖到成百行上，而不是逐行本身。** 门禁按逐行执行后，最省事的做法是把一句模板（“条件表达式续行：与前后布尔项组合…”“结束/分支边界标记，不单独写入状态”）盖到成百行上，覆盖率满而读者一无所得。修正方向是**每行写该行特有后果、加强正文**：难点的因果与推演写在块级正文和纸面轨迹里，行内只写这一行的对象、判据、写入/不写或范围承接；不得用另一种更长的模板句替换旧套话，也不得把旧逐行解析表的整句搬到行尾；更不得以“信息量不足”“正文已说明”“精简版”为由删注释或整行略过。

## 删除测试（每条新增尾注的验收动作）

写完尾注，设问：**删掉它以后，读者会少知道一个具体的条件、数据来源、执行先后、本次写入/不写的结果，或一个边界吗？**

| 自问 | 答不出时怎么做 |
|---|---|
| 它是否说明了本行的判据在排除哪条路径？ | 改写成“若此条件不成立，哪条写入不会发生” |
| 它是否说明了这个值的来源或去向？ | 指出下一个会读它的判断，或承认读取点未知 |
| 它是否说明了先后依赖（为什么先写后读）？ | 交换顺序会怎样，写成一句 |
| 它是否说明了“本次不写”的后果（保持、由谁清）？ | 写成保持或未知，不写成“清除了” |

四个问题只是复杂行的改写线索，不是每条短注释的必答题；简单业务动作与准确的结构承接仍须保留。无对象套话应改写，不删除应有尾注。反向陷阱：把“关键行”理解成“所有关键行”，同一句判断在十个分支上重复——重复同样过不了删除测试，须按各位置实际后果改写，不能略过未写的位置。

## 结构叙事是套话的伪装（默认逐行下最常犯）

把被禁的句式换一种说法，价值仍是零。`// 第一项条件，读当前工位到位输入，必须等于1`、`// 有车分支的起始边界`、`// 条件成立后执行下面唯一的赋值`、`// 分支汇合边界，两条路径到此结束`、`// 未获放行时 start 保持原值`，与 `// 条件判断开始`、`// 结束判断` 同属一类：结构走向读者从代码已经看见，删掉不损失信息。覆盖到这类闭合行或结构行时，必须写**最短的准确指引**（这一行承接哪一段范围、写的是哪个目标），不要为凑“有解释”而扩写结构叙述——扩写让它更像有内容，删除测试反而更难过；也不能因为难写就省略。

**带数字的行必须给对照数值。** 下标、边界、常量、位号的行，注释要点名索引对象，并在正文或紧邻处给一组具体取值。自造示例：`缓存区号 2、选中槽位号 7 → 读的是 axSlotPermit[7]，不是 axSlotPermit[2]`；`条件允许下标 <=24，但数组只声明为 ARRAY[0..15]，16..24 仍可能越界`。只写“按槽位号取许可位”、不给数值对照，读者仍会把两层下标读成同一个号——这正是嵌套索引行最典型的误读。

## 注释被否时的返工顺序：先校准小样，再批量

注释缺少实际信息时，应先校准表达目标，而不是增加字数或覆盖率。**先用少量难点源行校准，再批量返工**；格式、覆盖率与源码对账通过只证明对应机械检查，不证明读者已理解。批量返工须按各行的真实语义改写，避免仅替换同构句式。

1. 从当前稿挑 2–3 行最难的（两层下标、条件外赋值、边界常量、跨调用保持），只重写这几行。
2. 每行配 3–5 句纸面例子，用具体数值走一遍，写明这条注释防的是哪个误读、不写成会怎样。
3. 连同“注释规则要改成什么”一起交小样，等方向确认后再回填全文。
4. 方向确认前不动候选模板、不动已安装 Skill、不重生成整篇；也不把“已暂停整批改写”说成已完成。

小样获认可后批量返工，按新规则逐条重审，不沿用旧稿句式换皮；不要用“覆盖了多少行”“审查记录多少条”证明价值——那是覆盖率证据，不是信息量证据。

<a id="ref-nav-07"></a>

## 删除注释时同一步清理审查记录

尾注与审查记录/账本分居两处时，删掉一条低价值注释必须在同一步删掉它对应的记录条目，改写则同步改写；只删样稿会留下指向不存在注释的幽灵条目，只改账本则是给没发生的审查背书。收尾用检查器自己的推导路径复核一次——导入 `check_annotation_quality.py`，直接调它从样稿抽记录的入口与账本键函数，断言键集完全相等、无重复键、条数与样稿实际新增注释数一致。手写切分去解析围栏、续行、块注释和 `src:` 行号偏移，很容易算出一个看着对但已经和样稿错位的账本。

## 源码内逐行注释的风格参考

每次生成或改写源码内注释前，先读 [业务短句规则](inline-comment-style.md) 的“注释前置参考”与“变量命名辅助推断”，以及 [11组自造示例](inline-comment-examples.md)。采用对象＋动作＋结果、必要时加条件的业务说明；相邻同类赋值允许一致句式，准确的保存、发送、清除说明本身有价值，不要求每条都新增风险或正文未表达的信息。业务短句的表达口径优先，删除测试用于识别无信息的重复说明；覆盖密度固定为默认逐行（空白与纯注释行除外），只有当次明确要求原样源码或仅归档时才不追加。下标风险、保持、覆盖、平台限制与推演放段后正文，既有栏目和模板保留。示例全为自造材料；用户工程真实源码仅用于其本次独立预览，不加入技能样例。

<a id="ref-nav-09"></a>

## 源字符与原注释保真

- 原逻辑、变量、字符串、缩进、尾部空白和原注释均保留，只在完整源行之后追加注释；不能删除低质量的**原始源码注释**来美化教学稿。只追加不重排，源行自然成为成品行的字符前缀，逐行前缀相等只证明原字符保留；还须独立核对新增标记与非空尾注，不能用 `new.startswith(orig)` 单独证明已注释。
- 原作者注释逐字保留，但不代替新增说明：即使原注释已说明业务，仍在完整原行后追加一次 ` // AI: <简短说明>`；仅当该行已有本轮尾注时不再叠加。新增部分单独受质量门禁约束，不加“教学补充”前缀。检查器仍兼容历史前缀，不据此要求新稿使用。
- 字符串内 `//`、IEC `$'` / `$"` / `$$`、双引号/单引号重复转义、常见厂商反斜杠转义及 `(* ... *)` 内的 `//` 都不当作新行注释。
- 位于未闭合跨行块注释内部的源行，不能盲目追加 `//`；只能在原注释闭合后的可执行行末合法追加。无法安全追加时列为待补/待审，不能假称全部覆盖。
- `check_code_integrity.py` 与注释门禁职责分开：前者根据匹配源文件与 manifest 检查逐字符前缀和原注释保留，不解释注释语义；`src:none` 不是源码保真的证明。
- 严格引用另交原文跑完整性 `--strict`；教学注释稿独立过覆盖门禁，未注释原文不算已审教学稿。

## 自动检查能证明什么

`scripts/validate_handbook.py` 单文档模式（不加 `--final`）除覆盖率外还拦四类质量问题，先跑它再谈版式：

| 报错 | 触发原因 | 改法（不是删注释） |
|---|---|---|
| `未声明适用章节` | 文首缺 `> 适用章节：五、模块详解；九、未确认与证据` | 补声明行，章节 ID 与正文实际标题一致 |
| `注释信息价值低：字段/值直译` | 注释复述了 `NOT x` 就等于 FALSE | 换成证据边界：`FALSE 仅是本次输入值，不足以证明已空闲` |
| `「关键逻辑」只有描述没有推导` | 段落只说条件是什么，没写删改后果 | 用“若/因为/因此/否则/会”写明：若该条件不成立，哪些写入被跳过、哪些结论不再成立 |
| `注释重复粘贴（首次 Lxx）` | 相邻执行行套用同一句注释 | 核对是否说明了各自对象和动作；同类字段可沿用一致句式，不要求强造不同后果 |

这几类都不靠删注释通过：直译改成边界、套话改成该行的具体后果，覆盖率与语义价值同时满足。相邻行（如 from/To 两个同名完成位）最容易触发重复判定，写时就按“谁的生产方/哪一侧的握手”区分。

`scripts/check_plc_comments.py` 全文识别 PLC 标签（大小写不敏感）：ST、Pascal、SCL、structured-text / structured_text / structuredtext、iecst、iec / iec61131 / iec61131-3、plc、FB、IL/AWL、LD/LAD/ladder/ladder-logic、FBD、SFC。支持 `{.st}`、信息串、≥3 反引号/波浪号、≤3 格缩进并匹配闭合长度。

嵌套须长外围栏；外围未闭合或同长内栏疑吞源即错。引用/空格列表按下节解析，不支持容器明报错，不静默跳过；无源码不称审查记录已验。

教学交付默认按逐行口径检查（`check_plc_comments.py` 默认即逐行，`--require-every-line` 只作兼容别名保留）：每条非空 PLC 代码行（含结构闭合行）都必须有行内注释；`--legacy-selective` 只用于历史夹具的选择性注释审查，日常交付不使用；`--original-source` 只在当次明确要求原样源码时使用。

默认口径只认**代码之后**的尾注：同一行先写 `(* … *)` 再跟代码（`END_IF; (* 已结束 *) END_FOR;`）不覆盖后续语句；一个物理行有多个单元时各单元都要可辨认地说明；闭合行同样须有自己的尾注并受低价值/套话门禁。交付时把实际命令与输出一并给出，不口头声明已覆盖。

普通局部 B 与长手册的新 ST/SCL 追加注释稿另启用 `--require-condition-ai`：IF/ELSIF/ELSE 以及到 THEN 为止的跨行条件（含 AND/OR、括号判据）逐行要求真实 `// AI: ` 尾注；字符串/块注释中的标记不算，纯 END_IF 与只含 `)` 的闭合行不在此开关内重复强制，由默认逐行口径要求最短承接说明，CASE 的 ELSE 不按 IF 条件要求，LAD/FBD 不套此 ST 检查。

`plc`/`iec`/`fb` 等别名围栏若含 THEN/END_IF 等 ST 结构则按 ST 检查，只有条件关键字却无 ST 结构时报“无法判定”诊断，不静默放行。标记只认半角冒号加一个空格；全角冒号、缺空格或小写写法报格式不合规，不混同“缺少标记”。低价值判定取 AI 标记之后到下一个 ` // ` 片段的文本，后续片段不能替低价值说明兜底。已存在的作者注释保留且不代替新说明；原样源码请求除外。

只检查标记与已知低价值形式，不独立证明标记确实位于作者尾注之后，也不能证明条件解释正确。历史稿审查不追溯要求把旧注释改成新标记。

CLI 默认即逐行口径，`--require-every-line` 只是兼容别名，不再需要额外开启；空尾注报告“代码行缺少行内注释”，低价值和重复内容单列质量错误。输出文件路径、行号和源行摘录，任一错误退出非零。字符串及跨行块注释内的 `//` 不算尾注，跨行块注释不能覆盖开头的执行行。整册注释版沿用五部分块级结构，不增加独立逐行表；局部 B 保留原码与原注释，并按简洁业务句追加有效尾注；要求原样源码时不追加。

门禁查围栏、字符串/注释边界，按行/分号/THEN/DO/OF/ELSE 划单元查覆盖，拦已知语法空话、标识符/值复述、字段赋值翻译、注释重复、未闭合字符串/注释/围栏。清单列待解释单元/行号；长度/关键词不证明价值，不用任意大正则猜业务。

错误定位 `L行号 单元 序号/本行需解释单元数`；JSON `required_units` 列行号/序号/源码/覆盖。默认逐行口径下 `closure_lines` 也须尾注并计入需解释行；只有 `--legacy-selective` 历史稿才把无注释纯闭合行单列并登记理由。独立/手册检查器共用结果。执行行缺注释或低价值仍报错，审查记录不豁免。

不能证明任意语言注释价值、业务真实、任意 IEC 方言语法、特殊上下文合理性、图形覆盖、安全等级或审查诚实。新同义转述/伪造理由可能逃过有限检查；静态通过不等于注释全合格。给检查器加套话识别时，需求或用户点名过的每条无效说法（如“执行一次赋值”“调用一次功能块”“控制结构边界”“延续表达式”“处理数据”）各配一条负例和同位置具体正例；测试不要只断言文档里存在某句要求（“含删除测试”“含具体”这类关键词），否则带空话的样稿只要抄中那几句照样通过。检查器报 0 findings 只说明已知形式被清掉，交付前仍须逐条读完样稿注释并自己做一遍删除测试。

## 私有工程注释风格资产化

将私有源码中的注释风格提炼为技能资产时，交付物是**方法＋另造样例**，不是源码摘录。先看原作者注释到底保留了哪些信息（对象、动作、条件、是否写结果），再用一句话归纳，例如“对象＋动作＋必要时条件，短句说明实际用途”。接着**换业务场景与数据流独立编写** 1–2 个样例：不同行业对象、不同变量名、不同语句形态，单语句计算比照原工程的条件树/数组映射/握手流程更安全。仅改变量名、改编号或同义改写原注释都不算另造。

顺序固定：提炼规则 → 造样例 → 本机对照检查 → 出仓库外候选目录 → 交《隐私与相似性说明》→ 用户确认后才接入技能。确认前不写 `~/.hermes/skills`、不改已装模板、不 commit；候选只含 Markdown 资产，真实私有源码小样不并入候选包。

**样例要覆盖句式谱，不是凑条数。** 一两个样例只证明会写单语句，读者拿不到跨场景判断力。按控制形态各给一例：条件分支（含 ELSE 的保持路径）、连续多行赋值、`FOR`/`WHILE` 循环、标准功能块调用（`TON`、`R_TRIG` 的可见 IN/PT/Q）、边沿或事件检测、限幅/夹取、状态切换（`CASE` 或相位分支）、以及**已有作者注释时如何追加而不重复**。最后一个必须用两块展示“追加前/追加后”，并断言剥离新增尾注后与自造原行逐字符相同、重复追加不产生第二份尾注。

**扩充样例按增量处理，不重写已确认内容。** 保留已确认的风格规则与旧样例原文，只追加新场景；旧稿另存路径不覆盖，交付时用哈希证明旧文件未变。每轮扩样后必须**对新文件重跑一遍全文比对**——新增段落里的说明文字同样是被检查对象，追加内容最容易把先前只比对过尾注的口径绕过。

对照检查在本机做，不把私有资料传网页或第三方查重服务，脚本与对照记录放技能目录外，不成为技能运行依赖。可复现的计数项：

| 检查项 | 口径 |
|---|---|
| 标识符复用 | 剔除关键字、字符串、注释后取标识符集合，与原码/元数据/变量表比对，须为 0 |
| 原样代码行 | 去空白与大小写后逐行相等，须为 0 |
| 作者注释整句 | 归一化后整句相等或最长连续重合 ≥ 6–8 字符，须为 0 |
| 路径 / IPv4 / 邮箱 / UUID | 候选全文模式扫描，须为 0 |
| 重命名后词法重合 | 把标识符统一换成 `ID` 后的最长连续 token run，**单列说明** |

重命名后仍有 4–6 个 token 重合通常来自 `IF`/`:=`/`>` 这类通用语法，不等于算法或业务结构相似，不要拿它冒充相似度结论。

**标识符命中要分层报，不许靠静默过滤把结果做成 0。** 标准功能块接口名与类型前缀（`IN`、`PT`、`Q`、`ET`、`CLK`、`T#` 的 `T`）本来就会和工程里的短标识符撞名。检查器同时输出原始交集数、剔除标准接口后的**项目自定义标识符命中数**、以及被剔除的 token 列表；报告里保留原始计数与那份列表并注明“人工核对为标准接口/语法，单列不计入项目标识”，不要只写“标识符重合 0”。判断标准是 token 是否为该平台的标准接口或语法前缀，不是长度阈值调参。

**结构相似要给双向说明。** `IF`/`CASE`/循环/赋值的骨架在任何 ST 程序里都出现，结构相同既不能证明私有逻辑被复制，也不能反过来证明“完全不相似”。正文写清这一层，再谈人工判断的场景与数据流相似度。检查器要先用临时内存中的原标识、原注释构造反例，断言能被检出，否则 0 命中可能只是正则没生效；对照前先核对归档 `归档校验.json` 的 sha256，证明比对的是同一份源。

报告只写可复现计数与适用范围：**不给整体相似度百分比，不声称零泄露**，并说明词法检测无法覆盖同义改写、设计思想相似和未提供的其他工程。分三句结论：私有内容直接残留（当前未发现／发现 N 处）、业务场景与数据结构相似程度（人工判断低／中／高及依据）、注释表达风格相似（有意保留）。最后请用户确认两件事：候选是否仍含其认为敏感的信息、这种相似程度是否可接受，并写明确认对象仅限哪几个文件。报告用“检查项—口径—结果”的分项表（标识符、原样长行、作者中文注释 4/6/8 字重合、最长连续中文重合、归档全文 4/6/8 字重合、路径/IP/邮箱/UUID），每项单独给数，不要在文末折算成一个总分。

**样例里的逻辑要验，但只能报成纸面检查。** 自造示例含数值、分支真假、边沿序列、TON 门槛、状态转移时，用 Python 断言走一遍这些结论（输入→期望输出），并写明“n 项纸面断言通过，未执行 ST 编译、仿真、Trace 或硬件验证，功能块语义是本例显式约定”。另外核对代码块围栏数、`IF/CASE/FOR` 闭合配平、原行保真、去重追加。纸面断言证明的是文中叙述自洽，不是 PLC 运行结果；两者混报会让用户以为样例已在平台上跑过。

**候选包只装参考文件。** 合并稿（规则＋样例＋说明）单列一份 `.md` 交付；ZIP 只打包 `references/` 下的候选文件，写完逐个条目的 sha256 与审计结果对齐，并确认包内条数等于参考文件数——归档原文、对照脚本、历史真实样稿都不入包。

**围栏标签按归档实际情况取。** 工程导出常用 ```` ```iecst ```` 而非 ```` ```st ````，抽取代码块的正则只认 `st` 会得到 0 块却当成“没有源码”，先列出文档里全部围栏标签再写正则，并对块数与 `归档校验.json` 的 `sections` 数量断言相等。

## 作者逐块语义审查（必做）

生成后逐个源码块核对并列出每个需解释的行/单元及其处理：

1. 注释说的是这一处的作用/后果，而不是字段或语法翻译；不同路径的说明有实际区别。
2. 条件组、分支优先级、状态写入与调用顺序确实与原文一致；不把未出现的复位或安全性质说成事实。
3. 每项工艺含义有源文件/符号表/设计说明依据；仅源码可知的数据流与外部未知分开。
4. 原注释、字符串及所有源字符保真；负例与占位文字未混入成品源码。
5. 记录块位置、当前摘要、全部需审查行、证据与判断理由；有问题或未审查不能登记完成。

**审查记录的结论必须逐条特有。** 每条记录写清「删掉这条注释，读者会失去哪个具体条件/来源/先后/不写后果」，各条理由能彼此区分；几十条共用一句泛化结论（「已人工对照该源行，删除后会失去具体事实」）即说明逐条审查没有发生，按未审查处理，不要因为测试通过就认账。自动测试最多证明每条注释都有一条记录、记录与当前文本 hash 绑定，它不证明结论是真审查——门禁绿了仍要抽读结论是否可区分。

最终稿提交独立 JSON 记录，经 `--comment-review <记录.json>` 核对（`--final` 必需）。格式如下，行号是**成品 Markdown 行号**，列表按源码顺序；真实值须来自当前稿，不能抄此占位示例：

```json
{
  "document_sha256": "<当前文档原始文件字节SHA256，含CRLF或BOM>",
  "reviewer": "<实际作者或审查者>",
  "blocks": [{
    "fence_line": 12,
    "code_sha256": "<围栏正文以LF连接、不含围栏的SHA256>",
    "status": "reviewed",
    "covered_lines": [13, 14],
    "evidence": "<源文件/行范围/符号表；或明确的虚构教学约定>",
    "rationale": "<逐项核对条件、当前作用、下游后果和边界后的判断>",
    "issues": []
  }]
}
```

文档摘要用 `hashlib.sha256(Path(path).read_bytes()).hexdigest()`，块摘要用解码后 LF 连接正文的 UTF-8；支持 UTF-8、CRLF、可选 BOM。摘要/块集/行集/状态/依据/理由/零问题任一不符即拒 final。`issues` 记未解决注释错误，客观未知可在 `evidence` / `rationale` 说明，注释须准确限界，不编结论清空 issues。有错仅交非最终稿并标待审；记录只证明声明绑定当前文本，不证明机器理解。父代理/人工未复审标“待复审”，不称全合格。

块记录可选 `"omitted_lines": [{"line": 15, "reason": "仅闭合上方条件范围，无新增动作"}]`（历史稿示例）；仅 `--legacy-selective` 历史稿审查可用并只登记当前 `closure_lines`，默认逐行交付不得用省略记录代替闭合行尾注。提供时须列表，整数行号、非空理由、不重复；拒执行行、混合行、已有注释行、虚构行。`covered_lines` 仍等于全部 `required_lines`，不扣项。旧记录兼容，可在 `rationale` 逐列闭合行/理由；不豁免低价值注释。

模板里的 `<...>` 是填写边界，必须放在明确的 `text` 占位围栏中；替换为真实源码后使用 PLC 标签并运行覆盖、源码对账及语义审查。不能拿空模板当完整源码通过验收。

长闭合结构的保真与教学分段见 `references/code-reading.md`；所有非空源行（含结构闭合行）仍须有价值的行内解释。

## 来源标记与 Markdown 视图

来源共用 `scripts/source_annotations.py`：`<!-- src: 12-20 -->`、`<!-- src: source.st:12-20 -->` 或 `<!-- src: 12-20；来源/对象：source.st 或对象定位证据 -->`，中英文分号均可。每块独有标记紧邻开围栏（可隔空行），不跨正文/标题/前块复用。行号为 1 起闭区间、起≤止；有匹配源时查文件名、上界、逐行字符。声明、首 NETWORK 前初始化、未知前缀仍属源码；manifest 仅排空白、整行 //、可识别 [POU] 头，其余待分类，人工确认后命名。

坐标不可得时使用 `<!-- src: none；来源/对象：可定位对象或未知 -->` 并在正文说明证据限制；它不证明源码保真，也不能通过全源码完整性 final。不能用 src:none 为后续块提供来源、隐藏真实可对账源码，或把未知代码当成教学伪源码。

共用 `scripts/markdown_fences.py`：至少三个反引号/波浪线，闭栏同字符且不短于 opener；反引号信息串禁含反引号。长外栏内短栏仅示例，行内标记不开块。共用语言别名（ST 含 pascal/scl/structured-text/structured_text/structuredtext/iecst，PLC 另含 FB/IL/LAD/FBD 等），忽略大小写并支持属性标签。支持 `>` 引用、空格缩进无序/数字列表，剥前缀后按原物理行查执行行。tab 等异常缩进必报错，不零块假绿；列表包引用/同行嵌套列表等不支持组合报容器诊断，移顶层重验。本模块仅围栏/正文视图，不是完整 Markdown 渲染器。

章/目录/覆盖状态/正文表格查隐藏围栏的正文视图；Mermaid 取已解析块，`~~~mermaid` 同反引号。完整性/注释消费代码视图，防示例标题/表格/来源污染正文；不支持 PLC 围栏明报诊断。只读门禁区分源码下载/强制行为描述、离线手册下载、现场建议；禁指导强制 Y0、下载控制器、旁路保护。词法通过仍须作者查全文只读边界。
