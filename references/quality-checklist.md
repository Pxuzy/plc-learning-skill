# PLC 代码讲解质量检查清单

> 用途：核对实际讲解是否从事实推出原因，格式检查与语义审查分开记录。
> 适用：五部分块级讲解；局部模式 B 默认追加简洁业务短尾注并逐字保留原字符与原注释（用户要求原样源码时不追加），完整手册/教学重建保留行内教学注释。
> 本清单仅检查所选模式已有规则，不新增要求；B 输出规则以 `references/local-code-explanation.md` 为权威，执行方法按条件读取 workflow 的命名区段。

## 一、范围、来源与正式稿

- [ ] 完整手册先写一页整机逻辑主线，按可见证据串“输入→入口条件→状态→结果→消费者→复位”；调用/实例/任务关系未知时分开列示，不把节号当运行顺序。
- [ ] 语言像讲师带读：先说本段作用，再看条件和结果；短句常用词，术语先白话解释，重复背景和空泛好处删除，必要因果不删。
- [ ] 源码对象、可见范围、声明与调用证据明确；片段不冒称完整工程，未知内容不补造。
- [ ] 片段未闭合（缺 `END_IF`/`END_CASE`）时已明确标注，且没有据此断言“本段无复位”；示例工程不被说成投产代码。
- [ ] 关键变量在源码前，五部分顺序不变；类型来自声明，不按名称猜类型或业务。
- [ ] 变量表标识符与已知类型用行内代码，用途/条件/写读方不同的变量逐项列出；公共声明与假设有就近说明，表头与表体连续、列数一致，不把长机制说明塞进类型格。
- [ ] 正式稿只有当前结论、证据和教学假设，不混入修改对话、版本争论或维护过程。
- [ ] 源码与说明相邻。短块按逻辑切；单一长闭合结构完整保留一次，用至少两处分支锚点导航，不受25行机械限制，不截条件或补造闭合语句。
- [ ] 模式 B 原字符、空白与原注释逐字保留；默认按注释规范追加简洁业务短尾注，用户要求原样源码时不追加。完整手册/教学重建按注释规范覆盖执行单元，仅纯闭合行可登记省略理由。

- [ ] B 的完整源副本、版式与适用语义已按正式局部参考核对；有工具且实际校验时按 workflow 的“局部产物校验”执行，ERROR 未消除不报通过；无工具记未执行，未审项不报语义通过。
- [ ] 用户要求零基础时，第三部分源范围映射覆盖调用、ELSIF、末行赋值等全部执行单元；逐处确认作用/条件/结果及首次出现的 IN/PT/Q、赋值、分支解释。映射齐全不证明语义正确；新手复述未做则记未验证。

## 二、功能定位与设计依据

- [ ] 区分已给目标、代码事实、推断和未知；无工艺证据时只解释变量行为，不凭命名断言设备动作。
- [ ] 从目标与约束提出所需信息：当前电平、历史状态、持续时间或分支优先。再说明条件/状态如何提供这些信息，不用现有源码反证需求合理。
- [ ] 说明“为什么需要这种行为”，不预设当前写法唯一、最优或无缺陷。条件可能冗余，需求不明可写不足以确认必要性。
- [ ] 逐处检查“一句话说清”、功能定位、变量含义及正文的首个库/保持结论：在该处就限定 TON、同实例/无外部写入等假设；不能正文无条件断言，末尾才统一写未知。出现“未知”本身不是放行理由，必须核对其所限定的具体结论。
- [ ] 进入条件说明真假路径和可核对原因；“为了安全/防抖/规范”或出现因果连接词本身不算推导。

## 三、代码块整体讲解

### 处理过程

- [ ] 写出哪些输入经过什么判断，具体写哪些目标或跳过哪些写入；分开条件操作数的读取与分支执行。
- [ ] 表中的关键变量在整块真实逻辑中有明确角色：读入、选择对象、保存历史、中间判断、写入或消费；解释判断所需信息及由谁提供，不只翻译语法或罗列名称。
- [ ] 不以“执行判断”“满足条件则赋值”“详见代码”等代替具体变量与结果。

### 关键逻辑

- [ ] 至少选择一处有理解价值的条件、状态或顺序，用具体输入说明作用和边界。
- [ ] 删改反例一次只改变一个因素，其他分支、输入、初值与假设相同。替换整段同时改变故障、定时和保持，不足以证明单个条件必要。
- [ ] 原版与改版结果确有差异；无差异时如实说明局部等价或冗余，不编后果。
- [ ] IF/ELSIF 的优先级同时取决于分支先后和互斥，不能笼统说“不依赖顺序”。不同需求下的实现用适用边界比较，不强贴错误/正确标签。

### 写法好处

- [ ] 收益与代价有局部证据。缺少比较依据可写“本片段不足以确认比较优势”，这是合法答案。
- [ ] 不从局部推断全工程单写入、单复位、扫描无关或整机安全；状态保持和定时滤波不是同一机制。

### 状态变化

- [ ] 区分显式写入、本次不写、同实例跨调用保持与掉电保持，不把条件为假直接称作复位。
- [ ] 有清除写入才说明复位方。否则写“本段未见 FALSE 写入，实际清除点未知”；未见复位不证明别处一定存在。

## 四、具体推演

- [ ] 给出真实变量名、具体初值、输入序列及必要的同实例/无其他写入/库行为假设，明确是纸面推演而非实测。
- [ ] 至少三次连续执行覆盖正常、变化和边界；无调用周期证据用“执行”，不冒称相邻扫描。
- [ ] 每步按输入与前值→条件求值→分支→写入/跳过→后值核对；下一步承接前一步后值，不悄悄更换数组元素或初值。
- [ ] 计时重置后必须重新经过所需时间；跨时间跳跃写明经过多久或中间执行多次，不能称下一次立即到期。
- [ ] 仅当所讲源码确实涉及定时器、时间门槛或持续时间条件时，才检查对应时间轨迹；依据实际平台/库语义与明确假设逐步重算。`200ms TON` 的“输入中断后恢复不足时长”与“故障期间已计满后解除”双轨迹只是可选参考案例，不是通用必检项，也不得移植到无关代码。
- [ ] 表格与正文相互一致，说明保持、复位及恢复限制；类比若使用，注明对应关系与不适用边界。
- [ ] 同一实例刚调用后，Q不能脱离IN和历史独立任选；复用定时器的后分支须联查前分支写入，先写Done可能让后支NOT Done失效。条件推演要写明标准库与读取期间输入稳定的假设，不能把不可达输入组合当正常例子。
- [ ] 区分“本次写FALSE/TRUE的条件互斥”与“段末两个输出永远相同”；没有ELSE时历史保持可留下不同值。连续计数不得从6直接跳到90并称下一次，省略中间执行需明示。
- [ ] 教学四字段、行尾AI注释、导航标题、关键变量表及审查结论要一起复核；整记录赋值不能在正文误称只复制abyCode，已给的REAL/F_TRIG声明不能又列为未知。

## 五、交互与交接

- [ ] 来源、目标、关联变量、时机与影响有证据；缺消费者、复位方或调用关系时如实未知。
- [ ] 不从相邻源码推出调用先后，不从状态赋值推出设备已运行，不把待查路径说成已经存在。

## 六、判定与记录

**格式层**：分别记录源码逐字符保真、五部分与变量位置、标题、长结构导航和注释适用性。静态检查只证明这些可确定项，不证明语义。

**语义层**：逐项记录上述适用检查的依据。错误因果、无依据事实、轨迹断裂、虚构复位方或正文自相矛盾均需修复；无法核实的工程行为保留为未知，不为填栏目发明答案。

**不设最低字数或“连接词足够即及格”标准。** 一句有证据的必要性解释可以合格，长文也可能因果错误。篇幅仅决定拆批，不以删源码或省推导来满足上限；既有校验器的短字段/关键词提示只作筛查，不能作为语义签字。

审阅时为每个问题记录：文件与段落、原句、违反的事实或约束、具体反例、修正建议。仅维护技能/审计且获授权的行为微测按 `references/workflow.md` 的“行为微测的验收口径”保存未修改的原回答，格式与语义分栏报告，不将离线回归全绿当作实际输出已合格。

**覆盖不等于讲解（放行门槛）：** 覆盖清单里标 `已讲解` 前，该单元必须已有条件真假路径、写入/不写与保持边界、至少三次连续执行轨迹和一处单因素删改反例；只有概述、变量罗列或限制说明的单元一律标 `未讲解`。源码逐字保真、单元数齐全、围栏检查通过只证明可确定项，不得据此给出整体“通过”，也不得以末尾自认不足代替把该单元讲完。
### 平台行为边界

平台指令的时序、保持、复位、溢出及调用边界只在对应平台/指令证据支持时写成事实；静态扫描、synthetic fixture 和注释都不能替代厂商手册、配置或运行证据。证据缺失时把推演标为假设，尤其不要把 TON 的调用路径或计数器的回绕语义当作通用 PLC 行为。受保护块需要导出时，只提示使用对应厂商工程软件合法导出，不把某一品牌 IDE 写成通用步骤；品牌经验留在对应厂商资料中。
