# 按品牌经验读取 PLC 工程

- 默认先按用户意图和交付要求分流：只提供 PLC 代码或工程且未说明任务时默认讲解；明确要求提取代码、只返回源码、编写/修改程序或完成其它任务时按该任务交付，不自动附加讲解或改成教学重建。具体源码仍按输入形态走最简单、足够的读取方式：

1. **可读源码/文本。** 对 `.md`、`.st`、`.scl` 和其它可读导出，直接读取用户提供的内容并按问题处理。只询问与问题相关的缺失上下文；不进入工程恢复，不要求归档清点、OEM 查找、工程树恢复或全文件索引。目标具体时只读取回答问题所需的局部内容和上下文。
2. **原生工程/容器/归档。** 只有输入形态属于原生工程或容器时才继续本工作流。先核实品牌、产品/控制器、格式、工程软件和版本证据，再走匹配的厂商格式方法。已确认的 Omron NJ/NX Sysmac Studio SMC2 才加载 SMC2 专用方法；不把该路线推广到其它格式。格式未识别时只做最小安全清点，报告限制并请求最小必要导出，不猜厂商或格式。
3. **截图/局部片段。** 只解释可见、可辨认内容；不做工程重建。片段来源按用户提供内容记录，不声称已从工程文件提取。

本流程余下的工程识别、结构恢复与对象映射步骤仅适用于第二类输入。已指定目标只恢复定位所需的最小祖先节点与依赖；完整工程请求才盘点全范围。用户只给粘贴片段、截图或单一源码文件时按可见范围直接讲解，不强制重建整棵工程树；粘贴片段或截图不强制走全工程恢复。

## 1. 识别输入与适用组合

**输入分类（按读取复杂度从低到高）**：

1. **可读源码/文本**：`.md`、`.st`、`.scl` 和其它可读导出，直接读取给定内容；不进入工程恢复，不走归档清点、OEM 查找、工程树恢复或全文件索引，只询问与问题相关的缺失上下文。
2. **原生工程/容器/归档**：核实品牌/产品/格式/版本证据后，选择匹配的厂商格式方法；已确认 Omron NJ/NX + Sysmac Studio SMC2 时才加载专用方法，SMC2 方法只用于已核实的适用组合。未知格式（格式未识别）时只做最小安全清点、记录并报告限制、请求最小必要导出，不猜测或标作 SMC2，不得把其它格式标作 SMC2。
3. **截图/局部片段**：只解释可见内容，不做工程重建；仅在需要且相关时询问缺失上下文。

对原生工程/容器记录品牌、产品线/控制器、工程格式、工程软件及可见版本、来源和用户目标。综合工程元数据、文件内容、导出头与用户说明确认，不能仅凭扩展名、目录名或变量前缀判断；证据冲突或格式未识别时记录候选和缺口，不强行选品牌，也不标作 SMC2。未知格式时限于最小安全清点并记录限制；无法回答时请求最小必要的结构化导出、IDE 工程树/交叉引用或目标代码。固件版本只在影响结论时追查，不作为所有离线阅读的前置条件。

## 2. 加载匹配的品牌经验

从[厂商经验导航](../vendors/README.md)选择对应品牌，再按产品线、格式和版本匹配经验记录。品牌相同不等于格式适用；版本范围未验证时只把方法当候选，先核对本次样本的真实结构。

- 已有匹配经验：读取适用范围、识别依据、步骤、工具实际能力、失败与回退及样本验证结果，随后在本次输入上核实。
- 仅有方法参考：先只读小范围验证字段、结构和映射，不把经验文字当解析结果。
- 没有经验或格式不可读：说明实际尝试和限制；请求最小必要的结构化导出、IDE 工程树/交叉引用或目标代码。已有可读片段仍可讲解，不因解析器缺失阻断。

欧姆龙工程先经[欧姆龙入口](../vendors/omron/README.md)按证据核对产品线与格式。已确认 Omron NJ/NX Sysmac Studio SMC2 的样本再按[SMC2 方法](../omron-smc2-xml-workflow.md)核对对象类别，该格式方法不套用到其它品牌/格式。按输入形态和明确任务选最小读取范围；用户只要单个 ST FunctionBlock 声明/程序体且布局符合当前窄范围时，运行 `smc2_locate_pou.py` 只读定位 OEM 与所请求成员，不先做通用清点或解包。其他类型只按实际样本核对分类、ID、父子归属、引用与内容格式，不把待验证描述写成 CLI 支持。只有用户要求全工程范围或候选格式不适用时才继续本节通用清点/受控解包。通用解包仍须写入新的独立目录，拒绝绝对/越界路径及可逃逸的符号链接、硬链接，限制成员数和实际解压量，并核对写出路径与内容。无满足条件的工具时停止并请求已批准的解包结果或替代导出。不修改原始工程，不尝试绕过保护。

## 3. 恢复原生工程结构

先清点可读文件和元数据，再按该格式实际的清单、工程描述、对象 ID 与引用恢复层级。保留厂商原生对象名称，不强套 `Tasks → POU → Sections` 或任何固定层级。记录每个对象的父子归属、原始名称/ID、种类、定义与实例、来源位置及可读状态；未提供的节点不补造。

工程树排列不证明执行顺序。任务配置、程序登录/调度、显式调用顺序和代码内部顺序分别取证；缺调度证据时只确认对象归属，不声称每扫描按图依次执行。

## 4. 映射目标源码与配置

用显式引用、对象 ID、路径或已核验字段把目标节点对应到实际程序体、声明、变量表、类型及相关配置。文件名近似只能作为候选，回读源码与声明消歧；定义和同名实例分别记录。最小映射记录为：

| 原生对象路径 / ID | 定义或实例 | 引用依据 | 源文件 / 对象位置 | 行号类型或 XML 路径 | 状态 / 缺口 |
|---|---|---|---|---|---|
| 本次材料实际存在的对象 | 按声明填写 | 真实引用字段及位置 | 可回查来源 | 源文件行号、导出行号或对象路径 | 已映射 / 部分映射 / 未解析 / 受保护 |

检查请求范围内的断链、重复 ID、缺失目标、同名歧义、重复映射和孤立文件。孤立文件只说明尚未映射，不等于无用或未调用。导出/派生文本须记录到原件的坐标映射；缺映射即注明未核对原件。清点数量、元数据可读、程序体可读和对象映射完整性分别报告，不混称“工程已完整解析”。

## 5. 追踪声明、调用与读写

按[定位与追踪](../locating-and-tracing.md)回读声明、实参形参绑定、调用点、写入/清除点、消费者及适用的任务证据。按问题追到足够回答为止，不索取无关全工程。词法统计只产候选，图形网络、间接写入、HMI/通讯写入等未覆盖范围单列。结论遵循[证据与因果规则](../common/evidence-and-causality.md)。

## 6. 进入讲解并记录缺口

已选目标：带着来源映射回到用户明确要求的任务与交付；只要求提取时只提取，不因定位成功强制讲解或加载讲解/源码归档全套。只有用户明确要求讲解，或未说明任务而默认进入讲解时，才进入 A/B/C，不要求重复选择且不改变既有讲解模板。未选范围：交给[工程导航](project-navigation.md)呈现总览与可选对象；已授权完整范围则继续。详细讲解用[代码讲解流程](explain-code.md)，本流程不另定模板、分册、文件名或暂停门禁。

记录本次已读取范围、已映射对象、未解析链接、受保护/不可读对象、执行顺序未知项及实际执行的工具；未运行编译、仿真或硬件就写未执行。用户要求沉淀新品牌经验时，按厂商导航中的经验记录契约更新对应品牌文件，方法与验证范围分别登记，不保存用户工程源码或私有标识。
