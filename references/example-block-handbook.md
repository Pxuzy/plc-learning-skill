## 一、整体功能与关键变量 🧭

**控制目标**：请求满足普通许可时记住已接收状态；输入撤销不自动清除本段状态。

**整体流程**：启动请求与普通许可 → 建立运行记忆 → 供后续消费。

**职责边界**：只展示状态建立；未提供停止、异常、模式退出或掉电恢复路径。普通许可不代表已核实的硬件安全条件。

### 关键变量介绍

| 变量 | 数据类型 | 方向 | 含义 | 谁写谁读 | 证据等级 |
|---|---|---|---|---|---|
| `xRequest` | BOOL（假定） | 输入 | 本次启动请求 | 外部写入；本段只读 | 推断 |
| `xPermit` | BOOL（假定） | 输入 | 普通运行许可 | 外部写入；本段只读 | 推断 |
| `xRun` | BOOL（假定） | 内部状态 | 本段记录的已启动状态 | 本段置 TRUE；读取方未展示 | 推断 |

**变量关系**：请求表示当前输入，运行状态保存之前执行的结果，两者不是同一个概念。

### M01 启动状态建立

**一句话说清**：请求通过普通许可时把运行状态置为已接收，并一直保留。

#### 1. 功能定位与执行条件

**功能定位**：承接请求和普通许可，为后续流程提供启动记忆。

**代码职责**：两项输入同时有效时写运行状态，本段不负责完整的启停控制。

**设计依据**：当前请求撤销不能说明加工已经停止，因此需要一个独立状态记住接收结果。具体是否应该保持取决于真实需求；此处是教学设定，不冒充作者意图。

| 进入条件 | 必要原因 | 不满足时的行为 |
|---|---|---|
| `xRequest AND xPermit` | 有请求且普通许可满足才接收 | 跳过写入，保留运行状态 |

#### 2. 源码

**来源定位**：本文件虚构片段，无现场源行坐标。

**展示方式**：教学注释版；源字符保真要求用于真实程序，本例不声称出自工程文件。

<!-- src: none；来源/对象：本文件虚构片段，非现场工程 -->

```st
IF xRequest AND xPermit THEN // AI: 当前请求必须同时满足普通许可才接收
    xRun := TRUE; // 留下启动记忆；输入随后撤销不构成本段复位 // AI: 记录已接收启动请求
END_IF; // AI: 启动请求接收范围结束
```

#### 3. 代码块整体讲解

**处理过程**：请求与许可同时成立时建立运行状态，否则不更新该状态。

**关键逻辑**：输入资格与状态记忆分开；没有新请求只是不建立新的TRUE，不等于产生停止动作。

**写法好处**：在本例“接收后保存记录”的教学目标下，独立状态允许当前请求与已接收结果分离；代价是输入撤销不会自动清状态，必须进一步核实停止需求与清除路径。本片段没有复位源码，不证明全工程只有一处置位/复位或比其他实现更好。

**状态变化**：本段只有TRUE写入。条件失效时状态保持，实际停止与复位需要查其他写入点；不能据本段宣称拥有故障恢复或防重启机制。

**易混淆点**：如果改成每扫描直接赋值`xRun := xRequest AND xPermit`，输入失效就会清运行状态，与当前保持写法不同。这是行为变更，不是等价改写。

#### 4. 形象示例

**场景设定**：按钮发出短暂请求后松开，观察记录是否继续保留。

**初始状态**：假设`xRun = FALSE`，`xPermit = TRUE`，同一实例周期执行，无其他写入。

| 阶段／扫描 | 输入与原状态 | 本段处理 | 执行结果 |
|---|---|---|---|
| 第1次扫描 | Request TRUE；Permit TRUE；Run FALSE | 进入分支 | Run TRUE |
| 第2次扫描 | Request FALSE；Permit仍TRUE | 跳过赋值 | Run保持TRUE |
| 第3次扫描 | Permit也变FALSE | 仍跳过赋值 | 本段仍不清Run |

**理解要点**：条件失效与执行复位不同。需要停止的系统必须有另外可确认的清除路径。

**形象类比（可选）**：请求像提交工单，Run像“已接单”记录；提交按钮松开不自动撤单。类比不包含真实设备动作、调度协议或安全等级。
