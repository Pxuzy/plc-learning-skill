# 局部代码讲解：五部分块级版式 🧩

本参考是模式 B 局部代码讲解的正式输出规则权威；一页提示仅兼容呈现本规则，质量清单只核对、不另加要求。本参考只用于模式 B 的局部代码讲解；完整手册仍按 `references/handbook-guide.md` 与 `references/template-handbook.md`，完整手册的行内教学注释要求不变。用户明确要求详细/逐行时，不降低分析深度，仍保留下列块级结构，逐行问题可在“代码块整体讲解”中逐项回答。

**源码呈现约定：** 输出用户提供的 ST/SCL 等行式源码时，代码围栏逐字保留可见源码，包括空白、变量名和原有注释；新增说明只追加在完整源行之后，不改动任何源字符，不加 `// 教学补充` 这类前缀。本用户默认要求行内注释（见 `SKILL.md` 的 `PLC-COMMENT-DEFAULT`）：默认给有业务作用的行加短尾注，用户明确逐行时覆盖执行与结构行，交付时标清这是追加注释版、不称原样代码；用户明确要原样代码时才只给原码。整块因果仍写在围栏外的五部分正文，不以注释替代讲解。

**范围标签不等于片段行号：** 用户给出的“位置/范围”只有在同时提供可核对的工程文件、原始行号映射或明确说明时才可作为行号；若只给一段重新排版/删去注释的源码，按可见片段讲解，不自行推断起止行、缺失行或续接关系。

## 简洁写作提示词 ✍️

默认简明讲清，不把栏目数量当作篇幅要求。保留五部分、六列变量表、四个整体讲解字段、批判性审查及验证状态；同一结论在最合适的位置解释一次，后文直接使用，不再换句话复述。

- 定位交代位置与入口；职责交代写入目标；设计依据只补充必要信息，不重复模块白话概括。进入条件表按业务分组，用少量行表达，不逐项重抄源码注释。
- 变量表一变量一行，含义、读写点用短语。共享声明缺口与外部写者未知在表前说明一次，成员类型仍如实填未知；命名只解释影响本段理解的词段，不另列通用前缀词典。
- 四字段各讲一件事：处理过程串输入→判断→写入；关键逻辑选最易误读的一点并给简短单因素对照；写法好处只写可证效果；状态变化只讲写入、不写与保持。每字段通常1～3句，有独立因果才扩展，不以句数截断必要解释。复位位置留在交接，不在多处列同一组写点。
- 示例默认一个场景、一张短轨迹表，保留具体初值和三次状态承接；不额外堆真值表、第二套轨迹和边界长表。保持假设在首次依赖处简注，不把本段不写说成自动复位。
- 交接只写实际输入、消费者、清除点和最短可查位置；审查只列影响当前理解或行为的问题。共用未知、未执行验证集中说明一次，某结论专属的假设仍就地限定，不反复免责。
- 完整源码、原注释和按请求追加的业务短注释不减；条件、索引对象、执行先后、写入/不写与证据边界不减。压缩解释的重复，不压缩源码或关键因果。

出稿后删除重复概括、流水账、无关术语课和“本节将……”式元话术。读者应能复述“输入是什么→何时通过→写了什么→条件撤回后怎样”。用户明确深讲时展开独立信息，仍按此去重。

## 默认五部分块级结构 📘

成品直接从独立一行的 `# <对象与范围> 📘` 开始，接范围、变量表与模块五部分；执行动作、修改经过与对话回应留在交付消息中，正文只含教学内容。使用下列骨架的原字段标签与层级：模块标题为 `### M01 <名称> 🧩`，小节为 `#### 1. 功能定位与执行条件 🎯` 等“编号＋名称＋表情”；四个整体讲解字段为 `**处理过程**：`、`**关键逻辑**：`、`**写法好处**：`、`**状态变化**：`，内容可另起行，标签和冒号保留。**关键变量前置**在五部分之外，源码前介绍；模块五部分固定为“功能定位与执行条件 → 源码 → 代码块整体讲解 → 形象示例 → 程序交互与段间交接”，示例与交互分开，不合并成一节。

**块级**就是一小段完整源码后紧邻整块因果说明；在 B 中，一个完整局部片段视为一块：五部分只在第二部分保留原码一次，第三部分解释执行范围与整块因果；长 `IF/CASE/FOR` 保留完整闭合结构与全部原注释，按必要分支锚点导航，不截断、不重复贴码或用省略号代替；**单个闭合结构内部逻辑过多时**（一次贴完读不下来）按 `PLC-BLOCK-GRANULARITY` 分三层：外层骨架（骨架仅用围栏外的行范围导航，列头部、分支和尾部位置，不复制源码）→ 第二部分内部子块按原顺序完整贴码一次，第三部分逐范围讲解 → 整段汇总（执行顺序、分支互斥/优先级、完整状态变化）。子块边界取闭合结构或语义单元，不切断表达式、单条赋值与原注释；每个子块仍套用五部分的“源码＋整块讲解”思路，但不重复抄写变量表与整体交互。短的完整片段（仅一条 IF 或几个赋值）不拆，直接一块讲完。共享的小段源码/解释交替规则用于多个逻辑块或完整手册，不要求拆开这一完整片段；首次概念、因果推导与假设声明的深度不变。关键变量表列「变量、数据类型、方向、含义、谁写谁读、证据等级」；变量含义首次依赖库或存储语义时在该单元格就地限定假设，不能用后文补签。缺声明时已确认类型/范围仍未知；允许结合命名前缀、英文词段、作者注释与实际读写推测用途，标为推断，不从名字补齐已确认的类型、作用域、调用关系或物理动作；方法见 `inline-comment-style.md` 的“变量命名辅助推断”。

单对象文档一个 H1，章 H2、模块 H3、小节 H4；多对象嵌套沿用手册模板增加一级。每个模块标题下先写一句不含变量名的白话说明，再依次给出五部分。普通局部说明省去不适用的工程级章节，保留模块五部分；未知内容填在对应部分，不补造事实或为填槽重复结论。

**变量表的可读性**：保留六列；变量、成员路径及已知类型用行内代码，一格只承担该列的信息。用途、触发条件或写读方不同的变量逐项列出，不用多个名称加长段落合成一行。公共数组声明可在紧邻表前的小表列明范围与元素类型，成员行仍写完整路径及其已知类型或“成员类型未知”；共同库假设在首次使用前集中说明，行中按需引用。表头、分隔行、表体连续，各行列数一致；长机制与证据缺口的影响放正文，不塞进类型或含义格。

### 图形语言分支

LAD/FBD 的五部分和变量前置保持不变；第二部分保留原图、可核对的原生导出或拓扑文本，不套下面的 ST 围栏占位符、不伪写 ST。按网络号、接点/线圈/指令、串并联和汇合关系定位；裁切或连接不清列未知。第三部分逐网络说明输入组合、路径、写入与状态后果，不逐物理行追加 `// AI:`，不运行 ST 专用 CLI。混排时先清点单元，ST 子单元用 ST 检查，图形子单元人工核对对象坐标、拓扑和平台语义；没有图形自动对账工具就明确记未执行。IL/STL、SFC 等非 ST 文本按实际方言保留，五部分不变，校验范围同样不能冒用 ST 结果。

## 出稿前逐项核对（按适用范围）✅

1. 独立的 H1 标题；2. `**功能定位**`；3. `**代码职责**`；4. 进入条件表（含依据列）；5. `**设计依据**`（写事实与约束，不用“为了安全/规范”）；6. 完整原码；7. 第三部分四个字段 `**处理过程**`/`**关键逻辑**`/`**写法好处**`/`**状态变化**`；8. 示例的 `**场景设定**` 与 `**初始状态**`，至少三次连续执行；9. 交互表与 `**交接要点**`。聊天前言、执行计划、修改说明一律留在交付消息中，不进正文。

## 出稿与局部修正闭环 🛠️

确认来源与读者后，先读本参考全文；普通 B 不加载新手覆盖方法、工程模板索引或 catalog。明确要求深讲或新手时，再按实际标题读取 `references/code-reading.md` 文件中的“每小段按第一性原理推导”和 `references/teaching-from-scratch.md` 文件中的完整标题“源码深讲模式（读真实工程时加载）”所含适用方法，断言取出的区段非空，最后核对 `references/quality-checklist.md`。不取短答或可复制单元来替换本骨架。

成品保留完整原码，说明对应源语句，真假路径与保持边界均须可核对；源文件是当前输入的完整副本，不能凭子串或删原注释宣称保真。格式/源码检查只证明可确定项，待审清单未完成时不称语义合格或教学验收完成；无工具明确记“未执行”，不自报通过。

仅在有工具且实际做产物校验时，读取 `references/workflow.md` 的“局部产物校验”一个区段，按其中闭环执行；普通讲解不读 workflow 全文、不做 Git 或技能维护回归，不为标记细节先读脚本源码。段末恰一条 `<!-- 本段已完 -->`；有后续时替换为 `<!-- 继续点：M02 实际模块名 -->`，标记后无正文。

## 零基础正文覆盖（仅按读者需求启用） 🎓

用户明确是新手/零基础/初学者时启用，默认工程师口径不变。文首元信息须如实记录用户的读者要求：在 `讲解深度` 中保留“零基础”“新手”或“初学者”，也可单列 `> 读者：初学者`；仅写“局部深讲”不等于已满足零基础要求。零基础口径须覆盖每个执行单元；默认口径未核对的范围仍为待审，不能当作语义通过。在第三部分现有四字段中，用源语句或源范围对应“作用、何时成立、具体结果”，允许合并相邻同类说明，但必须覆盖每个执行单元，包括调用、ELSIF 和末尾独立赋值。先解释本片段实际出现的概念再使用：例如调用输入 IN、预设时间 PT、调用输出 Q 仅在所声明的 TON 假设下解释；`:=` 写入目标、IF/ELSIF 按先后选择分支。未出现的术语不另开课，不新增第六部分，也不把正文变成机械语法翻译。

在第三部分用 `<!-- explanation: L1-L1 -->` 对应具体源语句或范围，下一行给出实际说明；暂未说明或未核对的范围用 `<!-- unreviewed: L7-L7 -->` 并注明待查对象。标记对应当前输入片段，不冒称工程行号；空标记、只有标题、借用下一必填字段或源码内伪造标签不算解释。可用 `**末行**：具体说明……` 引导，不能以“未知”或映射齐全替代真实作用、概念理解与因果审阅。计行与标记解析按需见 workflow 的“局部产物校验”。完整教学示例可选看 [单一填实夹具](../evals/fixtures/local-explanation/ton-state.md)，不是额外必读文件或工程事实。

## 模式 B 的注释边界 ✍️

本用户默认要行式源码注释版；图形语言优先执行上文图形语言分支：按 `SKILL.md` 的 `PLC-COMMENT-DEFAULT` 默认给有业务作用的行加短尾注，用户明确逐行时覆盖执行与结构行（依 `references/comment-quality.md` 写业务含义加必要触发条件，不加“教学补充”前缀），交付时明确这是追加注释版。只有用户当次明确要原样代码时才给无注释围栏；此时解释全在五部分正文中完成，仍不把整段代码一次贴完（大结构按 `PLC-BLOCK-GRANULARITY` 拆块）。两种情形都保留原注释、不改源字符，原理、整块功能与状态推演一律放围栏外，不写成独立逐行表。

## 丰富但有语义的表情 🎨

表情让读者更快定位内容，不替代标题或结论，也不要求每句话都加。允许按语义选择并适度轮换：

| 用途 | 可选表情 |
|---|---|
| 文档/学习手册 | 📘 📚 |
| 整体脉络/模块 | 🧭 🏭 🔍 🧩 📡 |
| 输入/输出/信号 | 📥 📤 🔌 📶 |
| 条件/状态/流程 | ⚙️ 🔄 🚦 |
| 示例/核对 | 🧪 📝 ✅ |
| 交接/关系 | 🔗 ↔️ |
| 注意/边界/未知 | ⚠️ 💡 ❓ 🚧 |

章、模块、小节标题都要带与主题匹配的表情；同级同类保持一致，不同主题按语义选择。易混淆点、重要边界、确认/待办提示可在句首或引用块使用表情。避免连续堆叠、无语义装饰和重复强调。

**禁用位置：** 代码、变量名、表格字段、对象 ID、行内代码值、元数据值和证据等级内部不插表情；不得改动原源码来加入表情。

## 因果结论如何取证 🔎

深讲时只按 `references/code-reading.md` 的“每小段按第一性原理推导”适用方法完成事实→所需信息→实现→单因素反例→连续轨迹的分析，再填现有五部分。用真实变量串起读入、条件组合、中间结果、写入与已见消费者；下标、事件实例和状态变量分别说明所选对象、所记信息与结果用途，不用“输入/输出/状态”几个泛称替代。关键变量除了表中定义，还须在整块逻辑中交代作用及何时变化或不写，同构变量可对照解释，无需逐行重复。由“判断此行为需要什么信息、当前值为何不够、哪个变量补充信息”解释必要性，再用具体输入检验。目标未给时，以“若要满足某目标，需要某信息/行为；片段具备或不具备”推导，随后把可见行为单独核对；不把从代码猜出的目标写成已给需求。四个整体讲解字段分别保留，简短未知也可独立成字段。示例以状态账本为依据：先列时刻、完整输入与前值，算出调用/分支/后值，再写理解要点；初始清零第一次使能记为 t=0，后续到期标明输入持续区间。不能只把条件翻译一遍后补“为了安全/防抖”。库类型或保持语义仅是假设时，在第一处依赖它的结论前说明；未知工艺只解释局部变量与分支，不先断言机器开关、作者故意保持或条件必不可少。正式讲解不写历史修改、对话或版本选择经过。

先从可见表达式写出局部结果，再按已有证据决定是否扩展到调用周期、工艺目的或下游动作。**未知声明或调用关系时，默认用“每次执行到此处”**，不先宣称“每个扫描周期都会执行”，再到末尾说调用未知。普通 BOOL 的类型本身也不证明跨调用、初始化或掉电后的存储行为。证据边界贴着相应结论写；文末统一列“未知”不能替代正文中每一处推断的依据。名称只能作为待核实的线索；没有声明、原注释或调用/消费代码时，宁可解释表达式，也不为通俗化补写设备工艺故事。

区分当前实现的限制与数据类型的能力：反复覆盖同一个状态值会丢失先前事件，不等于整数不能编码多个事件；若未分析位编码等其他表示方式，不把当前写法泛化为所有实现都做不到。

| 要解释的内容 | 先写能核对的结论 | 扩展结论所需依据 |
|---|---|---|
| 条件为假 | 在这一次执行中，此分支不执行赋值 | 若要推演“下一次调用仍是旧值”，先声明普通可保持变量、同一实例/目标、两次调用之间没有其他写入或重新初始化；缺声明或调用证据时，将其写成纸面假设 |
| 复位位置 | 逐一列出当前片段实际的 FALSE 写入及其条件；仅对未见的路径标未知 | 是否还存在其他复位、由谁执行，须找到实际写入点；“未见其他复位”不推出“别处一定复位”，也不能把已见的故障清除说成不存在 |
| 多次写同一常量 | 若对同一个普通 BOOL 存储目标重复执行 `:= TRUE`，该赋值本身不产生 FALSE/TRUE 交替 | 下游是否重触发、是否安全、是否有外部副作用，须有消费者、调用顺序与目标映射证据；只凭赋值值相同不能证明“无副作用” |
| 条件或变量的业务含义 | 先说明比较、取反、读写目标，例如 `NOT xCycleFinished` 要求该成员为 FALSE | Finished 为 FALSE 不等于空闲、未运行、从未加工或握手结束；from/to、Enable、OK 等名称不能单独证明上下游方向、物理动作或作者意图 |
| 数组下标 | 逐个读写点抄清“哪个数组用哪个表达式作下标” | 同一段可同时有 `[iBufferIndex]`、`[slotID]`、`[2]`；不能用“全部同一下标”概括嵌套访问。合法性要对照每个数组的声明范围，条件中的业务值域不等于数组声明上下界 |
| 条件求值与分支执行 | 分开看“读取哪些操作数来判断条件”和“条件成立后写什么” | 条件最终为 FALSE 只说明 THEN 不执行，不证明条件内数组没有被读取。不要从 AND 的源码排列直接断言平台短路策略；求值策略须有平台证据 |
| 删条件的后果 | 保留其他条件不变，分别令该条件满足/不满足，再判断该分支赋值是否发生 | 对 `P OR Q` 删掉 Q 后，P 为 TRUE 时仍可通过，不能概括成“永远不能启动”；从“本分支不写”扩展到“整机不动作”还需检查其他路径 |

**例：就地说明，而非末尾免责。** 对只有 `IF xPermit THEN xStart := TRUE; END_IF;` 的片段，可以确认“许可为假时，本次不写 xStart”。若做两次调用推演，应先写“假设 xStart 是同一实例的普通可保持 BOOL，期间无其他写入、复位或重新初始化”，然后才说前次 TRUE 在本假设中保留。消费者未知时只说明赋值目标，不补写会驱动哪种机构，也不把假设当工程事实。
