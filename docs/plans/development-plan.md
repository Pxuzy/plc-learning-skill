# PLC 程序学习 Skill 开发计划

**状态：待审开发计划，尚未按本计划实施。**

**Goal：**形成面向初学者、忠于源码、能够逐项举证的多品牌 PLC 学习工具。

**Architecture：**保留短入口与渐进加载，分离通用证据规则、讲解流程、厂商知识、确定性检查及独立语义审查。先验证现有基础的真实讲解效果，再按可读样本扩展；目录仅定义职责，按需落地。

**Tech Stack：**Markdown/YAML、ST 与抽象 Ladder、Git hooks；现有 Python 标准库检查器仅用于维护，普通文本讲解不依赖 Python、网络、shell 或解析器。

**Spec：**《PLC 程序学习 Skill 改造需求规格》v1.0（[需求快照](../requirements.md)），下文“§”均指该规格。

执行沿用“需求共识→证据审计→方案评审→分步实现→独立验证→用户验收”。Codex 单写者负责实现，独立只读审查负责核验，父助手负责需求对接；用户明确同意后才讨论提交、发布。本次仅规划，不暂存、提交、改配置或启动评测，无工期估算。需求页首“尚未实现”为历史元数据，不据此删除已授权基础。

## 里程碑一：首次真实提交就绪

治理门禁必须先于首次项目提交；里程碑二的语义评测可独立推进。P3 不属于普通 PLC 讲解，但在仓库维护中仍是必需工作。

### A．需求追溯与持久设计（§1–3、7、9–13）

消费需求和现有入口、工作流、索引；拟由 `docs/` 保存架构、决策、验收及维护记录，`references/standards/` 保存规范差异。产出需求—规则—样例—检查—证据状态映射，使 scratch 不成为唯一长期存档。借鉴项按§3.6登记迁移边界，不搬旧文件、品牌实现、固定版式或历史制度；不预建空目录。

- [ ] 分别核对实施时的 Anthropic/Agent Skills 官方格式与 Codex 官方发现/加载文档，记录查阅日期、必需字段、身份字段及差异；另做真实加载测试，不以 YAML 合格宣称兼容。
- [ ] 正例：局部文本仅加载相关规则；反例：缺厂商资料不阻断文本讲解，规范差异不得静默忽略。全部需求有去向、待定项有批准门槛，才完成本项。

### B．隐私与提交门禁（§7、8、11、12）

消费有效 hook 路径、宿主入口及委托代码；`.githooks/` 负责分派，`scripts/` 负责扫描/格式校验，`evals/` 负责回归，`docs/maintenance/` 记录接入与恢复。版本化内容与本地/继承全局的有效身份、作者/提交者元数据、消息、路径和历史隔离分别核验，不把文件扫描当成元数据脱敏；生成交付物不统一脱敏，若纳入版本控制另走准入检查。

现有宿主 gate 在扫描后委托 `privacy.originalHooksPath`，缺省指向 Git 公共目录的 hooks；目标缺失或不可执行会返回成功。比较两案：①保持继承入口，以仓库局部委托接入版本化门禁，改动小，但缺失目标会静默跳过；②仓库局部 `core.hooksPath` 指向分派器，显式调用发现的宿主链并运行项目门禁，能主动检查必需链，但须转发全部宿主 hook 阶段。建议在完整转发与防递归验证成立时选②；否则暂停接入、提交待审方案，不能退回静默旁路。宿主路径仅由接入时发现并保存在本地配置，不硬编码机器路径、不改全局配置。

- [ ] 分派器验证必需宿主入口及委托配置，拒绝自指/回环、缺失、非可执行和非零退出；保留参数、stdin、退出码及扫描前后边界，不屏蔽宿主保护，不提供未批准绕过。
- [ ] 对暂存区新增内容和路径检查，覆盖令牌/API 密钥、硬编码凭据、私钥、非公开个人邮箱、真实 IP、绝对用户路径、凭据/签名文件、构建缓存和非项目个人素材；不能只扫工作树。公共 noreply/占位符仅设最小、可测试例外。
- [ ] 格式严格为 `type(scope): 中文标题`；type 仅允许 `feat`、`fix`、`docs`、`refactor`、`chore`、`merge`、`perf`、`release`、`revert`、`test`、`build`、`ci`、`style`；scope 英文小写，标题含中文且不超过100字符，之后空行，正文至少一条 `- `。
- [ ] 正例覆盖干净暂存、最小允许项和每个合法 type；反例逐类覆盖内容/路径泄漏、仅暂存版本有问题、标题越界、非法类型/作用域、缺空行或正文。输出只含类别和安全定位；敏感路径也脱敏，不回显测试敏感值、不改文件。全部预期判定及日志审查通过才完成。

### C．真实门禁闭环（§8、10–12）

消费 B 的实现与宿主链契约；在 `evals/` 形成测试，在 `docs/maintenance/` 保存结果。先测脚本，再在隔离临时 Git 仓库做真实提交；这是获准实施后的测试，本次不执行。

- [ ] 合法提交必须实际成功，违规提交必须实际阻止；测试链缺失/递归、宿主失败、格式失败、敏感日志、暂存与工作树不一致及元数据隐私。保留宿主保护，使用干净测试身份，不接触项目历史。
- [ ] 记录各层调用证据与退出码；不能用模拟退出码替代真实提交。负例异常放行或链路不明即停止；B/C 同批交付审查，通过后仅达到“可申请首次提交”，不自动提交。

## 里程碑二：真实教学验收与长文闭环

### D．三夹具新鲜行为评测（§2、4–6、9、10、12）

消费现有三组源码和规则；`evals/` 保存输入/输出追溯及评分，必要时修改 `references/common/`、`references/workflows/` 或入口。模型仅接收源码、用户任务和适用 Skill 指引，不接收案例卡答案；独立只读 PLC 语义审查者使用案例卡核对。

- [ ] 记录源码/指引精确 SHA-256、完整提示、模型与可得参数、加载环境、原始输出及其哈希、未知项；缺信息如实标记。不得事后润色失败讲解冒充 Skill 改善；修规则后重新生成并保留前后结果。
- [ ] 正例验证 startup 的输出过渡、handshake 的矛盾条件及缺调用顺序、Ladder 的可见串并联；反例检测擅改源码/原注释、误剥含 `AI:` 的原文、注释后缀越界、臆造 TON/保持性/设备动作。静态保真/注释检查与语义/教学评价分别出结论。
- [ ] 增补短答、无 Python 的直接 ST/Ladder、多个独立 IF/多写入及缺证据变体；每条可注非空行有准确 `AI:` 注释，例外有原因，块级解释有条件、读写、本次不写及结果；轨迹明确假设。批判审查区分证实缺陷、条件风险、未知，并给位置、触发、影响、置信度和未执行验证。三夹具及适用变体均有原始产物、双层结论且无未解决 P0 失败，才完成 D。

### E．嵌套长文与最小模板（§2、5、6、9、10）

消费 D 的实际失败与跨块任务；`templates/` 仅固化必要呈现，`scripts/` 仅承担可确定检查，`evals/` 保存覆盖及合并证据。

- [ ] 正例：完整外层范围→带外层条件的内部块→整体执行/状态汇总，稳定锚点覆盖源码，连续生成后合并为单一 Markdown；反例注入截断、缺节、重复、映射丢失、分支当并行执行，必须报错并定位，不能静默缩成摘要。
- [ ] 逐项判定 P0、触发的 P1；整体地图/厂商查证/轨迹/长文/安全问题按触发适用，安全不认证。P2 思维方法与图表只按需添加，不挤占核心；短事实问答不强套全文模板。
- [ ] 拟放行标准：P0 无未解决失败，触发的 P1 有证据或明确未知及缺件，初学者能循轨迹解释状态；独立审查与用户试读认可。门槛仍待用户确认；未发现问题不等于完美，静态全绿不等于行为通过。任何源码变异、幻觉或漏覆盖先停下修规则、重跑，不降标准。

## 里程碑三：有证据的四品牌扩展与发布

### F．按样本逐组合扩展（§3、4、10、13）

西门子、欧姆龙、倍福、台达均逐项登记产品线、格式、版本及授权样本。首个适配组合由实际可读且可复核样本决定，不预设品牌优先级。每个组合独立重复一个小闭环：输入识别→原生树定位→证据链接→正反例→能力声明。

- [ ] `references/vendors/` 登记控制器、任务、POU/实例、类型、GVL/局部变量、读写者/调用者；I/O 逐跳追到地址/过程映像、模块通道、方向类型和读写点；事件逐跳追到产生代码、ID/来源、日志/报警配置、HMI/客户端。每跳附路径证据，断链标未知。
- [ ] `references/external/` 与 `standards/` 记录官方/手册/外部 Skill/社区来源、许可、查阅日、适用版本、窄结论及验证状态；官方行为以匹配手册/工程为准，不复制私有材料或未经许可第三方语料。`scripts/`、`evals/fixtures/` 只为已有样本增加必要解析与回归。
- [ ] 正例可追溯树、目标和符号；反例错误版本、仅凭后缀猜格式、缺调用/映射、截断或不可读输入，均不得补造。部分解析失败须报告尝试、范围和替代导出要求，仍能解释可见文本。
- [ ] 状态按证据登记 `planned`→`reference-only`→`sample-verified`→`parser-verified`→`runtime-verified`；只声明已验证组合及具体能力，未运行不升级。缺获准样本则停在资料/规划层，不阻断 D/E。

### G．兼容、分发与发布（§7、8、10–13）

消费 A、D/E 及拟发布组合证据；`docs/maintenance/` 管理版本/发布，运行包仅含入口及必需参考、模板、工具。

- [ ] 正例在选定平台实测发现/加载、相对链接和直接文本讲解；反例检查漏依赖与误打包，排除 `.git/`、`evals/`、`docs/`、hooks、缓存及私有资料。平台差异不明、许可/隐私失败或教学回归则停止发布。
- [ ] 用户验收后才申请发布；仅发布节点按兼容新增 minor、修正 patch、破坏性变更 major 升版，tag 另记决策；日常提交不升版，不默认 beta，不自动创建 remote、推送或发布。
