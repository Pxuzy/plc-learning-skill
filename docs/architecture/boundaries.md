# 架构与运行边界

本仓库维护一个以源码证据为中心的 PLC 学习 Skill。入口和按需参考用于模型解释；检查脚本、Git 门禁和评测流程只服务仓库维护，不能成为普通文本讲解的运行前提。

## 内容分层

| 路径 | 职责 | 运行/分发边界 |
|---|---|---|
| `SKILL.md` | 触发条件、问题分流、关键不变量及按需引用 | 普通解释入口；保持简洁，细则由唯一权威参考定义 |
| `references/common/`、`references/workflows/` | 证据等级、因果解释、分块与审查流程 | 按任务读取；短事实答复不加载完整工作流 |
| `references/vendors/` | 品牌/产品线/格式/版本资料入口及限制 | 仅在识别出相关平台后读取；目录不代表支持 |
| `templates/` | 可复用且确有稳定需求的输出结构 | 仅局部讲解或长手册需要时加载；不为填栏制造空话 |
| `scripts/`、`.githooks/` | 维护检查、隐私政策及仓库级提交门禁 | 不属于 Skill 普通运行包；安装到实际仓库需另行授权 |
| `evals/` | 结构检查、合成回归和评测隐私流程 | 不将私有样本、逐字输出或其指纹纳入版本控制 |
| `docs/` | 需求、架构、决策、维护与评测治理记录 | 开发仓库资料，不作为普通讲解上下文 |
| `.codegraph/` | 开发机本地代码索引 | 已由 `.gitignore` 排除，不属于交付或评测资产 |

## 证据与能力边界

- 纯 ST/Ladder 文本可用于解释其可见内容；不需要厂商工程解析器、Python、Shell、网络或 PLC 软件。它不能证明完整工程结构、调用关系、变量表、I/O 映射或事件配置。
- 厂商能力必须绑定具体品牌、产品线、工程格式和版本。官方资料可佐证其明确覆盖的术语/行为，获准工程样本验证可读结构，实际运行或编译证据才能支持更高等级声明。
- 官方 Skill 文件格式与某平台的 Skill 发现/加载是不同边界。仓库根部 `SKILL.md` 的存在不能证明 Codex 项目已发现或加载该 Skill；平台安装布局和实测留到兼容阶段。
- 结构检查只能验证其明确定义的文件/格式属性；人工审阅负责语义、源码映射、教学价值和注释删除测试；PLC 编译、仿真、Trace 和实机验证必须分别实际执行后才能报告通过。
- 仓库隐私扫描只覆盖已实现的路径/内容规则及其输入范围，不保证识别所有编码、拆分或未知敏感材料。测试输入和派生输出按隔离规程处置，不能用“只存脱敏摘要”弱化可识别信息禁止入库的约束。

## Git 与宿主边界

门禁在临时 Git 仓库验证，不在本项目工作区安装/恢复 hook，不改变全局配置或宿主 hook 链。工作区既有改动按用户资产保留。提交、推送、合并、安装和发布需要分别确认；分支开发许可不扩大这些授权。
